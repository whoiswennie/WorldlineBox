# WorldlineBox 产品愿景与架构边界

> 0.1.0 基础现已增加 Windows DSH 实例、运行版本、整合包和备份管理，见[启动器实现](developer/dsh-launcher.md)。伙伴私聊、群聊、联系人与来源记忆已开始实现，见[伙伴消息系统](developer/companions.md)；完整世界状态与游戏运行器仍描述后续设计方向。

## 产品目标

WorldlineBox 是虚拟角色、世界和资产的中枢。长期陪伴、角色扮演、互动叙事与 AI 世界需要持续的人格、记忆、情绪、关系、行为、形象和声音，也需要真实世界状态与素材。角色脑负责这些长期状态和对话；具体任务由 DSH 等执行后端完成；游戏和世界运行器负责场景呈现与交互。

用户可以把它作为 DSH 启动器、整合包管理器、其他生态项目的入口或虚拟世界管理器使用。这些入口都围绕共同的角色、世界与资产展开。

## 领域分工

| 领域 | 持有的数据 | 边界 |
| --- | --- | --- |
| 资产 | 文件、标签、合集、媒体元数据、派生产物 | 沿用资产 Worker 与资源库数据库。 |
| 角色 | 人格、记忆、关系、目标、行为与呈现配置 | 不随 DSH 版本切换而重建。 |
| 世界 | 人物、地点、事件、规则、时间与世界线分支 | 区分角色提议、执行结果和已确认世界事实。 |
| 环境 | runtime artifact、实例、profile、锁、进程和操作记录 | 使用独立管理数据库；不把实例硬塞为 asset 记录。 |
| 执行 | 任务、工具权限、进度、结果与错误 | 经版本适配器委托给 DSH 或其他工具。 |
| 呈现 | 游戏、场景、头像、语音与交互事件 | 通过世界运行器与语音适配器连接。 |

WorldlineBox 的插件、脚本和 MCP 与 DSH 原生插件是不同协议，不因“都叫插件”就共用目录或依赖解析规则。资产库同步也不自动包含正在运行的 DSH 会话或实例数据库。

## 角色委托任务的闭环

1. 用户或世界事件进入角色脑，结合人格、当前世界状态和相关记忆进行交互。
2. 需要真实任务时形成结构化委托，携带实例选择、任务目标、必要上下文和允许的工具能力。
3. 执行适配器选择精确运行环境并提交给 DSH 或其他后端；角色仍可接收事件和保持对话。
4. 执行后端返回进度、结果、错误和证据。角色以自身的表达方式反馈。
5. 有确认依据的结果才改变世界状态；可复用的事实与关系变化按记忆规则保存。

未来协议应包含任务 ID、取消、结果关联和幂等语义，避免重试产生重复行为。角色对某事的叙述不能直接当作工具执行成功或世界事实。

## DSH 多版本与整合包

PCL 的关键启发是管理安装实例与启动数据目录，而不是只给一个全局安装增加版本选择下拉框。DSH 原生 profile 不等于完整实例：同一 Home 内的会话、存储与部分配置可能仍共享。

推荐的对象是：

- `RuntimeArtifact`：固定引擎、Node、包管理器、完整依赖、平台与来源摘要。
- `Instance`：artifact 引用、独立 Home、profile、工作区、日志、进程状态和快照。
- `PackVersion`：固定的引擎要求、插件组合、锁文件、配置、内容与来源说明。
- `Operation`：下载、安装、复制升级、导入导出与恢复的可持久化任务记录。

同一核心版本可以有多个不同整合包实例。每实例使用独立 `DSH_HOME`，技能隔离按对应版本的 agents 目录能力适配。先使用真实目录和上游包管理机制，不依赖 Windows 符号链接权限或跨实例共享可修改的 `node_modules`。

升级流程应为“生成新副本 → 获取与校验 → 安装与依赖对账 → 启动及业务验证 → 切换”。保留旧实例；恢复程序版本与数据格式恢复需要分别验证。缺少插件兼容证据时应标记未知，而不是承诺自动适配所有新版本。

PackForge 的 `.dspack` 与安装交互值得参考。当前仓库没有导入其代码，使用自有 `.dshpack` 格式，不声明兼容 PackForge `.dspack`。

## 当前工程与下一步

现有 Electron 主窗口、React UI、preload、资产 Library Worker、SQLite、媒体处理、资产插件、脚本、MCP 和 Windows 构建链继续保留。后续按独立领域增加环境管理服务、DSH bridge、角色服务和世界状态服务；耗时安装与引擎运行不占用资产搜索及缩略图调度。

首个功能里程碑应是：在 Windows 上登记或创建两个独立 DSH 实例，确认精确运行时、插件锁和 Home，不改变已有安装；能够启动、停止、查看日志，在升级失败后回到旧实例。角色与世界系统在这个可靠执行基础上逐步落地。

这些快照与建议不能替代后续双版本运行、插件兼容和数据迁移测试。适配器应按目标引擎版本维护。
