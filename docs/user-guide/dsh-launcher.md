# DSH 启动器

Windows x64 上启动软件默认进入「启动器」，它位于应用栏首项。不需要先创建资产库。启动器管理精确运行版本、独立实例、插件、整合包与停机备份；资产库和 DSH 数据分别保存。

左下角「设置」在当前模块上打开，关闭后仍停留在该模块。外观中的动态主题和个人壁纸应用于全局；切换启动器、资产管理及启动器内部页面不会重新加载壁纸或重置播放进度。

## 数据目录

正常开发启动和正式安装版共享当前用户的数据目录。Windows 默认是
`%APPDATA%\WorldlineBox`，DSH 的安装包缓存、解包暂存、运行版本、实例和整合包均在其
`dsh-launcher` 子目录下。项目目录只保存开发工具与测试夹具；正常使用不把 DSH 数据放在 `.tools`。

旧开发目录里只有下载缓存和记录时，首次启动会在新目标不存在的情况下校验并复制 DSH 存储，
旧目录保留。已有共享数据不会覆盖；旧实例需要先导出完整备份或整合包，再导入共享目录。
资产库、世界文件和浏览器配置不会从旧开发目录自动合并。

如需自行指定数据位置，可为两种启动方式统一设置绝对路径 `WORLDLINEBOX_USER_DATA_PATH`。
测试和明确选择的多实例开发运行仍使用各自隔离目录。

## 获取运行版本与创建实例

1. 在「网络」选择系统代理、直连或自定义代理；可保存多组地址，设置 npm、Python 和 GitHub 镜像。保存后新请求和新命令立即使用新配置，无需重启软件。
2. 在「运行版本」同步官方目录，按正式、RC、Alpha 等渠道选择精确版本并安装。GitHub 提供发行说明，官方 npm 提供实际可运行包与 SHA-512 校验；GitHub 源码压缩包不会当成 Windows 运行文件。
2. 管理器复制程序，不运行系统安装向导，不修改原安装、用户 PATH 或已有 `.dsh`。
3. 导入后显示真实 DSH 版本、来源 SHA-256 和完整运行文件摘要。`latest` 只是获取地址，不是实例的版本标识。
4. 安装完成后自动运行隔离兼容性检测。「运行版本 → 共享存档兼容性 → 检查详情」可查看每项结果、耗时和失败原因。所有实例统一使用共享会话、附件、默认工作区、账号与 DSH 模型设置，创建时只需选择运行版本。新发行版不需要加入版本白名单。
5. 选中实例并启动，在独立窗口打开官方随包 Web 工作台；首次配置共享模型与账户，后续实例沿用。关闭工作台窗口后进程继续运行，可以重新打开；「停止实例」终止该实例及其子进程。退出 WorldlineBox 也会停止受管进程。

主路线使用精确官方 npm 发行版和独立 Node 运行文件启动真正的 DSH WebUI。原来下载的桌面包保留在折叠的兼容导入入口，已有实例和数据继续保留。软件内置 Node、Python 3.13、Git、FFmpeg、ffplay、ffprobe，启动时自动加入本进程及子进程的工具环境，无需另行安装这些工具，也不修改系统工具版本。

同一时间只能运行一个 WebUI。普通「启动」会拒绝另一个已运行的工作台；「切换并启动」明确停止当前工作台后启动所选实例。CLI 任务和终端拥有自己的实例绑定，正在执行的任务不会因为默认版本改变而改用另一套插件。

关闭工作台窗口后，后台实例继续运行。点击实例右上角的「打开 / 返回工作台」即可重新打开原界面，无需停止重启；「停止实例」才结束后台服务。伙伴任务无需启动工作台，直接沿用当前 CLI 实例中已保存的账号、API、模型、插件与技能。DSH 的模型与世界线盒子全局聊天模型相互独立。

启动或执行任务时，会等待所选版本正在进行的检测；对旧失败结果，每次应用会话最多自动重新检测一次，同版本的并行请求共用结果。通过后复用证据，不在每项任务前启动 Web 检测环境。失败详情可在运行版本页查看并手动重试，不提供其他存档模式。

升级时会合并原有实例的会话、附件与默认工作区。当前默认实例的账号和模型配置优先进入共享设置，其他实例随后采用统一设置；冲突的凭据和配置原件存入共享目录中的迁移备份，原始数据不会直接删除。插件、技能与工作台浏览器分区仍按运行实例管理。

### 查看检测与删除运行版本

检测使用全新的临时 HOME、合成会话、附件和假凭据，运行真实原生接口，不读取真实存档，也不发送模型请求。检查包括文件完整性、隔离启动、会话重启读回、写入锁、工作区、附件、凭据、模型配置、无界面 CLI、跨制品双向互读和清理。可点击「重新检测」重试；取消、超时或任何失败都不会授予共享资格。

在「运行版本」的已安装卡片点击「删除运行版本」，会删除对应程序文件、检测报告和不再复用的安装包缓存。卡片会列出仍在引用它的实例、快照、整合包和运行任务，需先处理引用。删除实例与删除程序版本是两个独立操作。

每个运行版本分别管理和删除；顶部没有全局清理下载缓存按钮。删除时只清理该版本拥有且不再共用的运行文件与缓存，用户存档保留。Windows 暂时占用文件导致删除失败时，可稍后重试对应版本。

## 共享存档与插件隔离

采用共享模式的兼容运行版本、整合包与实例共用一份日常存档，不需要分别登录或重新配置模型。共享目录位于
`dsh-launcher/shared`；更换插件环境或程序版本不会另建空白会话库。

| 内容 | 位置或机制 |
| --- | --- |
| 会话与附件 | 共享 `shared/sessions` 与 `shared/attachments/v1` |
| 默认工作区 | 共享 `shared/documents/deepseek-harness/default-workspace` |
| 登录授权、API 密钥 | 共享原生凭据存储 `shared/.credentials.yaml` |
| 模型提供商、端点、模型目录与默认模型 | 共享 `shared/model-settings.json`，协调到各实例可编辑的 profile 配置 |
| 插件清单、补丁、依赖及锁文件 | 本实例 `home/profiles/web` 和原生 profile 目录 |
| 兼容技能 | 独立 `agents`，作为 `DSH_AGENTS_HOME` |
| 实例配置与迁移前数据 | 独立 `home`，作为进程的 `DSH_HOME`；旧数据保留 |
| 用户配置、临时文件及包缓存 | 独立 `user` / `cache` |
| Cookies 与浏览器存储 | 独立 Electron 持久分区 |
| 主机输出 | 本实例 `logs`，认证 URL 与常见秘密会脱敏 |

实例名相同也不会共享插件身份。同一程序制品可以复用，插件不在制品中安装。启动前校验程序摘要、私有插件路径和共享存档路由；未授权的越界链接或其它数据重定向会拒绝操作。

在任一实例的官方设置界面修改模型配置后，启动器通过原生设置接口同步其它运行实例。
不同字段的改动可合并；同一字段发生并行修改时保留原配置并提示冲突，避免后保存的表单覆盖另一边。
API 密钥由原生凭据存储共享，提示和日志不展示密钥值。模型配置仍可在官方 UI 中编辑，欢迎说明等界面设置保持各实例独立。

切换实例后，共享默认工作区中的记录和标题会自动更新；重启后仍可查看。
列表同步通过只读接口进行，同一会话的写入继续受 DSH 原生单写入者锁保护。
工作区排序、置顶和归档等界面偏好仍属于各实例，删除的工作区注册不会被同步重新创建。

「插件市场」支持搜索、查看能力和安装精确 npm 版本；实例详情可以启用、停用和移除已安装的第三方插件。核心运行组件受保护。「技能市场」支持搜索 GitHub 技能、检查固定提交和目录，再安装到当前实例；停用技能会保留在私有 `home/skills-disabled`。共享工作区中的隐式技能扫描已关闭，内置官方技能仍可用。

修改插件或技能前停止实例并关闭其终端，实际依赖与原生锁随实例保留。原生插件安装由固定版本的 DSH CLI 执行，错误可在操作日志中查看。这些是 DSH 原生插件，与 WorldlineBox 资产插件分属不同协议。

目录隔离不等于操作系统沙盒。第三方插件代码、Agent 访问的其他项目和远端服务仍有其自身权限；外部资源不随实例快照回滚。

## 当前 CLI 与浏览器

启动器的实时终端页面已移除。实例详情仍可将某个实例设为当前 CLI，伙伴后续任务直接使用它的精确程序版本、已配置的 DSH 账户、模型、插件与技能，不需要先打开 Web 工作台。切换默认实例不改变已经运行的任务。

应用栏新增独立「浏览器」，默认首页和新标签均为空白页，预置哔哩哔哩、Pixiv、GitHub、Bing 搜索收藏，支持多标签、历史、持久登录与下载管理，见 [内置浏览器与全局网络](browser.md)。浏览器和 DSH 工作台共用代理策略，站点存储分别保留。

## 整合包

停止已配置的实例，在「快照与备份」生成整合包并指定名称和包版本。`.dshpack` 保存精确程序摘要要求、profile 配置、锁文件、已解析插件依赖和技能，**不包含运行文件、会话、账户凭据、`.env`、浏览器数据或工作区**。它是 WorldlineBox 自有格式，不是上游 DSH 或 PackForge 的格式。

在「整合包」导出、导入或安装。新版 Node 整合包携带官方源完整性、Node / npm 身份和完整依赖锁；目标缺少运行文件时按该锁安装，拒绝把同版本但不同依赖的环境当成相同环境。旧版包继续要求精确程序摘要。每次安装创建新实例，因此同版本不同包、不同 DSH 版本的包，以及同一包的多个副本均可并存。

「导出分享文件」生成 `.dshpack`、公开 `.manifest.json` 和 `.sha256` 三个文件。填写归档 HTTPS 地址后，其他人可先检查清单摘要，再从链接下载并验证导入。内置 GitHub 发布功能上传归档、清单和校验文件，默认保留草稿；Token 只用于本次发布，不保存。公开整合包不包含账号、会话或工作区数据。

导入检查每个文件的摘要、清单、路径和容量限制，拒绝未列明文件、链接、路径逃逸及大小写冲突。生成包时拒绝明显凭据和不可移植配置；分享前仍需审查自定义代码，静态检查不能判断任意代码的全部行为。

## 升级、回退、快照和完整备份

升级时选择「创建升级副本」，指定新运行版本。旧实例保留，私有插件、技能与执行配置复制到新目录后验证；会话、工作区、账户和模型配置继续使用当前共享存档。要回退，停止新副本并启动旧实例，可把旧实例设为默认；共享存档不会随程序回退，不同数据格式的兼容性仍需验证。

「创建快照」在停机后封存实例的私有 Home、技能和执行环境。恢复会校验摘要并创建新实例，不覆盖原实例；它继续使用当前共享存档，避免回退插件时顺带回退全局会话或账户。浏览器分区、缓存与运行锁不复制。

当前已知 DSH 0.2.0-rc.2 的旧会话与工作区内部路径会迁到新实例，聊天事件内容保持原样。故意选择的外部项目仍是外部项目；未知会话格式不会盲目改写，迁移失败会保留原环境与备份。

「导出完整备份」包含精确运行文件、实例 Home / agents / workspace / user 数据（已迁入共享层的内容不重复复制），以及共享会话、工作区、账户和模型配置；导入、导出前需停止所有 DSH 实例与 CLI。管理器工作台的浏览器分区（Cookies、LocalStorage）、可再生缓存和进程锁不在归档内。恢复合并缺失数据，已有会话、文件与凭据不被替换；模型同字段冲突先预检处理。备份包含账户秘密，不宜公开分享；缺少对应运行版本时，可从备份内的密封程序恢复。

运行中不允许复制、生成包或修改依赖。耗时操作有进度、取消和失败记录；中断不会视为成功，既有实例不会因新副本失败而被替换。

## 操作记录与错误提示

「操作记录」保存下载、导入、启动等操作的时间和结果，历史失败用于排查，并不表示当前操作仍然失败。启动软件时不会把已有失败重新弹成红色提示；新发生的失败才会提示。关闭提示或重试同类操作后，旧提示不再反复出现，原记录仍可查看。

「清理已结束记录」只删除已完成、失败、取消或中断的记录及其操作日志。已提交或运行中的任务保留；运行版本、安装包缓存、实例、插件、整合包、快照和实例运行日志均不受影响。

普通结果提示显示在右下角浮层，不推动页面布局或改变滚动位置。成功提示短时收起；错误可关闭、展开详细信息或进入操作记录。官方 DSH 预览说明仍由 DSH 自身显示。

下载任务显示各自的字节数、实时速度和阶段。依赖安装分为解析清单、按包计数的下载与校验、本地安装、运行文件封存；未知总量时显示活动进度，网络空闲时速度归零。下载阶段可以暂停、继续或取消；校验与提交阶段仅提供取消。不同版本可并行安装，各自使用独立临时目录与计数器，经过完整性校验的依赖下载缓存会跨版本、跨重试复用，相同依赖的多个安装位置只下载一份归档。运行版本索引按顺序提交。失败或中断可点击「重新下载」创建新任务；重启后的未完成任务标为中断。暂停是在本次运行内保留网络流，不承诺服务器支持跨重启的字节续传。

「网络设置 → 测试连接」会显示注册表、解析出的 npm 子进程代理和响应时间。选择「跟随系统代理」时，安装使用系统对注册表返回的首选路线；Clash 的规则仍决定该连接在代理内如何转发。保存新设置后，对后续请求和新启动的安装命令生效；已运行的安装子进程不会在中途切换线路。依赖缓存可以减少重复下载，实际带宽还取决于本机网络、代理节点和上游服务。

「依赖解析与下载线路」默认「自动择优」：使用官方注册表时，比较官方与 npmmirror 的完整依赖元数据响应，也比较依赖归档的实际下载，减少解析清单和传输时的等待。官方 DSH 入口包使用官方版本目录的摘要校验，依赖按解析出的锁校验；请求继续遵循当前代理。镜像解析遇到网络、缺包或版本缺失错误时最多回退官方一次，完整性失败会停止安装。可改为「仅使用所填注册表」关闭；填写自定义注册表时保持该线路。

技能仓库检查、已安装组件列表与整合包分享表单在侧边抽屉中打开，完成加载不会把主列表往下推。音乐播放器位于「设置 → 音乐」，参见 [音乐使用说明](music.md)。
