# DSH 启动器

Windows x64 上，启动器管理官方 DSH 运行版本和原生实例。伙伴与用户工作台使用同一个共享 Web Host，每位伙伴保留独立工作区与原生会话。插件、技能、原生账号配置和会话使用 DSH 的管理机制。

## 首次使用与其他版本

Windows x64 安装包含 DSH 0.2.2-rc.5、Node 和运行依赖。首次打开 WorldlineBox 会从本地安装资源准备兜底实例「WorldlineBox DSH」。从较早版本升级时，启动器会为已有兜底实例保存升级前快照，并在原实例上验证新版本。准备完成后，在启动器中打开工作台。工作台登录和调用在线模型需要相应账号与网络。

如要加装其他版本，在「运行版本 → 官方版本」选择版本，再创建实例或升级现有实例。一个版本可建立多个实例，多个版本的实例可以同时运行。启动器默认使用「WorldlineBox DSH」。要换用其他实例，选中它并点击「设为共享执行实例」。此选择会在重启后保留。旧版没有记录选择来源的实例保留原有目录和数据，首次升级后由兜底实例接任共享执行。

内置兜底版本不可移除，对应实例不可归档、删除或切换运行版本。可随时选中兜底实例并设为共享执行实例。如果归档当前的共享执行实例，启动器会优先选择兜底实例。

通过 `02-Start-Development.bat` 启动开发版时，启动器也会复用已登记的同版 DSH，或使用本地准备好的 `.tools/dsh-runtime-release/dsh-runtime` 资源创建兜底实例。缺少两者时，可在开发环境执行 `node scripts/stage-bundled-dsh.mjs` 准备该资源。

默认实例会在应用启动后连接 Web Host。关闭工作台窗口后 Host 继续运行，可用「停止实例」结束服务。退出应用会清理受管进程。

预热时点击「启动实例」会等待同一次启动，服务就绪后直接打开工作台。原生 Host 首次启动 30 秒内没有输出时，启动器会停止该进程并自动重试一次，两次共用 120 秒的就绪等待时间。失败详情可在实例概览和运行日志查看。

官方发布通道可能先更新标签、后补齐依赖。安装失败会保留实际错误，不会偷偷换成另一个版本。已安装版本按制品摘要固定，刷新列表或安装新版本不会改变已有实例。删除版本前必须先处理实例、快照、整合包和正在执行任务的引用。

## 伙伴如何使用

每发送一条消息，桥接插件就在对应伙伴的工作区新建原生 DSH 会话，注入当前请求、角色提示词、VCP 召回证据与聊天工具。DSH 自己完成模型、文件工具、子代理、审批和存档。聊天气泡实时显示执行过程，结束后显示最终正文，可以展开查看过程。表情包与记忆工具继续可用，原生文件交付直接成为聊天附件。

每条消息拥有独立会话与来源记录，不自动重放整段聊天历史。需要前文时，伙伴可主动查询获准聊天、VCP 记忆或本人工作区的原生会话，也可以创建原生子会话协作。取消回复只取消对应会话，其他伙伴和用户的 Host 继续运行。旧任务中心已经移除，历史聊天和文件仍保留。

不再需要的旧实例可以先停止，再点「删除实例」。仍运行的终端、任务或其他操作会给出具体提示；删除操作自身不构成占用。只删除所选实例及其本地数据，其他实例继续保留。

插件和技能统一在共享 DSH 原生工作台管理。启动器只提供实例、运行版本、整合包与操作记录，不再提供插件市场、技能市场、伙伴能力目录或实例插件管理。所有伙伴共用一次登录、API 和插件配置；新建伙伴不再创建额外实例。启用或关闭某位伙伴不会关闭其他伙伴正在使用的共享 Host。

选定的共享环境保持统一生命周期，执行任务时合并启动请求。旧专属实例仍为历史任务保留，已接受的任务不随共享实例切换而搬移，也不会自动重发。需要持续接收平台消息时可选择「保持连接」。

「升级运行版本」切换程序引用而非重建实例。操作先保存原数据快照，保持环境 ID、会话、附件、浏览器登录分区、存储、技能和配置路径；新版本验证失败则恢复。原有「复制／升级副本」用于另建新环境，不能与这个保留状态的升级混为一谈。

伙伴默认复用自己的工作目录，DSH 工作区分组使用伙伴当前名称，例如「小肥鱼」，后续任务会话集中在该分组中。改名不移动文件；同名伙伴仍有各自独立的目录。明确指定已有项目目录的任务沿用项目工作区，不替换它的名称。

「正在连接 Web Host」、模型处理和工具执行是不同阶段。Host 已运行时不会每次重新安装依赖、遍历整套程序或启动一个伙伴 CLI。耗时包含原生会话执行和记忆准备时间。

## 插件与技能

打开对应实例的原生 DSH 工作台，在其中管理插件与技能。安装、移除、启用、停用和技能发现均交给 DSH；同一实例的用户与伙伴使用相同的原生配置。支持热加载的插件可在 Host 运行时生效，需要重启的插件按原生工作台提示处理。

安装一个全局 npm 包不等于把它注册为 DSH 插件；原生 DSH 也需要 `dsh plugin add` 或插件管理器登记。使用启动器管理的终端时，命令沿用所选实例的原生 `web` profile。软件保留真实 `USERPROFILE`、`APPDATA`、用户 PATH 和工具环境，插件可正常发现其系统依赖。软件不会改写官方全局 DSH 安装。

## 实例、复制与备份

每个实例分别拥有 DSH Home、agents 目录、默认工作区和浏览器存储。用户与伙伴共用所选实例，实例之间没有额外的共享存档层，也不会合并不同版本的内部文件格式。

复制与升级副本保留原生配置、账号、插件和技能，创建新的会话空间、工作区及浏览器存储。原实例保留，可先在副本中验证新 DSH 的配置和插件兼容性。

快照和完整备份保存停止实例的原生 Home、会话、agents 和工作区，恢复为新实例。快照要求保留匹配的精确运行版本；完整备份额外包含运行制品，可在缺失时校验并导入。实例的插件依赖目录不直接复制，恢复时由原生包管理器安装。浏览器登录存储不导出。备份可能包含模型密钥和私密会话，应放在可信位置。

整合包用于分享配置与技能，不包含账号凭据、会话、工作区、浏览器数据或 `node_modules`。它保存运行版本与插件依赖锁，安装到新实例时恢复原生依赖；启动器桥接插件由当前应用提供。不要把整合包当作个人数据备份。

## 数据位置

正常开发版与安装版均使用 `%APPDATA%/WorldlineBox/dsh`：

- `runtimes.json`、`runtimes/`：固定的官方版本与验证回执。
- `native-instances.json`、`instances/<id>/home`、`agents`、`workspace`：原生实例。
- `native-snapshots.json`、`snapshots/`、`packs/`：快照和整合包。
- `operations/`：启动器管理操作；旧 `task-records/` 仅保留已有历史记录。

应用级网络设置位于 `%APPDATA%/WorldlineBox/network`。旧 `dsh-launcher` 目录不再参与读取、迁移或执行。查看实现和实测记录可参考 [开发说明](../developer/dsh-launcher.md) 与 [本次验收](../developer/dsh-native-web-acceptance-2026-10-25.md)。
