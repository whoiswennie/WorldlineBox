# 防御性生命周期模式

[English](defensive-patterns.md) | 中文

## 初始化事务

一个插件初始化多个资源时，使用单个 effect 或显式事务：按创建逆序回滚，只有全部成功后才发布 ready 状态。初始化异常不得遗留路由、监听器、进程或 registry 项。

## 取消与超时

- 调用方取消、策略超时和 Fiber 卸载是不同来源，但必须汇合到一次幂等终止。
- 超时覆盖完整操作，而不是只覆盖第一段 I/O。
- 清理过程必须有自己的上限，不能无限等待不合作的子进程。
- 超时发生后发布 timeout 结果，不得稍后发布成功。

## 发布提交点

先完成持久化或状态变更，再发事件和更新缓存。失败操作不得产生“看起来成功”的 UI、日志或 Telemetry。

## 资源所有权

- 创建资源的 Fiber 负责释放资源。
- Registry contribution 必须可撤销，并测试单独卸载贡献插件。
- 后台任务、Watcher、PTY、Worker 和 Child Process 都必须加入 quiescence。
- 不允许依赖进程退出替代 disposer。

## 文件系统

先解析和验证最终绝对路径，再执行写入、移动或删除；符号链接和大小写规则属于 Provider。原子写入使用同目录临时文件和提交点，失败后清理临时文件。

## 跨边界输入

在配置、文件、JSON、模型工具、Remote、Worker 和进程边界验证。相同进程内已经由 TypeScript 保证的值不重复进行敌意验证。
