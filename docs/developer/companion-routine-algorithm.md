# 伙伴虚拟作息与离线推进

作息是同一个 SQLite owner 内的角色生活模拟。时区、睡醒时间、用餐和习惯属于可编辑的生活计划；这些计划不证明角色做过现实操作，也不会自动形成用户长期事实。内置伙伴采用按稳定角色 ID 编写的初始习惯，定制伙伴采用通用午休计划；不从头像或人格关键词猜测所谓专业参数。所有养成计数从计划实际创建或变更时间开始。

## 时间与阶段

`sleepAt`、`wakeAt` 和活动 `at` 是世界时区中的 `HH:mm`。全部伙伴作息统一跟随世界 IANA 时区，`system` 解析为宿主实际时区；不能再单独设置一个与世界不同的生活时区。每天按世界当地日历展开睡眠、餐食、休息和习惯，跨夜睡眠使用次日醒来时间。冲突优先级为睡眠、用餐、休息、其他习惯；同优先级先开始者优先，再按标题稳定排序。被更高优先级活动遮盖的习惯不算完整履行。

夏令时跳时中的不存在时间移动到后续第一个有效当地时刻；重叠时间只采用第一次出现。参与分钟、精力和习惯按真实家具参与窗口内经历的世界时间累计，步行及坐下/躺下过渡不计参与。切换时间模式按持久现实轴分段，返回实时日期倒退不会使已参与时间变负或丢失。计划阶段由已推进游标对应的世界时间计算，实际阶段以当前位置、家具和动作完成情况为准。应用关闭期间无需定时逐分钟写数据库，重新打开时分批推进到当前时间；不会补发一串过去的自模拟消息。

## 精力

精力 `E ∈ [0,100]`，每个实际时间片按阶段系数 `r` 更新：

```text
E_next = clamp(E + r × elapsedMilliseconds / 60,000, 0, 100)
```

| 阶段 | 每分钟变化 |
| --- | ---: |
| 清醒空闲或临时回应 | -0.08 |
| 睡眠 | +0.30 |
| 用餐 | +0.50 |
| 休息 | +0.15 |
| 运动习惯 | -0.12 |
| 学习习惯 | -0.06 |
| 休闲习惯 | +0.04 |
| 其他习惯 | -0.04 |

这些系数是虚拟产品参数，不是生理模型。宿主实际回复和任务启动另按实际事件扣除精力。离线积分保留中途达到上下界的饱和过程，不能简单把整段正负变化相加后只截断一次。完整且时区偏移稳定的当地周复用仿射截断映射；夏令时变化周单独分段计算。缓存最多 128 个计划/周类型，编辑大量计划不会无限增长。

## 养成

只有活动从计划生效后完整开始并结束、未被更高优先级活动或真实打断遮盖，才增加 `completedCount`。完成归属按 `end > chunkStart && end <= chunkEnd` 判断；分周计算时不会漏掉跨分块边界的习惯。计划刚建立时已进行一半的活动不补算完成。修改无关字段保留原习惯起始点，修改习惯自身定义才为该习惯重新计数。

```text
strength = 100 × (1 - exp(-completedCount / 14))
```

`streak` 是最近一次未完整履行后连续完整履行的次数。紧急互动的持久打断窗口排除与其相交的习惯；同一窗口重复或多个窗口重叠不会重复扣次数。strength、streak、completedCount 是可解释的虚拟养成指标，不允许模型或表单直接填写。

## 工作、唤醒与范围

睡眠、用餐、休息和习惯期间，普通新工作留在队列。宿主先检查原始作息，再认领工作，不能通过先标记 running 绕过休息。真实紧急用户请求可唤醒最多 30 分钟；否定、假设、引用和故事中的紧急文字不算请求。这个窗口只允许原始紧急消息及同一会话、序号不早于它的新后续对话，不放行旧的普通积压或主动联系。固定承诺可以单独唤醒，但不放行聊天积压；用户允许的弹性任务延后到实际下一阶段后重新检查精力，不虚构恢复时间。

仍在执行真实工作时，公开状态显示“正在处理已答应的事，作息暂延”。只有没有其他实际工作或行动时才结束临时回应。状态不扩大任务权限，普通作息问题不授权修改配置。私聊或其日程作息表单修改配置时记录真实用户来源；群聊只显示通用阶段与活动类别，隐藏私人习惯标题、进度和来源，不能修改私人作息。配置来源被遗忘或删除后，不再复用该配置的标题或原因，恢复为作者起始计划并重新计数。

阶段审计是最多 200 条的自模拟内部记录，不进入正式用户消息或自动长期事实提取。私人作息不能通过恢复时的缓存状态、公开情绪来源或群聊工具结果重新暴露。
