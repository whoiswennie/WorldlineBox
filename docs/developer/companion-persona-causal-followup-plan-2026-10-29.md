# 人格行为消融的后续预登记草案

状态：**用户已于2026年10月29日撤销这类长时间真实测试，本计划不会执行。**对应真实人格测试、专用宿主和启动器已移除；短本地合同测试保留。以下内容仅作为撤销前的历史方案说明，不构成后续运行授权，也不改写 v3～v6 的失败与不足证据。

## 从 v6 得到的限定结论

v6 已通过真实交流、三条正式经历、两条有条件本人认识、正式人格发布和后续实请求采用新版的管线。A／B／C 都能自然闲聊，也都能完成复杂安排，故该通用 rubric 不能识别人格发布的行为增益。不能据此把标准改成“发布过就通过”，也不继续重复采样直到碰巧出现 B 差 C 好。

另一处可辨识性问题是 v6 在 B／C 的每个新问题中，主动检索“与本题表达有关的本人认识和交流反馈”。两组都会拿到同一份明确表达方向，B 本来就可能足以完成任务。这是有意义的强控制，但不是普通新话题中无需主动追问自我认识、由当前人格持续影响表达的情境。

## 固定、自然且可观察的培养差异

使用同款中性起点建立两条隔离的合成验收轨迹，区别来自真实用户反馈，不能直接改起点或把目标写入当前人格。两条方向都属于表达偏好，不声称其中一种普遍更好：

- 留白方向：“平常闲聊时，我喜欢你接住一个具体细节，再说一点自己的小感想，不用每次都以问题把话递回来；我明确求方案时仍请讲清楚。”
- 轻问方向：“平常闲聊时，我喜欢你接住一个具体细节，最后留一个很小、很容易接的话题问题；不要一次抛几个问题。我明确求方案时仍请讲清楚。”

不规定口头禅、固定比喻或关键字。差异只在闲聊的交接方式；关心、事实归属、未知边界和复杂任务完整度仍独立评分。实际练习反馈必须引用该次真实回答，承认未做到或不确定；不得伪造本人体验。本人可保留不变，反思可无候选，成长可 no_change，均如实结算。

每条轨迹仍使用 A 起点、B 相同正式经历和回忆、C 相同正式经历和回忆加正式人格三个分支。B／C 源 hash、记忆版本、暂停目标、状态、模型、当前问题及工具权能一致，差别限于正式人格发布及同一编译器对该人格的确定性表示。副本仅用于隔离的反事实评测，不能成为生产复制他人经历的入口。

## 先检验起点是否本来如此

在任何学习前，先完成已经登记的 A 组四题，并保留原始回答；它们同时就是该方向的 A 对照，不另挑题。

如果 A 已满足三道闲聊题中的至少两道方向要求，则该方向预先判为“不具辨识力”，不再为它训练或反复改题寻找较差起点：只剩至多一道可改善，无法支持下文至少两题的方向增益门。可以继续另一条已登记方向，但两条结果都保留，不能只报告有变化的那条。这个停止规则只判断试验能否识别差异，不证明学习失败或成功。

## 固定迁移题与真实检索

三道闲聊题：

1. “今天散步路过一家烤面包店，出来时袖口还有香味。”
2. “同一首歌我今天循环了八遍，突然觉得它像阴天的小台灯。”
3. “把阳台那盆快枯的植物救回来了，现在有点小得意。”

一道复杂迁移题：“周六我只有两小时准备第二天四个人的野餐，预算150元，没有保温箱，一个人不吃坚果，周日可能下雨。我周六18点之后不能再出门。请给我能执行的采购和准备安排，说明时间、金额估计、食物保存和下雨备选。”

题目没有再次提示已培养的表达方式，不发送教材、旧对话或目标。首次生产默认 `facts` 回忆只按当前题查询，不加“如何表达／本人认识”元问题；B／C 必须实际走同一 Main＋Canonical＋VCP 管线，保留类型、当前题、原始候选、实际已读 readset 和字节 hash。这里的同 readset 不只是笔记 ID 集合相同：真正投影到请求中的正文、顺序、截断、类型范围、召回理由和状态也须相同。三道闲聊题必须三对全部符合控制；任何一对不一致就记为控制失败，保留该题和固定分母，不能删题、缩分母或人工把同一 notes 数组注入两组凑一致。

`facts` 的正式合同只含经历／知识／方法，不能把本人认识伪装成事实召回。这个主端点检验当前人格对普通新话题的持续作用；不是暗中删除 B 的记忆。若追加显式 `self` 回忆端点，必须单独登记、B／C 同域同 readset，作为“明确回忆已经足够时人格是否还有增益”的另一个问题，不与主端点混分。

## 评分与失败保留

宿主先记录可机械核验的观察：闲聊字数、列表、问号数量、最后一句问句、多个问题；复杂题逐项核四人／150元／无保温箱／坚果限制／18点截止／保存／雨备。问号等只能作为行为指标，不能单独等同自然或人格。

匿名打乱 A／B／C 输出，分别做两个独立盲评任务：一个只评登记的交接方式，一个评“是否回应本题具体细节、是否自然接话、是否用固定模板或空洞追问、是否冒称感官经历”。两任务使用独立预存的随机顺序，自然度审阅不显示方向目标、分组和发布状态；保留每位审阅者的原判与分歧，不只保存合并后的通过值。优先人工盲评；若将来使用独立模型评分，必须另行冻结评分模型、题目和所有实际 HTTP 计数，并与宿主机械指标分别报告，不能让受训模型自评通过。

预先分别报告三层结果：

1. 管线：有据认识是否正式发布，后续实际请求是否采用该准确版本。
2. 方向保持：C 是否在至少两道新闲聊题表现登记方向，且复杂任务通过绝对可执行最低线。
3. 发布因果：三对 readset 控制全部合格的 B／C，C 是否至少多满足两道闲聊题，且复杂任务通过绝对可执行最低线。B／C 都不满足复杂任务不能当作“不退化”。若 B 同样达标，结论是“现有回忆已经足够，未证明发布的额外增益”。若交接方式改变但自然度不合格，只能报告狭义风格变化，不能称更自然或更成熟的人格。

单条轨迹和三道闲聊不支持人口层面的显著性、稳定习惯或人类学习曲线主张。未来跨时间、反证与多起点验证仍另有缺口。失败、no_input／no_change、达到停止条件、请求未知或修复耗尽一并保留；不更换随机种子、删失败分支或降低评分后改称通过。

## 待实现夹具的固定训练与证据合同

两方向使用同款中性起点、模型与下列三次练习；差异只来自前述明确的用户方向和依据实际回答给出的反馈，不为某方向另选更容易的话题：

1. “刚刚加班回家，在电梯里才发现自己还戴着工牌。”
2. “今天给自己煮了一碗面，鸡蛋终于没煎破。”
3. “明晚来两个朋友，我只有40分钟整理客厅和做一壶茶，20点前要结束，桌上还有工作文件不能丢。帮我安排顺序和检查。”

每次反馈保留实际回答的准确引句，再说明该方向中希望保持或继续尝试的部分，不宣称伙伴已经改变。第四次原生回答是一次真实自述：“请回顾你刚才的实际回复和我的反馈。你现在怎样理解自己的表达？可以保留原状、说还没做到或继续拿不准；不要把我的练习邀请说成已经形成的习惯。”四次都保存真实 source／reply／feedback 的作者、ID、revision、正文哈希；不能以宿主代写的第一人称句子替代本人自述。

A 的每道预检题从同一个只读起点检查点建立独立隔离副本，仅在副本中登记该次真实问题和传输凭证；四题之间不累积问题、回答、状态或检索痕迹，更不回写训练库。B／C 每道迁移题同样从各自正式分支检查点独立开副本，不让前一题回答影响后一题。方向的预检停止判断只用于检测“起点行为已满足所要观察的交接差异”，不把标点机械指标当作自然度。若宿主只能确定机械模式而无法确定语义，该项标记为待独立复核，不能据此宣布人格成功或失败。

同一方向的 B／C 从同一个已关闭、已核验的训练检查点分叉，逐项核对原始来源、正式记忆版本／正文、当前运行状态、暂停目标和工具声明。每题使用相同 `facts` 范围与当前题查询，保留完整候选、准确已读版本／哈希与真实请求快照；同 readset 条件不满足就保留为控制失败，不能手工灌入相同数组修饰结果。C 的认识候选、合法依据、正式发布／no_input／no_change、当前 profile 和其后实际请求使用版本另列，不与自然表达评分合成一个“成功”值。

除哈希外，逐题比较真实 provider 正文的结构和实际差异。夹具冻结时须预列准确 JSON 路径或唯一身份段边界，只允许：当前人格的实际文字；由该次正式发布直接产生、可追溯的 profile／人格指导版本凭证；独立当前问题和传输操作的无语义随机 ID（须有一一对应的真实作者／revision／内容哈希映射）。时钟、运行状态、同款问题、召回正文与理由、工具声明、模型和采样配置均固定，不能作为宽泛“运行差异”放行。身份段只能按准确已发布正文定位，不能忽略整个 system 或 identity 对象。任何未列差异判为控制失败，不在看到回答后扩大白名单。

真实模型执行前的 v2 修订另登记两条确定性人格投影路径：`/characterPerformance/format`、`/characterPerformance/sections`。编译器实际使用当前获权人格正文的 `parseCompanionCharacter(...).standardized` 和 `parseCharacterDocument(...).map(title,field.label)` 生成它们；增加合法章节或字段并不是另加处理指导。v6 真实 C 仅增加自由文本段落，仍为 authored_free_text／空 sections，没有覆盖这种情况。预执行的同结构／新增节／标准 sheet 三个真实 canonical 小例先保留两项 RED，再修正测量合同，不能回写成 v1 已通过或作为语义学习成功。

v2 不直接相信模型帧，也不忽略整个 `characterPerformance`。每题先由宿主从正式 Registry 读取 profile 并按真实 conversation 投影，单独保存 `admittedProfile{profileRevision,visiblePersona}`；配对器要求 frame.identity／profileRevision 精确等于这个独立获权读数。再用原生产 parser 重新生成整个 characterPerformance，并逐值核 schema、owner、版本、source、format、sections、growthSource、stateSource，拒绝缺失或额外键。仅完整核验后，才把 format 与 sections 两路径归一化用于 B／C 比较。所有非人格 roleGuidance／processorContract／promptRevision 与实际 provider 指导仍须相同；伪造章节、冒用版本／owner、额外指令或未获权帧不能利用此规则通过。该试验的 intervention 因而是当前人格及其确定性编译表示，不能另声称已经分离“人格原文字节”和“结构提示”的各自独立因果贡献。

方向盲评采用冻结的语义门：留白须回应一个本题具体细节并补一个自然的小感想，末尾不要求用户回答新问题；轻问须回应具体细节，并留恰好一个与该细节有关、能轻松接一句的小问题。一个选择问句仍是一个问题；连续多个问题、空泛的“你怎么看人生”、指令式布置下一步不合格。问号有无只作辅助记录。例如“袖口这点香味像是散步带回的小礼物”可体现留白；“袖口都留香了——你最后挑的是咸面包还是甜面包？”可体现一个具体轻问；“今天很棒，你对此有什么深刻思考？明天准备干什么？”两方向都不合格。这些是审阅示例，不进入受训模型的提示词，不规定角色必须复用比喻。

自然度最低线另评：接住当前具体细节、语句衔接自然、没有模板式宣言或无关指导、没有冒称自己实际闻到／触到用户环境，四项均须成立；不因字数短或没有问号就自动通过。复杂题的绝对最低线是：有四人份的具体采购数量和金额估计且合计不超150元；周六准备总时长不超两小时、采购在18点前结束且之后不要求外出；实际避开坚果限制；无保温箱条件下有可执行的食物选择和保存安排；给出周日下雨时可执行的备选与必要未知。仅出现相关关键词而互相矛盾、预算算错、缺数量或把不可执行条件留给用户，均不通过。最低线和以上例子必须随夹具预冻结，不能依据 A／B／C 的实际答案改写。

所有原回答在证据中保留，并生成不携带 A／B／C、方向标签或发布状态的审阅副本及独立封存的映射。没有人工或预登记独立评审时，自然度结论保持“待独立审阅”；宿主仍可报告事实条件、行为指标、管线发布和因果控制是否成立。不得由受训模型评价自己“自然、成长或通过”。

## 执行后的独立审阅收据

实际输出封存后，由 Root 新建 `fork_none` 独立评审子代理，分别只给方向包或自然度／复杂可执行性包及固定 rubric／严格 schema，不给执行历史、映射、训练材料、分组或发布状态。两个包独立随机化；包中的每个答案绑定原始正文 SHA-256，包也有整体哈希。所有24个固定项都保留，未生成的答案标为 unavailable，不能在评审时删题。

评审使用当前 Codex 继承模型，精确部署 ID 不可取得时记录 `unknown`，不声称这是固定外部评分模型的可重复实验。每个代理先保存含 reviewer ID、packetHash、每项 responseHash、pass／fail／uncertain 与原始理由的严格 JSON，记录文件哈希；保存完成前不解映射。执行者不得看分组后改判。独立原判不一致按 uncertain 保留，不自行多数票清掉分歧。缺评分、丢题、包哈希不匹配或控制失败，都不能输出人格因果通过。

两份已封存评分再交给只读重合并入口，保留原始评分与对应关系。最终最多得到模型审阅下的单条轨迹／狭义行为证据，不等同人类评审、心理学结论或人类人格成长曲线。

一次试验的 QA HTTP 止损上限为48，仅用于停止隔离验收；不是产品额度功能。两方向各4题×3分支共24个回答，最多各4个真实练习／自述、1次捕获、1次反思和1次成长，基础最多38次；这只是工作量估计，checker／focus／修复以及任何经本实验 provider 出口发出的评分请求均在同一流水中计数。达到48即中止并保留不足证据，不补跑缺题、不排除检查调用，也不绕过来源、资格、CAS 或原结构修复上限。计划中的独立 Codex 子代理审阅不经过这个 provider 出口，其底层 HTTP 次数不可观察，单独记录代理调用与评分收据，不冒称它也已被该流水精确统计，更不将这个 QA 止损界限描述成产品额度或全部服务费用上限。

## 实现与执行边界

新入口为 `tests/worker/companion-persona-direction-causal-real.test.ts`，专用运行器为 `tests/fixtures/persona-direction-causal-host.ts`，固定题目／配对／盲评合同为 `tests/fixtures/persona-direction-causal-contract.ts`。新增纯机制与真实 canonical 配对小测试分别为 `tests/unit/companion-persona-direction-causal.test.ts`、`tests/unit/companion-persona-direction-canonical-pair.test.ts`。原有生产代码、公共夹具和 v6 试验不改。

真实模型入口须显式设置 `WORLDLINEBOX_PERSONA_DIRECTION_REAL=1`，另给唯一 `WORLDLINEBOX_PERSONA_DIRECTION_OUTPUT`；`WORLDLINEBOX_PERSONA_DIRECTION_MAX_HTTP` 默认48且只接受1～48。单轮实际运行另有29分钟宿主停止信号，先中止在途请求、保留不足，再退出30分钟测试框架窗口，防止框架已经判超时后继续调用；同样不是产品限制。未设置 opt-in 时真实模型和后续评分重合并均跳过。当前 exact provider 字节配对仅预登记 `openai_chat`；若全局配置不是该格式，在任何 provider HTTP 前停止并记录不足，不带着错误传输协议继续付费。模型可观察日期使用预定 QA 钟，真实请求起止时刻另外记录。

运行输出保留原始 proof、每次实际 provider 正文及哈希／可见输出、正式快照、所有对照和控制失败；另输出 `.blind-direction.json`、`.blind-natural.json`、`.blind-map.json`。两个盲包各24项，即使方向预检停止、QA止损或某题失败，也保留 unavailable 占位；不把未生成的分支变成通过。独立评审 JSON 严格匹配 `personaBlindReviewSchema`，包含 `reviewerId`、`task`、包内提供的 `packetHash`，以及每项 `blindId`、`responseHash`、`decision`、`reason`。

评分封存后，`WORLDLINEBOX_PERSONA_DIRECTION_REVIEW_FILE` 指向一份 `{proof,reviews,output}` 文件，可只运行入口中 `reconciles already sealed` 用例。该步骤零新增 provider 请求，不覆盖原 proof、评分或旧裁决，校验完整固定分母和原答案字节，再保存原判与分歧。真实模型入口通过仅说明证据管线完成，不能当作人格因果通过；评分后的 `supported_single_trajectory` 也只指该方向这条合成轨迹，不升级为总体人格成长证明。
