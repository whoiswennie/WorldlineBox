# 伙伴身份、通信与社交观察

实现入口：`main/companions/identity.ts`、`main/companions/social-model.ts`、`companions/social-store.ts`、`shared/companion-social.ts` 与 `renderer/companions/CompanionSocialMonitor.tsx`。

## 身份与当前回复

主脑和各 provider 共用宿主生成的身份投影，不以 API 的 `role=user` 推断真实发言者：该角色只是传递上下文 JSON 的信封。`identity.self` 固定当前伙伴，`participants` 是实际成员，玩家使用独立 ID `user`；伙伴专属会话不添加玩家。玩家群里 NPC 对另一 NPC 发言时，玩家仍保留为实际成员。

`currentReply` 绑定真实来源、speaker、addressee 和回复锚点。行动结果回复原 `sourceMessageId` 的作者，后续新消息或工具文字不能改变对象；恢复循环沿用原任务范围，同时刷新宿主身份。被指向的伙伴与其他成员的发言机会分别表达，无内容时允许 PASS。

作者设定的姐妹关系绑定角色 ID：小肥鱼的姐姐是大肥鱼，不能把私聊玩家默认当作姐姐。玩家明确指定自己的称呼可以使用，但称呼不改变真实身份。历史 assistant 的错误称呼、引述和转述不能成为身份事实。

## 唯一会话、实际通信与存档

伙伴之间的手机与现场发言共用正式 `messages`，实际作者始终是说话的伙伴。玩家与伙伴的私聊、玩家群聊与伙伴社交房间互相隔离。两人私聊按无序两成员唯一，三人及以上群聊按完整无序成员集合唯一，标题不参与身份判断。房间保存在原有 SQLite 数据库，只有 UtilityProcess 持有连接。

`social.conversation.ensure` 创建或查找隐藏的伙伴房间，`social.send` 提交发件意图。原生聊天工具在主进程对当前玩家原话做语义分享授权；只有实际授权消息 ID 留在宿主待发记录中，玩家私聊内容和来源 ID 不写进伙伴社交消息。伙伴自主发言不冒充玩家，也不能产生玩家任务或 DSH 授权。

手机初次发件至少经历 1.2 秒真实输入状态。睡眠、用餐和真实电脑集中工作期间保留持久待发；普通休息、兴趣活动和行走不再按活动类别一概禁用手机，姿态衔接仍由宿主完成。接收者暂时不能回复时，清醒发送者仍可发出真实来信，接收者的回复等待合适时机。现场交谈要求双方确实处于同一现场且距离不超过五格。手机不要求进入对方房屋，来信事件不公开发送者的私屋位置。

同一伙伴的待发和回复共享一个输入租约。另一条待发、来信通知或旧失败回调不能覆盖或清除当前输入。正式消息、收件人、虚拟发生时间、世界事件、记忆提取队列与交谈链账本在一个事务内提交；未发出的草稿不会成为正式历史或记忆证据。重试使用固定 clientId，改变内容会被拒绝。

玩家聊天也参与同一手机时序，只有 `companion_world_work_records` 中实际 `ready` 的 `chat` 才占用，`waiting` 不会抢先锁住手机。已核验急事可以接手；旧 peer 结果或受托回报在提交时重新核验该占用，退回原 pending 作业，结束后重领同一个事件，不在玩家对话期间偷偷发送。

一次自主交谈最多四条正式消息，包含首条，最多三次回复。群聊每条最多选择一位下一回应者，不向所有成员分配回复。模型返回空文本即结束该链。自主新话题每伙伴虚拟日最多两次，同时间隔至少六虚拟小时和 120 现实秒；回复每伙伴虚拟日最多八次。当前玩家明确授权的发件可以越过自主话题限额，仍需遵守身体状态与输入时序。每个回复任务最多尝试八次，失败与尝试次数持久保存在任务账本，避免永久重复调用模型。

`social.job.claim/complete/fail` 使用持久租约。claim 固定本次来源序号及最近五十条可见消息的校验集合，complete 在同一事务重新核验来源可见性、正文、作者与会话。模型生成期间发生遗忘、更正或删除时，旧结果不能重新发布秘密。当前进程停止后，租约到期可重领同一个任务，不重复已有正式消息。每位伙伴每轮按索引扫描最多 32 个候选，保存并轮转扫描位置；只有实际开始输入或领取任务才占用本人。旧的配额等待或失去现场条件的消息不会永久挡住后续可执行消息，积压者也不会挤掉其他伙伴的处理机会。

每位实际群收件人都有独立目标事件，共用同一正式发言来源。关系评价只接受本次模型实际观察的真实事件，核验真实发言者、收件人、来源及置信度，沿用伙伴独立关系算法与世界时区的日额度。普通问候不按聊天次数自动增加好感；来源撤回会撤销其关系增量。伙伴社交不增加玩家关系。

## 只读观察 API

- `social.conversations {companionId?, day?, query?, before?, limit?}` 返回 `socialConversationPage`，按本次匹配消息的实际更新时间倒序、ID 倒序。日期或搜索筛选后的预览、条数与更新时间使用同一范围，不显示所选过去日期之外的新正文。
- `social.messages {conversationId, day?, query?, before?, around?, limit?}` 返回 `socialMessagePage`。每页是游标之前最近的一页，页内序号升序；继续向前使用最小序号 `nextCursor.sequence`。`around` 必须属于同一伙伴房间且满足当前日期和搜索范围，否则拒绝，不会跳进玩家私聊。
- `social.days {companionId?, month?, query?}` 返回所选虚拟月份按天汇总的消息数与会话数。

页面附带 `timeZone / observedDay / virtualNow / backlog`。日期按单一世界时钟及世界时区的虚拟日计算，支持 DST 的 23/25 小时日；消息 `createdAt` 保留真实写入时间，`virtualCreatedAt` 另行展示。离线推进未追上时使用已实际推进的时刻，不宣称完成离线认知。搜索使用编码 Unicode 字符的 FTS 索引，短中文无需 embedding 或全表 LIKE。

内部 `social.message.append` 用于宿主已有真实发言的原子登记及隔离验收，可附真实同房间 `replyToId`，不会自动创建另一条回复链。公开观察面板只有查询能力。

## 主脑与分享边界

世界决策结合人格、真实作息、兴趣、精力、可见事件和独立伙伴关系选择是否联系，没有新内容时不发言。`world_social` 是独立的无工具认知目的，只读取当前伙伴会话可访问的正式来源、自己的安全状态与公开世界投影。成员位置、真实天气时钟和关系可参与判断；玩家任务原因、其他会话原话、私有作息来源与私人标题不会随全景快照传给社交推理。

伙伴话语不能触发玩家 DSH、文件操作、用户日程或授权。玩家当前明确要求转告时，主脑 `world.message` 才能落实实际收件人和内容；`world_message_authorization` 仅核对当前玩家原话的逐字证据、发送意图与内容范围，旧任务、主动联系、引用、假设或否定不授予转发权限。发送后仍由对应伙伴署名，不能替玩家或收件人承诺。

## 观察界面与工作概览

入口是「伙伴 → 社交」。左侧选择世界日期、伙伴和唯一会话，右侧复用 `CompanionMessageBubble`、头像、Markdown、引用及消息时间。观察视角只决定哪位伙伴的气泡靠右，每条保留真实作者和“对谁说”，不会把伙伴改名为玩家。界面显示虚拟时刻，悬停可查看现实记录时间。会话与消息分别分页、搜索；跨页引用遵守相同筛选。上翻阅读时新消息不抢走位置，提供回到最新记录按钮。面板没有发送框，观察不会加入成员、改变社交关系或生成未读。

右侧手帐的「工作台」与日程便签分开：读取所属伙伴的正式工作单，汇总进行中、待处理和暂停状态，最多预览两条。点击预览在独立工作台展示真实发布者、完整要求、数据修订和成果；关联行动按实际 actionId 打开执行记录，不从模型文字生成假进度。已完成旧消息链接仍打开历史记录。内部伙伴工作不能在玩家管理表单中改成外部授权；玩家工作须暂停后在原发布聊天中修改。

## 委托来源与事件回报

`social-continuity-store.ts` 把原玩家委托与伙伴交谈链分别持久化。传给 peer 模型的 `origin` 仅含实际发起者、委托伙伴与已授权共享的正文，不含原玩家私聊、消息 ID 或完整请求。它在 outbox、chain、job 的每一轮保留；`identity.self/currentReply.author` 始终是当前回复作者，`currentReply.speaker` 是本条来信者，`origin.initiatorId=user` 仍是独立真人，不能因姐姐/妹妹人设改为姐姐。

玩家委托的真实 peer 回复、拜访许可变化会建立耐久 notification outbox。原玩家消息校验、对应 peer 消息或拜访事件校验、拥有者状态与可见范围在提交时再次复核；正式回报以原伙伴本人署名，回到原玩家聊天并引用原委托。事件键和固定 clientId 去重，租约到期可恢复。来源遗忘、重置、删除或变化后，已领取的旧结果也不能提交；模型只收到这一个已确认事件和最小共享来源，不读取整段其他私聊。

拜访回应若绑定房主的消息来源，建立回报前先在房主原会话范围复核来源，领取和提交时再检查可见性、正式状态与来源指纹。来源被遗忘或重置后，不再从原始拜访表取出旧回应供模型使用。房主来源 ID、私聊 ID 和指纹仅留在宿主内部；回报只含已明确共享的回应，公共的允许/拒绝事实与已经实际送达的历史不因这一校验被改写。

这是已获授权事项的后续，关闭自主联系不会阻断。自主初次联系仍尊重保存的 false；新建资料默认 true，不覆盖既有选择。邀请回应与实际到场分别记录，回复说可以来玩不能当作已经见面。生成文本仍需模型正确理解给定事实，这些宿主校验不等于保证语言绝无误解。

`world_social` 可对当前真实 peer 明确提出的工作返回有来源的 `workOffer`。宿主核验 sourceMessageId 与逐字 evidence，在同一完成事务内派生真实发布者、固定当前接收者，创建 internal/offered；接收者本轮明确接受才转为 accepted。来源不能是玩家、自己或其他房间；它不会继承原玩家外部执行权限。普通建议、邀约和引用不应被模型提为工作，伪造证据会在消息与工作单共同落盘前拒绝。

主脑原生 `work`、`life_rule` 的写操作另外要求当前真实 user 来源和逐字证据，并通过 `companion_management_authorization` 核对具体对象、操作与完整限制；语义复核后再次检查来源。旧记忆与主动机会不能新增授权。工作暂停或取消经过 Main 的实际终止路径；规则创建与工作创建都用固定 clientId 支持回包丢失后的幂等重试。

## 验收证据与限制

`tests/worker/companion-social-store.test.ts` 与独立 `companion-social-review.test.ts` 验证实际 SQLite、严格 IPC 响应、日期范围与 DST、分页与搜索、输入租约、重启待发、来源撤回、远程关系与故障事务回滚。

`tests/e2e/companion-social.test.ts` 使用本地 provider 验证真实 IPC、持久待发、睡眠等待、手机动作、私聊/群聊接续和成员复用；`companion-social-monitor.test.ts` 验证只读界面与分页。后者工作状态明确使用 `synthetic_action_fixture`，不把合成记录当成真实任务执行或模型语义通过。

`companion-social-continuity.test.ts` 验证真实 SQLite 的原发起者持续传递、关闭主动联系后的受托回报、重启租约、事件去重、来源撤回与内部工作权限；`companion-management-authorization.test.ts` 和真实 Service 测试验证具体管理语义、当前源范围与终止确认。`companion-work-life.test.ts` 验证实际工作台与日常事件的保存、修订、取消、跨夜窗口、重启和移除，使用暂停的合成工作单，不把 UI 状态当作真实执行成功。

在线身份语义样例于 2026-10-15 尝试生产同款 Electron `net.fetch`：`player_after_wrong_history` 和 `action_feedback_original_player` 连续两次达到 120 秒超时，第三条已取消、第四条未发送，随后停止重试。未修改真实用户存档，也未执行现实工具。这是历史失败记录，原始尝试回执不随源码分发。这些样例没有得到模型回答，不能作为真实模型语义通过的证据；宿主身份、接口协议和本地行为链分别验收。

正式界面与手机行为回归可运行 `node scripts/run-e2e.mjs tests/e2e/companion-social.test.ts tests/e2e/companion-social-monitor.test.ts`；截图和报告写入本地忽略目录 `.tools/test-output/companions/`，不作为源码资产提交。
