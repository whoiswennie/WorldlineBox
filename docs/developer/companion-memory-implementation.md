# 伙伴自治记忆实施说明

日期：2026-10-14。设计依据：[无 Embedding 自治记忆设计](design-companion-autonomous-memory.md)及 [VCP 调研记录](research-vcp-companion-memory.md)。这两份文档保留研究与设计要求；本文描述当前代码路径、可检查的行为及尚未覆盖的部分。

## 消息、记忆与模型职责

`messages.sqlite` 继续由 UtilityProcess 独占写入。本次已按维护者授权直接清空本机旧聊天、消息、记忆及关联任务，保留联系人资料与模型配置。代码只维护当前数据结构，不按旧编号保留实现分支或迁移旧聊天。此后的正式消息是已发送、实际提交的记录；未发送草稿和失败消息不自动成为事实。消息来源包含聊天、作者、序号、修订、正文校验与时间。消息提交时登记观察者和待处理项，后台按持久化位置补登记尚未整理的正式消息；模型调用在 SQLite 事务外运行，提交时再校验来源与任务租约。

`CompanionMemoryService` 使用该伙伴已有模型连接提取新信息，写入前检索相关旧记忆与标签。没有增加一个能读取所有伙伴私人内容的审核角色。前台循环优先，后台按批次处理；连接不可用时队列保留，模型错误保存原因并重试。后台恢复按来源身份、修订和正文校验核对，不能把网络调用描述成天然恰好执行一次。`captureMethod` 区分自动收录与手工补充；内容修订号只用于纠正和并发审计，不是代码兼容版本。

类型覆盖事实、偏好、约定、经历、任务状态、伙伴感想、知识与经验、阶段概览和假设。证据状态区分明确表达、已确认、主观、假设、冲突和来源待核查；无消息证据的手工补充保留待核查状态。事件状态区分计划、进行中、完成、取消和重新考虑。引用、玩笑、猜测与未完成操作的区别由提取提示和宿主证据校验共同处理，但正文确实存在并不能证明模型的解释必然正确。

## 自动形成与原生工具

后台提取与主脑原生工具共用存储入口。`memory.record` 要求真实来源及逐字证据；`memory.revise` 带读取过的修订号；`memory.organize` 维护标签或事件归属；`memory.forget` 按用户请求提交规则。`memory.search` 查找相关事实、事件、标签与原话，`memory.read` 展开来源前后文及关联记录。外部电脑操作仍交给 `dsh`，记忆请求直接由宿主处理。

写入在同一事务内更新权威记录、来源、事实修订、标签关系与必要全文索引。旧来源晚处理不能覆盖更晚的事实；来源重复提交按身份核对。更正保留历史关系，当前查询与历史查询分别选择有效记录。存在冲突、尚未核查的无证据记录不能直接冒充当前已确认事实。

## 自动召回与可见范围

每次普通回复在建立基础上下文前形成查询；采用当前用户请求及最近相关消息，先走可直接执行的检索路径，需要语义理解时由当前聊天模型生成本次检索词。查询结合主体、事实键、事件、标准标签及别名、字符全文、时间和有来源的关系。关系扩展目前有界，不运行 VCP 的向量投影、EPA 或 RiverMemo 数值算法。主脑遇到证据不足时还可调用记忆工具继续核查。

没有配置或调用 Embedding 模型，没有引入向量数据库。召回集合与来源按相关性和范围取得，没有额外的主脑总字符预算；消息和来源原文不按该预算静默截断。分页、有限关系展开和最近消息窗口仍用于检索与持续聊天。模型服务本身能否接收某次完整请求仍受其上下文能力限制。

群聊仅使用本群可见来源；私聊使用该伙伴合法观察到的经历，不能借实体名、别名或关系读取另一伙伴独有的私聊。回复查询绑定源消息序号，较晚事实不能进入较早已启动请求。原始消息检索和来源展开也检查观察范围、来源修订及遗忘规则。

## 修正、遗忘与用户可见状态

「我们之间」打开紧凑的伙伴手帐，记忆按钮另开最大 1160 px 的管理弹窗。弹窗采用列表与来源阅读双栏，通过 `memory.browse` 与 `memory.inspect` 提供分页、关键词、类型与状态筛选，展示标签、证据性质和事件状态。管理界面允许查看无证据的手工记录，主脑 `memory.search`/`memory.read` 仍严格校验来源。已遗忘记录只返回无正文和来源的墓碑。来源详情可展开原消息及关联修订，再定位到实际聊天记录；任务结果信源显示可读结果并打开任务详情，不在时间线重复制造技术气泡。手动补充是可选入口，日常收录与召回不依赖这个入口。修正带当前修订号，失败时保留编辑内容，不能显示保存成功。

遗忘先写规则和失效状态；后续召回、原文补查与后台提交均检查规则。指定旧来源的遗忘不自动变成对未来新信息的永久禁止；持续规则另行标识。聊天原文默认保留，普通历史浏览与记忆召回职责不同。遗忘操作不在审计正文复制被遗忘内容。

后台状态包括待处理、处理中、失败、已完成、消息位置、提取位置、尚未整理消息登记位置和最后错误，在记忆窗口中默认折叠。水位表示已处理来源的位置，不表示每条消息都值得形成长期记忆。UI 可以重试失败项；无需用户手动安排正常收录。数据库内容与模型工作分开，因此刚提交的正式记忆无需等另一个异步向量索引完成。

伙伴手帐主体用于当前状态、周历和便签待办。`state.get` 与 `routine.get` 读取当前聊天范围内合法可见的状态，`onChanged` 更新精力、PAD、关系、作息和真实执行情况；完整人格留在联系人资料。PAD 和关系细项放在可展开详情，不把内部字段堆在侧栏。日程单独使用大窗口管理，所有创建、编辑、暂停、取消和立即执行都调用当前真实命令，编辑带修订校验。作息与习惯编辑读取实际配置后提交，不以界面自造值替代宿主状态。状态计算与产品参数见 [连续状态与关系算法](companion-state-algorithm.md)。

初始生活计划由作者按内置伙伴稳定标识编写；自定义伙伴采用通用午休，不根据关键词猜测人格。初始习惯完成次数为零，不作为过去经历进入事实记忆。养成程度、完成次数和连续性从实际经过的虚拟作息推导；真正运行中的回复或任务优先占用活动时间，不能同时虚计习惯完成。用户可从私聊日程窗口编辑，也可通过明确的聊天要求由原生 `routine` 工具检查并修改。群聊只读公开状态，私人习惯内容与编辑入口不进入群聊。离线虚拟时钟推进不等于离线执行外部电脑任务；计算规则见 [作息与习惯算法](companion-routine-algorithm.md)。

## 流式回复与正式发布

聊天模型通过真实 SSE 将当前轮次的可见正文增量传入同一个消息气泡。OpenAI Chat Completions、Responses、Claude、Gemini 和 DashScope 各自使用原生流式协议；结构化记忆提取仍在完整 JSON 校验后处理。界面不展示思考字段、JSON 包装或尚未完成的工具参数，工具只在模型正常结束且完整决策已持久化后执行。

流式事件独立于整页状态通知，首个正文片段立即发送，后续片段约每 60 ms 合并；只有对应气泡订阅更新。持久化草稿约每 750 ms 合并写入，中断立即保存，重试和恢复按同一气泡、同一步骤替换未完成尝试。读取历史时新增片段不抢走滚动位置。服务重启可恢复草稿，但不会将半段回复当成已完成的回答。

草稿和工具循环尚未完成的消息不发布为正式信源，不进入全文搜索、自动记忆收录或其他请求的召回上下文。整轮完成后才一次发布完整来源并安排记忆处理；同样的正文从草稿转为正式记录也会完成索引登记。取消会终止模型读取并阻止尚未启动的工具，网络重试不会追加重复气泡。

## 验证与真实边界

本次 UI 测试使用明确 fixture，三个测试文件共 48 项通过：记忆面板 9 项、伙伴 UI 34 项、手帐/日程/作息 5 项。场景覆盖分页与范围参数、类型及历史筛选、持久化水位与错误重试、来源及修订展开、修订校验修正、确认遗忘、失败草稿保留、旧搜索响应失效、后台更新不打断来源阅读、任务结果可读展开、遗忘墓碑，以及人物名称使用日常称呼且不暴露内部事实键或管理枚举。新增场景核对实时状态刷新、详细数值按需展开、延期说明、日程修订与重复字段清理、暂停和取消语义、失败创建幂等重试、作息真实配置保存与只读养成进度，以及群作息无写入口。隐藏的任务或填表来源不会重复显示在消息时间线或提醒引用中；原始证据仍可从管理窗口核查。这些测试不调用真实模型，不能证明自然语言抽取或语义召回准确率。存储、模型协议和完整服务测试应分别核对来源校验、并发、断点恢复、范围隔离与遗忘再提取，结果以本次实际测试输出为准。

两项实际 Electron 验收已分别通过。自动记忆用例从空临时用户目录启动，通过普通「我喜欢看海」自动形成有来源的偏好，下一次普通提问收到自动召回；并实测并发修订冲突拒绝覆盖、刷新后保存、确认遗忘，以及重启后仅返回脱敏墓碑且召回为空。手帐用例通过普通感谢消息和有来源的原生状态调用更新 PAD 与关系，在 UI 创建数秒后的提醒并确认只收到一次真实消息，再创建弹性任务、调整作息与习惯并检查联系人完整人设。时钟自然推进曾导致状态修订必然冲突，已修复并增加实际调用成功断言。

两项均使用真实 Preload、IPC、Main、UtilityProcess 与 SQLite，仅外部模型由本地 HTTP fixture 替代，不调用真实付费模型。界面检查包含独立记忆双栏、320 px 手帐无横向溢出、日程与作息大窗口，以及亮暗两种主题。记忆截图为 `artifacts/companions/verified-memory-system*.png`，手帐、日程和作息截图为 `verified-companion-journal-*.png`、`verified-companion-schedules-*.png`、`verified-companion-routine-*.png`。这些是实际应用界面截图，不能当作真实模型语义准确率或长期养成效果的评测。

最终统一构建 Main、Preload、存储进程和 Renderer 后，两项桌面用例在同一轮运行通过，输出 `2 passed (1.3m)`；自动记忆用例 52.3 秒，手帐/日程用例 22.9 秒。最终八张截图已逐张检查，已有历史截图没有改写。

当前具备自动增量形成、查询理解、多路召回、来源核查、事实修订和可见管理闭环。后台还会在新原子记录形成相关簇，或任务结果进入完成/取消状态时，自主整理有实际来源的事件/年月阶段概览、经验和伙伴感想。整理读取原子记录及真实消息，生成结果必须逐条保留证据及贡献记录依赖；更正或遗忘会使依赖它的派生记录失效，原子内容仍保留。阶段概览使用稳定主体和事实键延续同一主题，不以旧摘要充当新事实证据。

自主整理已经有独立模型/服务测试，覆盖真实任务来源生成概览与带适用条件和局限的经验、拒绝无证据或未读记录依赖，以及后续更正的派生失效。它属于当前后台增量工作；当前全文索引可在存储 owner 的事务内从权威记录重建，只有一套现行规则。完整实体歧义治理、跨多年多级阶段导航、脱离新来源触发的独立反思计划和经验反例的自动验证，仍需专门实现和评测。

在 100,000 条原始消息的本机 SQLite 全文检索验收中，各查询中位耗时为 0.37–2.11 ms，较深游标查询约 1.64 ms。这是本地原文索引查询测量，不能代表额外模型调用、记忆形成或完整回复链路延迟，也不代替多年连续运行测试。

额外成本来自提取和查询理解的聊天模型调用。模型不可用时基础检索仍可工作，但隐含语义能力下降。没有多年连续运行负载或标注集结果时，不能宣称已经做到完美准确、无遗漏、固定低成本，或保证每一条过去信息每次都能被想到。
