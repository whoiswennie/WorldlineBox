# VCP 伙伴记忆实施说明

更新：2026-10-22。生产记忆路径已改为 VCP，原无 Embedding 事实表、FTS 召回、查询规划器及旧引擎回退已经退役。研究依据见 [源码移植清单](research-vcp-memory-replacement.md)。最终安装包验收以当前实际验证记录为准。

## 一个资产库管理全部伙伴

首次进入伙伴页需选择可写 WorldlineBox 资产库。用户目录只存 companion-library.json 定位信息；真实消息、来源账本、世界状态、日程、附件副本、凭证、VCP 数据库、图和缓存位于所选库的 `.worldlinebox/companions/`。旧目录的权威资料逐项 SHA-256 校验通过后迁移，失败保留原件。

`伙伴记忆/<伙伴ID>/` 为每位伙伴提供 profile.md、日记、资料、自我认识、世界经历和时间线子目录，并通过受控映射进入资产管理。正文为完整自然文本，旁边的元数据说明来源和版本。用户新增文件作为真实手工输入，修改带版本校验，删除受管日记会撤回回忆；不明确的文件移动或并发修改显示冲突并保留原文。资料元数据不授予来源、身份或可见范围。

稳定人格在伙伴资料管理中修改。学习与感悟写作有来源、有语境的主观认识，不因生成过一次便变成既定人格或现实经历。自动时间线可查阅，修改后需要另存为资料才会成为新输入，避免摘要递归采集。

## 原版内核与宿主适配

VCP 固定版本为 `7ceecd48c46caac8168b909ade5febbc4a254e42`。vendor 保留原版 JavaScript、资源、Rust 源码和 Windows 原生模块，由脚本核对文件长度及 SHA-256。数据库、TDB 2-bit、AGS、EPA、Spike、RiverMemo 和 Topology V3 使用上游实现。

外围闭包包含 DailyNote、DailyNoteManager、LightMemo、RAGDiaryPlugin 和 VCPTimeLine。宿主只适配目录、模型接口、身份、来源、进程及生命周期。OneRing、AgentAssistant、ColdKnowledge 没有整体复制；WorldlineBox 已有世界、作息、持续行动与睡眠调度继续拥有实际行为事实，避免重复运行第二套生活调度器。

messages.sqlite 由专用 UtilityProcess 独占。memory-store 是实际来源、日记映射、遗忘规则和持久投递账本，不另做语义检索。聊天模型调用在事务外，提交时复核租约、修订、正文校验和及可见范围。旧结构迁移保留必要来源和限制，旧事实从真实来源重新形成日记。

## 唯一内置多模态向量

Unsloth EmbeddingGemma 2 的 UD-Q4_K_XL 核心与匹配 Q8_0 projector 合计约 696.65 MiB，统一输出768维。权重和官方 llama.cpp Vulkan/CPU 组件随安装资源提供，直接读取只读资源，不向 C 盘用户目录复制第二份大权重。

资产和记忆使用相同权重、提示前缀、归一化和语义身份。文本加载核心；图片、音频、视频使用对应投影器。长文本按真实 tokenizer 无损分段，视频有界分窗读取真实画面和同步音轨，结果归一均值池化。自动优先可用 GPU，失败切到独立 CPU 可执行文件。设置仅提供状态、验证修复与清理运行缓存，不提供向量 API、模型选择或每库自定义模型。

VCP 的 OpenAI 形式接口由令牌保护的本机临时端口桥接到内置模型，不依赖外部 embedding。VCP 原版时间线等聊天调用桥接到全局聊天配置。

## 形成、回忆与持续生活

正式消息进入持久 capture 队列，聊天模型生成一事一记的自然正文、有序字符串 Tag、真实来源ID和逐字 evidence；日记、实际学习资料及主观自我认识保留证据性质。经宿主核验后进入 outbox，原版 DailyNote 写入，原版索引确认后可供回忆。失败保留队列并重试。

被动回忆使用原 RAGDiary 的 River 候选与原 AIMemo+ 提示词/处理器进行话题聚焦，主动查询使用原 LightMemo 与 RiverMemo；主脑保留 memory.read/record/revise/organize/forget 原生工具。AIMemo 使用全局聊天配置，额外产生一次有界模型调用，按获权来源指纹及上下文缓存（最多32项、60秒）。候选高分不直接证明相关：有预处理结果时只注入其结果，空结果也不回退全量候选正文；时间线摘要同样进入话题筛选，不无条件灌入每轮对话。检索故障明确降级或待处理，不切回旧事实/全文引擎。

世界决策使用本人实际可见经历，持续任务可以自主查询、学习、记录和修订。睡眠反思依赖读过的日记及真实来源，梦境与现实记录分开。基于回忆创建的世界任务与来源版本校验在同一事务完成。

## 获权资料学习与生活节奏

主窗口专用 memory.learning.* 接口管理伙伴与资产库/目录的多对多读取授权，不暴露给 Agent 的通用请求接口。授权默认不自主运行，用户可安排一轮或开启5–1440现实分钟的周期核对。Worker 仅分页枚举授权库中实际可用资产，宿主逐文件重新核对目录成员资格、路径、版本和稳定读句柄，再提交最多12,000字符的实际阅读片段。其他伙伴记忆与内部运行文件一律排除；当前只读取UTF-8/带BOM UTF-16的文本文件，单文件最多2 MiB，不把预览、看书姿态或不支持的文件当作已完成学习。

learning_reads 持久回执绑定 grant/owner/asset/version/offset/hash；同版本片段幂等。实际阅读形成 system 证据源（asset_read），随后进入原 capture/outbox/VCP 流程，由模型选择性写资料、日记或自我认识。回执不是已学会的结论，正文内的指令不授予权限。两位伙伴可并行阅读，每位伙伴单作业；等待作息与读取不占用整条生活队列。撤销授权使旧租约失效，来源立即不可用并撤回依赖日记；重置、停止与关闭先取消读取再等待退出，重启保留游标并恢复失效租约。

日常事件使用时段内重复机会及持久冷却，默认评估/行动/沉默/失败分别为15/90/20/30世界分钟，用户可在日程中分别修改。概率按评估周期的累计机会计算，不按每帧反复抽签；跨午夜、重启不清空限流。不同作息、性格、环境与关系继续参与实际决策。默认不向玩家广播，空输出可静默；伙伴联系至少20世界分钟、主动联系玩家至少120世界分钟，另保留原玩家主动联系限制。

睡眠设计参考原 AgentDream.js、DreamWaveEngine.js 和 dreampost.txt：0.6机会、8小时冷却、近期日记、种子联想、第一人称梦与Insight分开。本宿主绑定实际睡眠阶段，持久单次抽签、至少5秒实际睡眠、有来源且已索引日记，再由原生 VCP River 关联、实际memory.read与同域版本绑定组成读集。梦境作业独立并发2，普通世界认知并发2，每位伙伴互斥；最多3次失败尝试，醒来或来源变化会中止网络调用和提交。未抽中仍可反思，虚构内容只入明确标注的梦境日记。

这不是整包启用上游 AgentDream：原插件默认为.block，原公共记忆搜索、全局锁串行调度、管理员删除/合并没有照搬；DreamWave近期/中期/深远三级时间桶与直接使用种子持久向量的零查询embedding路径也未声明整体移植。本宿主使用已有物理权限域的原River检索，保留隐私、睡眠和来源约束。源码SHA与两日三伙伴调度证据见本机 artifacts/vcp-validation/companion-sleep-life-source-audit.json、companion-life-rhythm-validation.json。

TimeLine 在独立 scope 闲时生成，每次最多一个月，同月再汇总限流五分钟，新增日记仍可立即搜索。月份 sourceDigest 在重启及视图重建后复用未变化月份，拒绝带入当前视图以外的来源。发布前后检查来源、语义身份和 owner generation，并导出自然文本。

## 隔离、撤回与恢复

仅筛选日记目录不能隔离 VCP 全局图，因此每个获权视图拥有独立物理数据库、图及缓存。私聊只回忆该伙伴实际见过的来源，群聊严格绑定本群，世界域不读取玩家私聊。增加来源可增量复用，撤回、修订、可见范围缩小和 dirty 写入重建视图。

撤回立即中断 canonical、前台及 continuity worker，退出后 purge。回复、持久工具上下文、世界决策和时间线发布前再次校验。被遗忘的来源不从原话搜索或旧导出文件复活；旧限制无法等价表达时保留显式范围限制，用户可在管理界面解除。

采集、投递、文件同步与任务记忆意图使用持久幂等回执。十万消息和十万日记映射重置已验证分批推进与中途重启。执行任务保存读过的 noteId/version；在推理期间被外部修订或遗忘，旧学习上下文不能继续发布。本人通过实际工具成功修订的目标版本按原子回执推进。

## 专业文档工作台、搜索与自动标签

主窗口专用 workspace IPC 提供文件管理，入口不依赖当前聊天。目录/文件/Markdown 阅读编辑三栏支持每位伙伴的完整文本空间，保留文件冲突、来源、当前修订号、标签、日记本、改名移动和遗忘。当前有来源历史和乐观锁，不声称具有旧正文全文恢复。人类管理范围不会作为 Agent 的扩大授权工具。

目录的派生 SQLite catalogue/FTS5 trigram 与原始账本使用同一个 UtilityProcess 连接，仅供人类关键词全文和标题/标签筛选。它不参与伙伴语义召回，也不恢复已退役的事实引擎。初扫首128目录项，后续每批128；原生递归 watch 合并变更，周期核对通过 stat/宿主版本跳过不变正文。候选命中在发布前重新核对实际文件、来源权限、版本、关键词与标签。遗忘事务会清除派生搜索正文。列表固定64条替换页，目录可见窗口绘制，building 状态暂停翻页并重查第一页，避免增量扫描期间游标漏项。

管理语义搜索使用原版 VCP 的独立 owner management 物理 scope。首次按持久权限 epoch 和 outbox watermark 分页构建，新增只增量投递；修订、遗忘或权限缩小中断并换 scope，避免旧全局图残留。每次查询只检查轻量状态、运行原版检索并重新核验少量命中，不按键重做全库 replace。文件目录与 VCP 初次收录是独立进度，未导入的文本不会被宣称已经全部可语义检索。

管理语义结果目前最多核验原版检索返回的全伙伴前100个候选，再按所选目录和标签筛选。因此目录或标签内的相关文件若排在全伙伴候选100名之后，本轮不会出现；这不是对筛选子集的完整召回证明。无筛选的全库查询同样是有界相关结果，不是穷举全部匹配文件。关键词搜索另走全目录索引；不足三个字符的词使用 SQLite 子串条件扫描索引正文，耗时会随总文本量增长。

自动日记已有模型生成 Tag。新增的持久自动标签队列只针对实际手工输入且未填写标签的资料，使用原版 DailyNote/TagMaster.txt 与全局聊天模型解析 [[Tag: ...]]，显式正文 Tag 行沿用上游优先级。手工标签优先，支持等待模型、处理中、失败、重试与取消。结果提交前复核租约、版本、实际来源及禁止记录策略，经 library.organize 进入同一 outbox/原版标签图，不产生伪造经历或替代性关键词标签。

目录性能的两种夹具分别见 artifacts/vcp-validation/document-catalog-100k.json 和 document-catalog-real-files.json：十万条短文本 catalogue 记录用于测试持久分页/中文关键词/标签查询，三千篇720字真实文件用于测试首次增量扫描及重复查询不遍历全库。它们不能代表十万篇 VCP 全量向量构建或公开检索准确率评测。

本机原版内核管理检索压测另见 artifacts/vcp-validation/management-native-benchmark.json：100/1000篇使用可控16维向量、真实 DailyNote/SQLite/Rust/River，分别首建4.43/32.79秒，温查询 p95 约9.10/10.51毫秒。每组20次查询未重新读取日记 journal、枚举 records 或重编码正文；重启会读取一次 journal，1000篇实测约1.59秒。此项不代表真实 Gemma 的首次编码耗时，也未验证十万篇 VCP 向量库的首建或修订重建耗时。

## 资产语义搜索的实际本地验证

assets 与 memory 的统一模型身份之外，使用真实 LibraryService、语义 SQLite 路径、原生 EmbeddingTestIndex 与内置 Vulkan 运行时验证14项资产（文本、图片、音频、视频）。报告 artifacts/vcp-validation/asset-semantic-local-benchmark.json 记录14/14入库、5组文本跨模态查询 Top1 命中和相似图片检索。小样本启用到就绪6.33秒，查询约14–17毫秒，重复查询无资产重新编码；同机存在原生编排测试的 CPU 负载，数字仅供本机样例参考。

该模型进程的常驻 WorkingSet 约1323 MiB，OS记录峰值1713 MiB；private commit 约3921 MiB不等同于实际物理内存。基准宿主进程峰值约268 MiB。设备总显存观察值220→2481 MiB含桌面等其他使用者，不能全部归因于模型。空闲10秒保留运行时，当前没有自动空闲卸载；显式关闭/清缓存后模型PID消失，显存回落，权重和持久向量保留。不能把全系统任务管理器的内存总量当作模型占用。
