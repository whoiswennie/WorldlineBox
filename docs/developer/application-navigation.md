# 应用侧边栏与模块入口

最左侧窄栏属于应用层，资源库、文件夹、合集与工作区标签属于资产模块。DSH 启动器是首项和默认首页，伙伴是第二项，资产管理是第三项；新增完整功能仍通过同一个模块列表接入。伙伴内部另有消息/联系人导航，其角色推理、任务与消息存储在独立后台服务中持续运行。

`src/renderer/ApplicationShell.tsx` 接收 `ApplicationModule[]`。每个模块提供稳定的 `id`、本地化名称、现有图标和 React `content`。`App` 负责当前模块与模块登记，资产工作区由 `AssetManager` 承载。新增功能应使用独立组件，在这个列表登记；不要把模块选择混入资产工作区标签、资源库数据库或资产插件侧边栏。

模块内容使用 React `Activity`：切换时保留组件状态，隐藏模块的 Effect 会清理，重新进入时恢复。新模块的订阅与临时资源必须遵守 Effect 清理规则。需要跨模块持续运行的安装、引擎进程等任务应由主进程服务管理，不依赖页面 Effect 存活。

底部设置按钮和 Ctrl+, / ⌘, 调用应用设置入口，不修改当前模块。现有设置控制器保留在资产模块，通过 `keepEffectsActive` 在全局设置打开时临时恢复，模块视图仍保持 `hidden`。设置、诊断日志和关联提示通过 Portal 在应用层显示；聚合弹窗状态控制保活，避免设置转到日志时中断控制器。隐藏的资产模态不参与 Escape 和焦点处理，资产浏览快捷键只在资产模块启用。关闭后恢复普通 `Activity` 生命周期。Windows 主菜单过滤通用设置项，原生菜单的设置命令继续保留。

`ThemeBackground` 在应用根只挂载一次，位于各模块 `Activity` 之外。动态视频与个人壁纸均由它持有；切换模块不会清理媒体源或重置播放位置。提示和文本编辑菜单宿主也位于应用层。

侧边栏使用语义主题变量，独立于资产背景；窗口拖动区与按钮的 `no-drag` 区分开。资产内部的导航折叠、面板拖动、搜索、预览和上下文菜单继续使用原有实现。

验证覆盖模块状态保留与 Effect 清理、底部设置及快捷键，以及真实 Electron 中的资产导航、工作区标签和动态背景。

2026-10-12 Windows x64 验证：应用导航、资产壳层导航、两项工作区标签页、全局壁纸及两项启动器故障隔离共 7 项 Electron 测试通过。从默认启动器首次打开 AI、插件、MCP 设置和诊断日志均保持当前模块；两套动态壁纸跨模块保留同一视频与来源，不触发重新加载。主应用与浏览器扩展类型检查通过；修改文件 ESLint 无错误，`App.tsx` 保留两条已有 Hook 依赖警告。本轮没有执行其他平台的桌面验证。
