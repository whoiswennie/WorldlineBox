# 伙伴分组、运行中引导与记忆正文修正

## 问题与实现

本机只读检查确认，截图所示原音频约 108 MiB，`send_file` 文件复制端允许 256 MiB，而 Worker 登记接口仍限制 100 MiB。文件复制完成后登记失败，模型又委托 DSH 复制同一个大文件，仍无法消除登记限制。现统一快照阈值为 256 MiB，更大的普通文件使用受登记的本地引用；不再要求模型为发送而转码、压缩或重复复制。

图片内置预览上限为 100 MiB，音视频为 2 GiB。较大音视频通过字节范围流式读取，保留按需播放和拖动能力；超过预览限制仍可系统打开。本地引用依赖原文件位置，不保证文件移动或删除后仍可读。头像、模型视觉输入的像素预算是独立用途，没有随播放阈值一起放大。

DSH 的原生 workspace 按 Session 头中的真实 cwd 识别，且成员必须使用完全相同的 cwd。此前将每个 invocation 的独立目录作为 cwd，同时赋予相同伙伴名称，必然产生多个同名 workspace。现在原生 Session 使用稳定的伙伴目录作为分组标识，各 invocation 的工作及交付目录继续独立，通过明确的任务目录传入执行提示词，并由原目录验证交付。不同任务仍是不同原生 Session。此处是正常并发的目录约定，不代表同一伙伴的 Session 之间存在额外文件系统权限隔离。

`sessionWorkspacePath` 显式记录原生 cwd，`workspacePath` 记录该任务的交付目录；恢复保持原生会话的真实 cwd。删除伙伴时按实际拥有的目录与原生分组清理。已有历史 Session 的不可变 cwd 和历史分组不被强行重写或删除，新任务使用统一分组。

原生桥接的结束判断增加两道检查：提示词接收期间不发布完成；`sessions.flush` 返回后重新核对提示词修订、会话序列和 Agent 状态。引导在保存旧阶段时到达，不再让旧阶段的结束事件终结新任务。

进度核验现在要求每次拒绝指出拟稿中的实际原文，并区分社交事实、附件交付与范围外的本地任务细节。本地复制、格式、大小和执行说明不受窄社交凭据摘要裁决。核验可读取本任务的用户输入及引导；“DSH 已生成文件”仍不等于“本聊天已经附上文件”，没有实际附件回执的交付声明仍会拒绝。

恢复入口只保留在故障消息自身的过程卡片中，按该消息的 `workId` 重试。移除列表末尾的会话级“继续上次回复”提示和未指定任务的重复重试按钮；旧故障不再挂到新消息下方。即使旧 recovery 状态仍在，新回复成功也不会出现会话底部提示；原消息恢复成功后，其故障卡片自动隐藏。

另一条实际索引失败的标签是 `坐标(10,13)`。宿主标签数组允许标签内部标点，VCP DailyNote 的字符串协议却使用逗号等字符分隔标签，接入层原先直接拒绝。这并非正文丢失，也不应将坐标拆成两个标签。现在只在原生传输边界把单个标签内的协议分隔符编码为间隔点，原宿主标签、正文和来源保持原样。启动时仅将旧版这项明确格式错误的耗尽任务重新投递，仍经过普通版本、来源与租约核验，不重置其他失败原因。

## 记忆与元数据边界

- ID、哈希、来源关系、修订版本和租约属于数据库与不可变历史凭证，不作为新的经历。
- 修订历史文件的内部封装保持完整，用于身份校验、撤回和修订读取；人类文档接口、标题、摘要与全文搜索只投影自然语言正文。另存为资料也获得正文，不会复制内部封装。
- 左侧不再展示 `note_<hash>` 修订目录，修订集中在“记忆历史”，列表使用原文标题与“第 N 版”。文档行使用文档图标，目录保留文件夹或类别图标。
- 已有全文搜索目录作为派生数据失效一次，从当前文件重建，清除曾索引过的封装元数据；正文与来源记录保留。
- 日记候选入口拒绝将宿主历史封装或索引锚点作为正文。写作提示词要求机器凭证留在结构字段，正文使用自然称呼、事件和时间。
- VCP 接入层在原生切块、标签处理及 Embedding 请求之前去掉精确的 `WorldlineBoxMemory` 内部锚点。元数据对象本来就不拼入正文；新增真实请求断言覆盖这一边界。
- 语义索引使用新的 `narrative-v2` 代际，从获权正文重建，不沿用含旧锚点的向量或旧预备回忆缓存。
- 普通 JSON、代码、业务编号、文件名和正文中有实质意义的技术信息保留，不按“像 ID”笼统删改。
