## 注意力、消息与浏览器

- 每个伙伴在用户聊天与伙伴社交之间共享一个注意力队列，跨位置的新任务按源消息顺序处理。等待容量为 100 条；满额会明确拒绝登记，不静默丢失已接收消息。消息和任务登记在同一事务中提交。
- 联系人可选择引导或排队，默认引导。同一正在处理的会话可追加引导；其他位置的消息等待当前任务结束。新增通用 `wait` 工具，单次 100～60000 毫秒，支持取消；用户聊天的引导会提前唤醒等待。等待结束不被解释为外部操作成功。
- 浏览器原生视图只有实际打开浏览器模块时可见；伙伴后台动作不抢占聊天画面。同 URL 重用已有标签页，动作后提供新观察、标签摘要和时间戳。隐藏视图使用临时的 CDP 视口，解决 Windows 下零尺寸页面导致读图、点击迟钝的问题。

## 文件交付与完整重置

`send_file` 在气泡内交付图片、GIF、音频、视频和文件卡片。音视频最多 256 MiB、图片最多 20 MiB；更大的媒体登记原文件引用并提供系统打开，避免复制或把数 GB 文件整体读入内存。音视频通过 Range 流播放，同一个播放器跨聊天和模块切换保持播放。PDF 内置预览上限 32 MiB，文本最多读取 128 KiB；不支持的格式可通过文件位置交给系统应用。

重置在后台逐阶段报告进度，允许不同伙伴分别重置。先设置写入屏障、取消并排空模型/工具/DSH/记忆任务，再清理聊天、记忆、来源、决策与角色运行资料、资产索引和伙伴受管工作目录。共享 DSH 插件、账号和配置保留。原生会话按 DSH 官方归档接口结束；不直接抹除上游自身管理的全部归档日志。

### 内存边界

原版 TDB 的 FP32 文档向量按 ID 从 SQLite 读取；压缩导航码、位置表和活跃关系图仍会占用随数据增长的内存。四个原生进程是数量预算，不是总 RSS 字节上限。本轮保留原版算法及 SQLite 参数，没有宣称索引完全不驻留 RAM。

宿主原先每个打开的 scope 常驻全部日记正文，现改为薄目录和有界正文 LRU。目录仅保存身份、状态、路径、必要归属字段、内容哈希和指纹；任意大 metadata 与正文共同进入有界记录缓存，命中时才按需读取。正常差量同步按指纹比较，不再先 `list()` 复制全部旧正文。梦境继续使用原版算法，目录验证改读内容哈希与字节数。

| 宿主缓存 | 生产默认预算 |
| --- | --- |
| 每个原生 scope 的完整正文记录 | 16 条、2 MiB |
| 完整回忆收据 | 每 scope 32 条、4 MiB |
| 全局视图元数据 | 16 份、16 MiB |
| 全局月度时间线缓存 | 8 份、8 MiB |

视图超大条目只落盘、不长期驻留；未完成原子保存可短暂固定，已落盘 dirty 状态允许驱逐，恢复后强制新范围而不伪装 clean。失效清理遍历持久清单，覆盖已驱逐条目。现场注册表释放已退休模型 client 和已卸载的持久视图；过期的月度生成冷却键会移除。正文删除和关闭同时清理路径目录。

独立记录缓存压力样本为 200 篇、合计 12,000,000 正文字符。薄目录 JSON 为 93,691 字符，不含正文或任意 metadata；正文缓存约 1,994,949 个计费字节，重启恢复后约 1,994,853，均低于 2 MiB。另对多 owner/profile 轮换、反复整理、100 次未提交准备、超大 manifest 及磁盘全 owner 失效执行容量回归。这里验证缓存结构与预算，不把计费字节当作完整应用 RSS 实测。证据：`artifacts/vcp-validation/runtime-record-catalog-pressure.json`、`tests/unit/companion-memory-view-cache-residency.test.ts`。

完整回忆收据限 32 条、4 MiB，并绑定语料 epoch、完整消息、日期/时区和原版解析的时间范围；语料或派生时间线变更立即清除，缓存命中保留真实引用并标明原计算时钟。原版供应文件 129 项校验保持通过。

规模限制仍然存在：轻目录、原生图和查询期间的完整授权快照会随语料增长；一次性 `list/export` 也需要对应结果的内存。因此当前没有承诺任意多年数据下的恒定内存或固定秒数。进一步降低超大库峰值需要轻量清单、分批读取和分批差量同步，而非仅扩大缓存。

### 来源核验与前台排队

根因是一条放大路径：数据库已同步核验完整来源依赖图，但 Main 的全局版本被并发状态更新推进后，会放弃该证明，经带守卫端口逐个重读祖先；共享 DAG 被反复当作树展开。仅增加进度提示和请求内 memo 不能解决这条退路。

- 原子 worker `execution.sources` 为当前持久消息及终态 action 的确切 typed readset 提供 digest。包含来源 checksum、各来源房间成员权限、记忆版本及游标、话题/checkpoint 与传递依赖检查。Main 保留活动授权、协作/思考租约、上下文/模型、外部文件等异步检查。
- 栅栏变化时有界重读确切 SQL 证明，在异步检查后再次核对，以最终同步 SQL 读取作为线性化点；不等待无关世界状态永远停止更新，也不将整张祖先图再次送入 Main。没有证明的历史记录仍走原有完整验证。
- 刷新时证明缺失、读集已更换或运输异常属于本次暂不可核验，不因时间竞争永久撤回健康记录；明确失效才进入原有撤回流程。独立代理复核了该边界，补上了最初“缺少证明即撤回”的错误。

## 后续修复：任务快照、用户停止与跨会话任务中心（2026-10-26）

### 一次被动回忆与持久恢复

用户明确接受任务开始时的旧信息，普通记忆更新不应重做语义检索。旧实现把全局 evidence/corpus 变化当作本次推理变化；即使实际输入仍然有效，也会放弃模型轮次并重新准备，且持久化后台社交任务在重新领取时再次回忆。

现在新任务只准备一次被动回忆，并保存包括空结果在内的任务快照。私聊、群聊、后续工具步骤、原任务停止后恢复以及持久社交推理的租约恢复均复用该快照。普通日记修订、新日志、聚焦模型变化和跨天不会触发同一任务再次被动回忆。后续新任务仍按当时的记忆检索；显式回忆工具仍是独立请求。

被动快照绑定当时实际使用的原始 source checksum 与 note-source 历史，普通正文/标签修订不再强求当前 note 版本。用户明确遗忘、原始来源撤回、会话权限失效仍使旧输入失效；失效不自动追加被动回忆。常规聊天移除失效的模型输入并保留原始工具审计，持久领域日志不能安全恢复时明确拒绝恢复，避免重放已有作用。主动工具读出的实际记忆版本继续按原有精确协议核验。

完整审计另外发现持续活动每步、工作单重新领取、世界决策重试、生活发生项和独立 DSH 完成回报中的宿主自动检索。现在这些入口也使用同一被动检索管线并保存整个任务 ID 对应的初始结果；持续活动不会因 step ID 变化重查。世界/生活及内部工作单最终提交携带实际 typed readset，原子核验确切依赖后提交，不用全库 revision 拒绝普通维护。内部单交付消息保存该执行读集，继续保护后续引用。

持续活动完整回忆和 DSH 回报缓存使用独立冷表；普通任务列表及执行证明读取不解析这些大型正文。DSH 回报的普通 checkpoint.get 默认也不加载回忆；回报路径显式读取，缓存不可替换，随所属 action 删除。生成前后只检查真实输入，聚焦上下文覆盖的候选笔记不再重复按当前版本否决。

### 任务中心与执行控制

新增跨伙伴、群聊及私聊的统一分页目录，覆盖回复、原生执行、持续活动、委托、日程及单次发生、社交/通知、世界任务、学习/学习目标及记忆处理。列表只读有界元数据，不为打开面板加载完整历史模型上下文或原生日志；任务详情保留来源房间、真实用户目标、阶段及时间。

聊天气泡在执行后继续显示完整总用时，终态时钟冻结，包含排队、上下文、回忆和工具执行。任务中心区分创建、实际开始、结束及用户停止时间；未记录的历史时间不推算。

停止只针对所选真实任务及其确切子执行。用户停止以 actor=user、reason=user_requested 持久化，迟到结果不能覆盖；后续模型输入收到相同会话的宿主停止回执。原生硬停止确认后更新终态，已经完成的作用与历史仍保留。回复、原生任务、持续活动等支持沿原 ID/步骤恢复，不另造用户消息或重放确认过的效果。单次日程停止不删除整条周期规则。

每位伙伴跨所有聊天和执行入口共享并发预算，默认 3，可在任务中心设为 1–10 并持久保存。父任务和其实际子工具只占一个槽。降低上限保留已经运行的任务，后续领取等待空位。过期租约不永久占槽；若父租约过期但实际原生子任务仍运行，仍保留一个真实槽并允许同一父任务恢复，避免重复计数和降低额度后的恢复死锁。

限制：记忆来源捕获、索引、时间线与生活规则发生项为可见的维护记录，部分入口只读并给出原因。任务中心没有用“停止成功”假装中断不可独立取消的维护事务。记忆自动标签使用已有按 note 取消入口；周期学习停止保留进度。

## 任务中心统一输入、过程与结果（2026-10-26）

任务中心现有 17 类入口统一使用按需详情：聊天、原生工具、持续活动、委托、计划及单次定时执行、伙伴交流、后续回报、世界决策、实际世界事件、生活规则执行、资料学习、学习目标、来源整理、索引、标签和时间线。实际世界事件独立记录为点事件，不伪装成一段仍在运行的任务，也不为它累计运行时长。

详情提供输入、过程、结果三个页签，保留暖白、灰绿样式。可以查看任务要求、来源作者、已保存的系统提示/注入记忆、工具参数和回执、实际发布的回复、归档日记版本、学习片段和学习总结、时间线及摘要。不是为每轮模型推理额外复制整份数兆级提示词；没有保存的旧输入、旧时间和旧产出会明确说明，当前文档、当前来源不会冒充原执行版本。模型请求、伙伴生成内容和宿主实际记录分别标识，不展示私有思考文本。

准确性保护：

- 开始处理时单独保存来源消息输入；定时执行保存当次计划要求，后续修改计划不会替换旧输入。日记归档只显示本批输出对应的原版本，不能用当前新正文冒充旧版本。
- 伙伴交流与后续回报按真实 `resultMessageId` 读取实际发布内容，包含地址分享等宿主最终添加的文字；不把提交但未发布的模型文本记为已发送。没有发送回执时如实说明。
- 世界提交只在真实运行租约发生提交时保存输出；已经完成的幂等重放不会凭新的请求参数制造产出。失败尝试保存原因；用户停止后的迟到失败不会改写停止结果。
- 世界任务重试等待与已经结束明确区分，开始/结束时间由领域转换记录，保留用户停止请求的时间。其他来源的新状态转换有 SQLite 原子里程碑；旧的未知时间不补造。
- 时间线任务及输入/输出改为持久保存，结束时等待短数据库写入完成。重启后保留历史，异常退出残留的运行状态转为等待后台重新检查。重置清理新增记录；来源撤回、遗忘和学习授权撤回仍阻止读取旧正文。

长内容与性能：

- 列表每页 20 项，仍只返回元数据。计数随实际数据库变更原子维护，打开界面不扫描全部历史正文。分页索引匹配时间倒序、ID 正序，避免同一时间的大量记录触发额外排序；去掉过时重复索引以减少写入开销。任务只读接口不再顺带执行经历文件归档。
- 一个详情页签每页 12 项；数据库先截取正文，界面默认预览 600 字符。展开后每次读取 6,000 个 Unicode 字符，前后段替换而非无限追加。结构化数据按字段呈现，Markdown 标题、列表、表格正常排版；相同内容不会反复解析。
- 完整原生工具归档也能在本面板中按需打开，复用原有来源校验的 `action.record` 入口。每次 20 条、单条默认 2,000 字符及原有 12,000 字符页预算；长条目续读，结构字段每组 20 个，并可定位最终交付。原归档达到保护上限时明确显示，不声称缺失部分已完整保存。
- 变更通知合并刷新，活动详情另有 1.5 秒兜底；已结束详情不设持续轮询计时器，但仍响应变更通知。切换任务、页签、分页或关闭面板会取消旧订阅和忽略迟到响应。

最终 20,000 条工具记录样本：列表查询约 **3.6 毫秒**，选中详情约 **0.8 毫秒**；列表返回 8,536 字符，详情返回 4,691 字符。这是隔离本机 SQLite/存储接口的样本测量，不能当作所有机器的整窗首屏耗时保证，也不等于对百万条、超大单任务日志的完整压力承诺。证据为 `artifacts/task-observation-performance.json`。
