# 伙伴工作单

工作单由同一个 SQLite UtilityProcess 持久化，和普通聊天回复队列、生活日程分开。来源必须是当前真实会话的正式消息；表单发布会原子保存完整的人类要求消息。发布者取实际消息作者，不能由模型声明。玩家来源的工作为 `external`，受理后通过现有行动/DSH 执行；伙伴来源为 `internal`，先 `offered` 等待接收者受理，始终没有玩家的现实执行权限。

公共命令位于 `shared/companion-work-order.ts`：`work-order.list/create/update/accept/pause/cancel`。工作单包含接收者 `companionId`、真实 `publisherId`、来源链、标题、完整要求、状态、数据修订号及实际行动/结果消息引用。列表使用按序号的 keyset 分页；群聊只能管理当前群的工作，私聊只能管理所属伙伴。玩家修改外部工作要求前必须暂停，并在原始聊天中记录新的完整表单及原授权链。伙伴内部单可接受、暂停或取消，不能由玩家表单改写成含玩家消息的伙伴专属房间；要改变其要求，应在玩家自己的聊天中新建授权工作。`expectedRevision` 阻止并发覆盖。

内部协调器通过 `work-order.claim` 获取 `{order, leaseToken, leaseUntil}`，定期 `heartbeat`。同一伙伴当前有效租约不重复认领；进程恢复先中断旧行动并释放旧内部租约，再继续同一张工作。创建行动时通过 `action.workOrderId` 唯一绑定实际执行，重复创建返回原行动。普通现有行动也会自动建立对应工作单，避免实际执行不出现在工作台。

`external` 的成功只能由实际关联行动 `succeeded` 证明，不能提交模型编写的完成文字。行动终态自动同步工作单；协调器随后用原租约读取结果是幂等的。`internal` 的完成则在同一事务复核来源、租约和状态，原子追加接收者本人署名的正式结果消息，再保存 `completed`，重复回包不重复发送。发布来源撤回会阻止迟到提交，并在管理投影中遮蔽已撤回要求与结果。

受理和运行中的工作保持电脑集中期，暂停、失败、取消或全部完成后完整起身并释放。普通聊天原地用手机；实际工作、睡眠或用餐期间的普通消息等待，核验过的急事可打断生活姿态并回应。暂停/取消外部行动仍由 Main 执行标准的实际进程终止，不能仅改变工作单标签。恢复前存储确认旧行动已停止，保留原行动引用以复用真实 checkpoint；改变要求才解除旧行动关联。取消的工作不能通过旧行动详情偷偷恢复。

重置按批清理订单审计、工作单和生活规则/发生记录；源序号水位与已有 owner stop 阻止旧作业复活。自定义联系人删除后取消其未完工作，后续协调器也排除已删除身份。没有执行成功证据的离线时间不能填成工作结果或同时计为习惯参与。

真实 SQLite 定向验证位于 `tests/worker/companion-work-order.test.ts`，覆盖手机站/坐姿与路径恢复、紧急醒来、主动联系关闭、表单来源与并发、电脑集中期与实际行动去重、伙伴工作不获现实权限、来源撤回、内部结果幂等和重启租约恢复。真实工作与既有历史/重置回归另行合跑；不以 UI 标签变化替代执行证明。

主进程自治协调器另由 `tests/unit/companion-autonomy-service.test.ts` 连接真实 SQLite 验证：外部工作等待真实行动终态并完成起身释放；暂停后恢复同一行动及原 checkpoint；内部工作仅向选定模型提供实际伙伴来源、不发送玩家私料或声明外部工具；遗忘后拒绝迟到结果；生活概率累计后只发送一条实际作者问候；取消一个接收者不会取消另一位的工作。`tests/unit/companion-service.test.ts` 同时保留手机回复取消、睡眠语义通知、固定提醒幂等与天气/时间两个源独立循环的验证。
