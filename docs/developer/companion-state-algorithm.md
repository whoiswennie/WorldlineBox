# 伙伴连续状态与关系算法

当前实现由真实互动事件驱动，不让聊天模型直接设置好感、信任、尊重、精力、关系阶段或情绪坐标。模型仅提出带原文证据的语义评价、归因、强度与判断信心；宿主绑定伙伴、聊天和来源后提交。稳定人格始终完整保留，动态状态只调整表达、主动交流与弹性安排。

## 理论框架与产品参数

情绪采用 pleasure、arousal、dominance 三个连续维度。这个表示方式借鉴 PAD 框架，维度分别关注情绪正负、激活程度与控制感；作者也讨论过其在机械系统中的应用。[PAD 研究](https://doi.org/10.1016/0092-6566(77)90037-X)、[PAD 作者说明](https://www.kaaj.com/psych/scales/emotion.html)、[机械系统中的 PAD](https://www.kaaj.com/psych/ai.html)。事件理解借鉴认知评价框架，先说明发生什么、与谁相关、如何评价，再由宿主更新连续状态。[OCC 认知评价框架](https://doi.org/10.1017/CBO9780511571299.004)。这里没有复刻论文中的量表或将游戏关系分数当作心理测量。

本项目的事件冲量、阈值、衰减速度、0–100 关系分数及每日上限全部是可调的产品/角色模拟系数，不是心理量表结果，也没有声称测量真实人的感情。affinity、trust、respect 是独立的游戏状态；不能将它们等同于一条科学验证的关系量表。关于信任应区分多个因素和具体语境的研究可参考 [Mayer、Davis 与 Schoorman 的信任模型](https://journals.aom.org/doi/10.5465/amr.1995.9508080335)。本项目没有照搬其组织情境中的测量或因果结论。

## 来源和主体归因

`support`、`respect`、`boundary_violation`、`hostility`、`shared_success`、`repair`、`disappointment` 必须有真实消息来源及逐字引用。只有归因 `user` 的实际用户互动可以改变用户关系；`self`、`task` 和 `other` 只影响伙伴情绪。

普通任务、礼貌请求和消息数量不自动增加好感。用户指出真实失败、要求履行承诺或正常修改需求不当作敌意。任务失败不能扣用户信任。其他人的话、小说、引用和假设不能变成用户真实关系事件。来源校验只能证明原文存在，语义判断还需针对这些场景评测。

宿主对来源身份、评价类型和归因执行幂等约束，相同消息的同类评价不能重复生效。低于 0.65 的判断信心不产生情绪或关系变化。这个阈值是保守的产品选择，不是概率准确率证明。

## 增量、恢复与限速

`state-store.ts` 的当前起始值为 PAD `(0, 0, 0)`、精力 `100`、关系 `(affinity=50, trust=50, respect=50)`，表达 `gentle`，互动阶段 `new`。这些是角色系统的中性起始设定，不是对现实用户作出的感情判断。

每项评价提供强度 `i ∈ [0,1]` 和判断信心 `c ∈ [0,1]`。令 `τ` 为来源距提交的毫秒数，小于零按零处理；`c < 0.65` 时不更新。其余评价的情绪权重和关系权重分别为：

```text
wA = i × c × 2^(-τ / 7,200,000)
wR = i × c × 2^(-τ / 604,800,000)
```

对每个 PAD 分量 `x ∈ [-1,1]`，取下表中的相应情绪系数 `a`，令 `d = a × wA`：

```text
Δx = d × ((1 - x) / 2)    当 d ≥ 0
Δx = d × ((1 + x) / 2)    当 d < 0
x' = clamp(x + Δx, -1, 1)
```

仅 `target=user` 且实际用户来源校验通过的评价更新关系。对关系分量 `r ∈ [0,100]` 与表中系数 `b`：

```text
Δr = b × wR × (100 - r) / 100    当 b ≥ 0
Δr = b × wR × r / 100            当 b < 0
S  = Σ max(Δr, 0)
B  = clamp(当天剩余正向预算, 0, 6)
k  = min(1, B / S)               当 S > 0；否则 k = 1
r' = clamp(r + (Δr ≥ 0 ? k × Δr : Δr), 0, 100)
实际预算消耗 = Σ max(r' - r, 0)
```

当前事件矩阵如下。全部系数都是项目调优参数，表中的正负方向不保证模型的事件分类正确；来源和语义评价必须另行验证。

| 事件 | P | A | D | affinity | trust | respect |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| support | 0.30 | -0.08 | 0.12 | 2.4 | 1.2 | 0.5 |
| respect | 0.12 | -0.03 | 0.20 | 0.6 | 1.0 | 2.5 |
| boundary_violation | -0.35 | 0.30 | -0.30 | -1.0 | -1.5 | -3.0 |
| hostility | -0.50 | 0.45 | -0.25 | -2.5 | -2.0 | -2.0 |
| shared_success | 0.40 | 0.25 | 0.30 | 1.4 | 1.8 | 0.8 |
| repair | 0.15 | -0.12 | 0.14 | 0.9 | 2.4 | 1.4 |
| disappointment | -0.25 | 0.06 | -0.18 | -1.2 | -1.8 | -0.3 |

PAD 范围为 [-1, 1]。事件添加按边界饱和的冲量，不会用一个标签覆盖整个当前状态。迟到事件的情绪作用以两小时半衰期减弱，关系作用以七天半衰期减弱；迟到的历史提取不应抹掉更新的关注。

当没有新事件时，pleasure、arousal、dominance 分别按两小时、半小时和四小时半衰期向中性恢复。关系不会仅因一段时间没有聊天而被忘记。

其恢复公式为 `x(t + Δt) = x(t) × 2^(-Δt / H)`，其中三个分量的 `H` 分别为 `7,200,000`、`1,800,000`、`14,400,000` 毫秒。这个恢复只作用于已有短期情绪；迟到来源只衰减该事件的冲量，不用来源年龄重置更新的整体状态。

每个关系分量范围为 [0, 100]。正向变化随接近上限逐渐减弱，负向变化随接近下限减弱。宿主按来源日期记录正向预算，每天三项关系增加的总量最多 6 点；预算耗尽仍允许真实事件产生短期情绪，不再增加关系。负向事件不能借由抵消正向预算来获得新的加分额度。

精力和真实互动阶段由宿主根据实际互动、工作与时间恢复更新。mood 从 PAD、精力和当前工作状态派生，模型不能任意指定 mood。

当前精力已经统一使用作息分段积分：每分钟清醒 `-0.08`、睡眠 `+0.30`、用餐 `+0.50`、休息 `+0.15`、运动 `-0.12`、学习 `-0.06`、休闲 `+0.04`、其他习惯 `-0.04`；每段都截断在 `[0,100]`，真实回复/任务事件另行扣除。初始生活计划按稳定伙伴 ID 由作者编写，自定义伙伴使用通用午休；计数从创建的零值开始，不由人格关键词推断，不声称已有虚拟经历。养成强度为 `100 × (1-exp(-completedCount/14))`，streak 为最近一次未完整履行后连续完成次数，真实工作和紧急打断会排除相交活动；进程崩溃只记录最后观察到的工作时刻，离线期间恢复正常作息推进。完整时间、范围与公式见 [作息算法](./companion-routine-algorithm.md)。

当前 mood 的有序映射为：精力不超过 `25` 为 `tired`；否则 `P < -0.18` 且 `D < 0.1` 为 `low`；否则正在工作，或 `A > 0.18`、`D > 0.18` 且 `P ≥ -0.05` 为 `focused`；否则 `P > 0.18` 为 `bright`；其余为 `calm`。这些标签用于呈现和表达选择，连续 PAD 才是情绪状态本体。

## 对行为的影响

疲劳或低落时减少无关话题和主动扩展，保持回答所需内容。较低 pleasure 或较高 arousal 时冷静、清楚地表达；affinity 影响熟悉程度与主动性，较低 trust/respect 影响平和说明边界的方式。所有映射都受稳定人格和用户当前要求约束，不能据此拒绝正常请求、增加日常审批或扩大权限。

当前主脑行为映射：精力 `≤25` 或 mood 为 `tired/low` 时采用简短回复并减少扩展；`A > 0.35` 且 `P < 0` 时冷静清楚表达；`P < -0.18` 时偏安静。非疲劳时 `affinity ≥65` 且 `trust ≥55` 可以采用更熟悉的主动性，否则克制主动扩展。`trust <35` 或 `respect <35` 时平和明确边界，正常请求仍可执行。focus 只在真实 `focused` 状态且当前范围可见时进入主题指引。

主动联系另有宿主门控：精力 `<25`、trust `<30`、respect `<30`，或 `P <-0.45` 且 `A >0.35` 时跳过这次自主联系。affinity `<50` 时每天最多一次、间隔至少八小时；否则每天最多两次、间隔至少四小时。这些规则只约束未经用户当前发起的主动联系，不能拦截正常回复或固定日程。次数上限和阈值也属于项目参数。

固定日程按用户承诺执行。只有用户允许 `flexible=true` 的弹性工作可以因实际精力延后。群聊只看到可公开状态；私人原因、关注实体和来源不得通过状态注入泄露。

纯计算位于 `src/shared/companion-affect.ts`，数据库来源、幂等与日期预算由单独的存储 owner 处理。测试分别验证中性互动、实际正负事件、错误归因、低信心、每日限速、饱和、迟到衰减与行为映射，不能仅以聊天次数增长证明关系准确。
