# 伙伴虚拟世界

## 运行与休眠

SQLite 与现有 UtilityProcess 是世界状态的权威。`Companion.active` 默认仅 `deepseek-flash` 为 true；其余内置联系人及自定义联系人为 false。首次升级只为缺少字段的记录写入默认值，此后保留用户选择。

`companion.set-active` 带资料修订号，休眠先提交状态、取消工作领取，再停止并排空模型、持续行动、日程和 DSH 进程。各数据库领取和提交入口再次检查 active。聊天、收信和观察窗口不授予激活权。

热世界 JSON 只保存激活伙伴的 actor。暂停身体保存在 `companion_world_suspended` 的 SQLite 行，休眠时不反序列化；场景构造只为热 actor 创建小屋。感知、认知与精力推进均跳过休眠伙伴。观察休眠伙伴时不创建 WebGL；已打开的画布会 dispose 人物、纹理、几何及 renderer。缩略头像仍用于联系人列表。

## 独立场景与入口

场景类型为 `home` 和 `park`。小屋各自使用局部20×16空间，公共花园是独立56×36场景。没有街区、房屋外壳地图、全局住宅位置或跨场景 A*。

每个场景声明 `portals`，包含稳定入口标识、`entry/exit/both` 方向与本地坐标。同一入口可同时用作出口。场景内的家具实体占地、相邻交互锚点、渲染与四向 A* 使用同一份几何资料。

`move` 仅在当前场景中使用家具 `destinationId` 或本地探索 `position`，两者互斥。`travel` 接受 `targetSceneId/entryId`。宿主只在 actor.route 中保留当前场景到出口的局部路径，将目标标识与抵达后的局部目标保存在 journey；到出口后重新核验目标存在、激活、忙闲与邀请，然后从目的入口继续局部寻路。跨场景 waypoint 被拒绝，不能通过坐标越界切换场景。

`visit` 提出邀请申请，`respond allow` 给出 `destination:{sceneId,entryId}`；不会移动客人。只有随后 travel 才开始通行。对方休眠、睡眠、用餐或工作会阻止入口通行；邀请到期、撤回和重置同样被核验。`leave` 从本场景出口返回自己的小屋。

现行物理存档版本为 `sceneVersion:2`。旧街区的身体、路线、占用和邀请被重建，不翻译旧坐标；聊天和来源记忆仍保留。当前代码不维护旧 navigate/enter、街区地图或地址学习表。

## 联络、时间与观察

联系与自己的必要问候、邀约是基础能力，自然语言委托可进入 `activity.start`，无需玩家提供“发送xx”口令。宿主保留原始来源、收件范围、轮次、配额和冷却检查，私人玩家资料不能顺带转发。

原生聊天或持续行动第一次联系伙伴时，授权判定同时区分原请求的 `visit/message` 目标。要求本人拜访时，`activity.visit.ensure` 在事务中保留原用户来源与对象，必要的第一条手机留言和任务一起提交，防止只发了问候就结束。重复调用与另一个 `activity.start` 复用同一任务；普通问候不能扩大为出行，休眠对象也不会因此加载。`visitTargetId` 标记到场要求，`visitArrivedAt` 只在真实身体已结束移动并抵达对方场景时记录；未到达的 complete 会退回继续规划。邀请、路径与忙闲仍由原子世界能力验证，宿主不按固定拜访剧本替伙伴作决定。

`world.status` 返回轻量模拟时钟、联络状态和真实交互，不加载另一份完整世界。接收者状态包括 available、dormant、sleeping、eating、working、busy。睡眠、工作、用餐时保留待处理通信；休眠不会自动唤醒或加载小屋。

聊天标题栏的虚拟时钟按照 `virtualNow/speed` 插值，接续存档时停止外推。时钟作为姓名下方的轻量信息，交流入口收在右上角工具区；有交互时显示简短对象和状态，详细原因放在悬停提示中，不在消息区占用一整行。全景玩家观察和伙伴主观感知使用不同的投影，不能把玩家观察结果直接给模型。

`world.status.environment` 与世界窗口按同一模拟游标计算，标题栏并列显示虚拟时间、日期、天气和室外温度；窄窗口收起次要文字，保留时钟和天气。天气中文名称与图标使用共享定义，不再无论天气都显示太阳。模型环境只使用自己的实际感知，明确 `weatherStatus:current/remembered/unknown`；旧天气放在 `lastWeatherObservation`，不会进入当前 weather 字段。社交回报同时接收有限感知、时区和对应持续任务的实际进度，不能自行补造天气、风或已经开始的移动。

社交后续回报按同一委托合并最多16个已等待事件，一次领取共同租约；输入包含原玩家会话中委托之后最多50条可见正式消息，优先保留该委托已发回报，再填入最近对话，涵盖普通回复与行动结果。模型仅回报新信息，允许 `text:null` 消费无需再说的事件。提交事务重新核验全部事件、来源和对话快照；推理期间对话变化则重新排队，不能插入孤立的旧回报。重试、重启和空回报均保留幂等消费状态，玩家私聊不进入 peer 模型。

主动联系使用实际获得手机后最近对话的游标，记忆回查和上下文过滤沿用该游标；显式用户请求仍冻结在自己的消息游标。主动机会没有新的玩家授权，待处理对话存在时不创建新机会。主动循环通过 `proactiveWorkId` 独立保存，不能覆盖原问题的恢复记录或重新完成旧请求。

## 知识与记忆边界

所有外部世界资料通过 `memory.world_query`（或 world.query）查询：contacts、scenes、social、observations。social 限本人参与的会话，observations 限本人真实感知。当前感知只自动投影本次可见的物件与人物，不自动注入历史家具、完整联系人目录或他人私屋。

查询生成本人隐藏世界会话中的带校验和观察凭证，标记 `internalized:false`，不会进入自动提炼队列。引用到的原始社交消息保留依赖，修改或遗忘原始来源后，凭证与所学记忆均不可继续使用。长期内化必须另行调用 memory.record/revise；整理调用 memory.organize。入口分享只生成凭证，不自动教会接收者；scene_entry 记忆必须匹配房主真实分享的原始入口。

每位伙伴在原生聊天与持续行动中都可以自主回忆、记录、修订和整理。空闲世界决策可以创建自己的记忆目标，由持续行动执行；睡眠整理沿用有来源的记忆链。任何路径都不能借整理产生未见知识、读取别人的记忆或扩大现实操作权限。

## 验证

Worker 用例覆盖激活默认值、休眠零身体和零小屋、进程领取门禁、入口邀请、局部路径、通行前忙闲复核、查询与内化分离、私聊隔离和自主整理。UI 用例覆盖激活操作、模拟时钟与交互入口、休眠渲染器释放。

`tests/e2e/companion-independent-scenes.test.ts` 使用隔离用户目录与真实 Electron/IPC/SQLite/WebGL，检查默认激活、画布创建和释放、压缩虚拟时间、休眠收件人提示与交流记录。该用例不调用付费模型；自然语言决策使用独立服务测试检查，不能把界面验收当作真实模型语义准确率评测。


## 实时社交图谱与紧急打扰

观察入口默认以当前聊天伙伴为中心。`social.graph` 读取该主体的真实玩家私聊、伙伴会话、有效拜访记录及少量当前通信状态；不构建场景、调用模型或写入记忆。玩家私聊仅在玩家自己的观察界面出现，绝不回流到 peer 模型。网络连线显示真实通信租约、待送达消息、待回复、待许可和实际同场状态；同场不等于当面交流，后者必须有核验通过的 `face_to_face` 正式消息。

`social.graph` 使用索引支持完整自我关系网的统计、状态分组、姓名/ID搜索和ID游标分页；默认仅返回40位伙伴及玩家节点，返回包与画布节点数不随关系总量增长。聚合数量来自完整的有效会话成员和拜访记录，去重后计数，不以当前批次冒充总数。全局事件查询按中心的全部有效会话读取，独立于当前节点页；事件携带权威姓名，画布外的人发来消息也能辨认。观察时钟只投影共享时钟锚点，不为读取图谱触发同步模拟；已提交的物理事实仍由宿主唯一产生。

界面合并变更通知并限制读取频率（图谱最短750ms、普通快照500ms），并在可见时每2秒校准，返回可见窗口立即重读；切换主体和关闭时取消旧请求结果与订阅。暂停按钮只暂停观察，不控制伙伴。事件只采用正式消息和允许列表中的宿主事实，世界原始事件文本、私人任务目标、内心评价均不进入事件投影。`social.flow` 按世界日期、时间与ID游标分页。图谱仅显示当前主体实际参与的事件，不把同群其他人的私人往来冒充为她的认知。

普通休息/轻松习惯可以受理拜访决策；睡眠、吃饭、集中工作仍会暂缓。手动行动在软作息期间保留移动窗口，避免 travel 或场景内 move 被休息计划立即覆盖。拜访任务绑定实际请求ID；完成前必须既有真实到场记录，也有到场后双方正式当面发言。任务领取/提交避开正在输入的手机回复和社交回报，避免同一主体并发叙述与行动冲突。

玩家通过消息菜单「紧急打扰并发送」明确标记当前消息，无需发特定口令，也无需模型猜测是否紧急；自然语言紧迫性分类仍保留。对应队列项优先领取，作息中断只属于该真实来源，旧待处理消息不会一起放行。伙伴可用 `world.message urgent=true` 发起真实紧急联系，宿主在实际来信验证后有限时暂缓接收者当前活动、保留路径并在结束后恢复；每位发起者两分钟内只接受一次紧急联系，普通消息维持原等待规则。休眠伙伴不自动激活、不加载场景。

`companion_focus_interruptions` 在同一 SQLite 事务中保存被临时暂停的工作单及暂停后的版本；主进程停止并等待关联执行，再处理优先消息。结束或重启恢复时，仅恢复仍是该版本的暂停工作，玩家之后的暂停、修改、取消优先。紧急标记不会给伙伴新增现实文件/DSH权限。社交模型只获知本次实际 urgent 标记与自己的有限感知，不获知他人的私人任务内容。


### 长期事件流的资源边界

- 实时窗口固定最多60条事件；文字只投影600字预览，完整来源保存在SQLite，往来记录另行分页。界面替换快照，不无限追加DOM、消息正文或已见ID集合；中心导航、翻页回退栈也有上限。
- `companion_social_audience` 将真实作者和实际收件人规范化为可重建的磁盘索引，由正式来源插入/变更/删除触发器维护。实时查询按主体、虚拟时间和ID读取索引尾部，不遍历整段消息历史。群成员不自动成为每条消息的收件人。
- 物理事件分别通过发起者、接收者的部分索引取最新候选后合并；各分支先限量，最终合并集有固定上限。拜访记录按访客/房主时间索引取尾部，独立的去重接触投影防止重复拜访放大关系统计开销。过往审计仍留在磁盘，不塞进热世界JSON。
- 刷新只持有一个在途读取与一个待更新标记；持续通知也有最短间隔，卸载时清理计时器/订阅，隐藏图谱不发送查询。普通聊天快照和行动面板也限流，实际流式回复保留独立增量通道。
- 后台世界任务按所需会话读取上下文；记忆工作先只读取激活主体，领取任务后再读取对应来源会话，避免每次工作都展开数万个隐藏会话。
- 验证包含2万条实际关系、20万条归档事件、10万条拜访记录，以及4万次连续通知；它们是隔离的合成压力夹具，不表示NPC真实执行过这些往来。

### 持续行动的等待与恢复

规划资源按实际领取租约后的耗时计费（单次最多120秒，总计最多一小时），并保留32步与连续失败三次的限制；不再把创建时间到现在的墙钟差当作执行耗时。`deadline` 是领取时按剩余规划预算投影的诊断时间，不是包含离线与等待的任务失效时刻。等待谓词先核对真实结果，待房主许可和忙碌/休眠回信不通过模型轮询；正式许可也能唤醒该拜访的手机回信等待。暂停的虚拟时钟不会误结束delay。

`activity.recover` 仅修复24小时内、原始来源仍有效、尚未被更新拜访替代且不足32步的旧墙钟误判或后续寒暄重复分类误判的失败拜访，保留原任务ID、历史、邀请和已发生行为；真实失败、取消、完成或来源撤回不会恢复。恢复后的结果使用独立幂等标识，保留旧回报同时允许发送实际最终结果。此修复不直接编辑用户数据库，仍由正常宿主恢复流程执行。

已绑定`visitTargetId`的玩家拜访不再逐句把原始短指令重新分类为联系授权。收件人必须仍是原对象；后续发言由独立`visit_peer_speech`生成，仅有该双方实际会话、公开设定和本人有限感知，既不带原委托/私人规划草稿，也不沿用拟发文字。初次跨对象分享仍复核当前来源；不合适的单步通过`activity.reject`保存失败回执并重新规划，连续三次相同拒绝才结束，避免一次分类误差直接扼杀整项行动。拜访完成自动回报只描述实际到场、双方当面发言及当前位置，不把模型添加的泡茶做饭等叙述写成既成事实。
