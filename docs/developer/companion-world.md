# 伙伴世界：运行、感知与行为契约

实现所有者：`src/companions/world-store.ts`、`src/shared/companion-world-engine.ts`、`src/main/companions/world-service.ts` 与 `src/renderer/companions/world/`。

## 一套实际状态

世界与聊天共用现有伙伴身份和 SQLite UtilityProcess。位置、路径、家具、电脑使用权、拜访许可、实际活动、世界事件及后台认知任务均由存储宿主管理。Three.js 只显示这些事实，在已收到的路径上插值，不能自己决定人物去向、让未完成的任务显示成功，或在未获准时把人物画进别人的家。

主脑通过原生 `world` 工具观察并行动。交互结果继续进入当前 agent loop；持续生活由独立的世界认知任务处理。状态转移遵循“观察 → 语义决定 → 宿主验证并执行 → 真实结果”，自主决策没有玩家的外部文件或执行器权限。

参考了 [Cortico 的事件环境接口与 Persona 分层](https://github.com/Pal-AI-Lab/Cortico) 和 [Coopanion 的表现层与环境接口分离](https://github.com/Pal-AI-Lab/Coopanion/blob/main/README_zh.md)。项目自身保留原有主脑、能力、记忆和存储实现，没有引入另一套 Agent 框架。角色美术来自用户指定的废弃项目选材与本次独立图片制作，未使用 Coopanion 的大肥鱼分件贴图。

## 世界时间与现实承诺

默认 `compressed`：现实 20 分钟对应虚拟 24 小时，时间倍率为 `1440 / dayDurationMinutes = 72`。`realtime` 的倍率为 1。时间以持久化锚点计算：

`virtualNow = virtualAnchor + (realNow - realAnchor) × speed`

改变模式以切换瞬间重新建立锚点，世界时间保持连续。世界日期、日照、天气、气温、睡眠、用餐和兴趣活动使用世界时钟。用户说“明天下午三点”“每天早上八点”的提醒或现实任务继续使用现有日历的现实日期与 IANA 时区，不能因为加速世界而每 20 分钟执行一次现实日程。

人物行走、跑步、坐稳和动画按现实秒推进，保证过程可观察。一天加速并不把一个房间内的行走也加速 72 倍。日程开始代表准备参与；只有实际到达相应家具后才进入睡眠、用餐或练习。精力恢复与习惯参与基于实际活动窗口。

进程关闭时不能发起模型调用、执行现实任务或发送消息。重新启动按保存的时钟与路径补算可确定的世界活动，保留未补齐游标，分批追平；不会伪造离线期间已经完成的外部工作或模型对白。中断的外部工作仍按原任务恢复规则处理。

## 持续存档

世界没有临时演示状态或每次启动重建的随机住户。现有 `companions/messages.sqlite` 是唯一权威存档，物理推进与命令在同一 UtilityProcess 中按事务保存。进程恢复保留人物、稳定房屋地址、坐标、路径、目的地、时钟、作息、拜访许可、关系与事件；只结束属于已经退出进程的外部工作占用，不把离线时间当作任务执行证据。时钟游标落后时分批补算，后台认知等待追平后领取任务。

长时间离线的追赶受每次推进预算限制。追赶期间，显示的世界时间、天气、动作帧、短表情、实际作息与精力都对应同一个已推进时刻；现实 `realNow` 另行保留。界面显示正在接续离线生活，不能一边显示未来的天气，一边把尚未补算的人物画在旧状态。一次作息/状态读取也钉在同一观察时刻，避免嵌套读取再次推进导致能量、计划与实际活动错位。

热状态只保留当前工作、有效拜访和最近 100 次结束拜访、最新时间锚点。全部工作与拜访审计、历史时间段、情绪来源和梦的处理水位保留 SQLite 索引记录。历史时间段通过索引完成现实与虚拟时间的双向换算，不能因切换时间模式而破坏过去的习惯、精力或证据核算。归档和热态替换同事务提交，失败一起回滚；不会靠删除历史避免长时间游玩的增长问题。

观察地点、跟随对象及逐场景镜头是独立的本地显示偏好。原生观察窗口按最小空闲槽位使用 `companion-world-observer`、`companion-world-observer-1` 等键；同时观察的窗口不互相覆盖镜头，关闭后重开的槽位可恢复自己的偏好。只在偏好变化时写入。它们不能覆盖数据库的人物状态；联系人入口明确选择对应小屋，全局世界入口恢复对应窗口上次观察。镜头数据做有限坐标、距离、缩放及数量校验，损坏或存储不可用时恢复正常默认视角。

## 场景、坐标与使用条件

每位伙伴有独立小屋；小屋包含电脑、书桌、电脑椅、床、厨房、餐桌、沙发与活动区。公共街区连接各房门。场景使用统一 tile 坐标；真实物件占地与家具交互锚点同时供寻路和美术使用。房屋在街区中的实体占地阻挡寻路；室内外只能通过房门连接。

路径由确定性 A* 产生，沿四向路段推进，不穿家具、不沿两次快照之间的直线抄过墙角。场景扩展须同时声明边界、物件占地、可用交互、门或连接点，不能只添加一张背景图。装饰放在既有家具上或不阻挡的边缘；新增实体障碍必须进入权威地图。

交互校验身份、当前场景、可达性、距离、家具类别和占用。`move` 表示开始移动，返回的路径不是“已经抵达”；`interact` 的完成以宿主实际状态为准。不同伙伴不能因知道一个物件 ID 就使用它。

## 电脑与实际工作

聊天回复和现实能力执行共享电脑准入。普通消息遇到睡眠、用餐或休息时等待；明确的紧急当前消息和已授权固定承诺可以唤醒。通知的紧迫性属于独立的有限语义判断，不能由一个关键词把引述、假设或否定变成紧急授权，也不会在通知阶段执行任务。

工作进入 `waiting → moving → seating → ready → ended`。只有找到有使用权的空电脑、实际走到座位并坐稳后，才开始任务主循环或执行器。等待、移动、取消和关闭不能落出一个仍在后台执行的幽灵任务。

做客时，获准进入且对方电脑空闲，可以使用该电脑。电脑被占用时选择自己的电脑并实际回家；自己的电脑也被占用时等待。占用/预约按工作身份保存，多项同伴工作不能互相错误释放；最终结束或取消释放最后的使用权，再恢复生活行为。世界里的“使用电脑”并不独立授予现实文件访问权限。

## 拜访、社交与关系

拜访是持久化请求，包含客人、房主、原因、创建与过期时间，以及允许/拒绝结果。房主本人结合自己的状态决定，玩家观察面板不能冒充房主替其同意。请求、允许、抵达、离开是不同事实；在路上许可过期也不能继续越过房门。

住所目录只公开伙伴身份和地址，不能把全景观察者可见的私屋坐标、私人原因、记忆或聊天交给另一个伙伴。现场交流要求双方在可交流范围，发言只代表发言者，不能替对方、玩家或第三方承诺。伙伴原话有独立来源，不能成为玩家命令。

伙伴对伙伴的关系独立于伙伴对玩家的 affinity/trust/respect。互动数量本身不会增加好感。关系评价需引用可见的真实事件、发言者和原话，并达到判断信心阈值；正向日额度、饱和、衰减及来源撤回遵守现有情绪算法的原则。对失败的正常批评不自动算敌意，引用中的攻击不自动归因当前发言者。

## 环境、情绪与身体状态

世界环境按虚拟日期和时区推导昼夜、日光强度、季节性气温及可重复的虚拟天气。天气是本项目的虚拟气候，不表示现实所在地的天气预报。晴、多云、雨、雪具有相应光照与降水表现；室内照明来自实际灯具，室内外温度分开提供。

温度舒适度和实际活动通过宿主事件作用于 PAD/精力；不能每个显示帧重新加减，也不能把不适扣成玩家的信任变化。世界角色的公开状态取自同一份运行状态，主脑读取相同事实。作息计划、正在前往家具、实际参与活动和已形成的习惯记录分别表达，不能互相冒充。

情绪表现由实际 PAD、精力、事件和活动推导。身体动作优先保持真实姿态：电脑前的工作、床上的睡眠、桌边的用餐不能为了一个表情而突然换成站立姿势。关系和心情参与语气、社交选择与休息决策，不改变来源验证、任务权限和固定承诺。

## 睡眠整理与学习

睡眠回顾是有真实来源的后台认知任务。只有已经到床睡着、没有正在进行的工作时才能进行，醒来或证据失效会阻止提交。整理读取伙伴自己的有效记忆和可见原话；允许形成标明性质的认识、概览、反思与假设，保留依赖的原子记忆、版本、逐字证据和不确定性。

梦的描述、整理记忆与任务完成同事务提交。缺来源或半途中断不能留下“我已经学会”的伪成果。撤回/纠正来源后，派生内容与相关回顾也必须失效。模型没有读取过的外部资料不会因为一次睡眠变成其已知知识；真正阅读现实资料仍需要经授权的实际能力结果。继续使用当前自动召回系统，不引入 embedding 模型。

## 表现与性能

世界通过 `CompanionWorldWindowManager` 打开独立的 Electron `BrowserWindow`，每次打开可以新增窗口。原生窗口自带最小化、最大化和关闭；聊天主窗口不再被世界模态层覆盖。世界里的加号可另开当前场景，再独立选择其他小屋，生活侧栏可折叠。关闭一个观察窗口只释放它的 renderer、WebGL 资源和监听，不关闭主窗口或其他观察窗口，也不停止世界。

观察窗口只暴露专用 preload：读取安全联系人投影、世界快照、修改世界设置及自身窗口控制。没有主聊天发送、DSH、模型密钥、资产管理或任意 shell 接口；IPC 按已注册窗口和其 main frame 验证。所有观察窗口共享原有服务与唯一 SQLite UtilityProcess，不新增模拟 timer。并发快照由主进程短时合并，设置与状态变更使缓存失效；可见窗口数量由原生生命周期广播，不依据是否获得焦点决定渲染。

角色采用独立动作文件，每张只含同一角色、同一动作的三个有序帧；坐下、起身、躺下和醒来分别制作，不能倒放一个文件代替另一个动作。图片为真实 alpha；动作以固定画布、比例和姿态接触点对齐，不能拿透明图的最低像素当作座位或床面。详见 [动作素材契约](companion-world-art.md)。

世界窗口按可见场景建立模型并释放旧资源。命令式 renderer 按实际画面变化绘制：移动、镜头和降水连续更新，静止人物在三帧动作切换时唤醒，灯光或快照没有改变画面时不重复提交。1–3 个可见观察窗口以 30 fps 为动态上限，4–6 个为 24 fps，更多为 20 fps；DPR 上限 1.5。静止画面低 FPS 是按需绘制，不能当作移动吞吐。最小化或隐藏取消 rAF/等待任务并停止轮询；失去焦点但仍可见的窗口继续观察。

镜头和角色帧更新不驱动整页 React 渲染；标签 DOM 只在文字或屏幕像素位置变化时更新。移动按真实快照间隔沿已经收到的折线路径插值，抵达和停止以宿主事实为准，不固定走 750 ms 后再等 250 ms。静态阴影和家具矩阵不逐帧重建，场景先编译 shader。纹理只为当前场景和实际动作加载，旧动作与退出场景的资源及时释放。

头顶标签使用与侧栏共用的 `worldActorStatus`：实际身体活动优先于待办承诺。睡觉、吃饭、起身、坐稳、走向目标、赶回家里电脑、读书、做饭与真实处理工作分别显示；多个已准入工作显示实际数量，不能把排队任务画成正在执行。性能验收同时覆盖多窗口行走、镜头、主窗口聊天、静止和最小化，不以单帧截图或 CPU 提交耗时代表完整呈现流畅度。

## 行为验收

必须验证以下因果链，并同时检查模型输入、宿主状态、持久数据和可见画面：

- 普通消息遇到睡眠会等待；否定、引用与虚构紧急不唤醒；真实期限/紧急需要能通过语义理解触发响应。
- 从床或街区接到紧急请求，先起身/移动/抵达/坐稳，再出现任务推理和真实能力执行；取消立即停止准入并释放预约。
- 经允许后沿门和街道拜访；拒绝、过期或撤回不能入屋；做客电脑占用时真实跑回家。
- 现实日程不随加速世界重复；切换模式、关闭和重启保持时间和行为连续，离线不会生成假的外部成功。
- 行走不计作睡眠恢复或兴趣练习；真实中断和任务窗口扣除，习惯状态只能由足量实际参与形成。
- 伙伴交流有自己的发言与关系来源；正常招呼不刷好感，天气不扣玩家信任，忘记来源后不重现派生知识。
- 世界与聊天的情绪、精力、位置和实际活动一致；缺模型配置时只能展示可确定生活，不能生成预制假对白冒充模型决策。

测试结果、实际模型语义样例、实机截图与性能记录随实现更新。通过结构校验或模型正常返回不等于行为成立；模型仍可能误解含义，验收需保留失败和不确定结果。
