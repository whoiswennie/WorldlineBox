# 伙伴统一记忆生命周期架构方案

设计日期：2026-10-26。状态：实施中，进展与真实结果见 [实施台账](companion-memory-lifecycle-implementation.md)。源码调研与差异证据见 [VCP 记忆对照调研](companion-memory-upstream-research-2026-10-26.md)。旧设计、历史验收记录保留历史含义，不能代替本文的实施验收。

日常触发、各伙伴文件位置及软件编辑方式见[运行指南](companion-memory-user-guide.md)。
本次代码交付及未完成的验收、清理范围见[交付报告](companion-memory-lifecycle-delivery.md)；完整两小时测试按用户于2026-10-27的要求取消。

伙伴的记忆应随真实经历逐步形成，在交流、学习和执行任务期间持续维护。深度整理不以真实夜间开机为前提；任务可以使用开始时的记忆快照，后台同时更新下一次可用的记忆。来源撤回、明确遗忘和权限收回始终立即约束后续使用。

核心决策是保留原版 VCP 的检索、语义图和 DreamWave 能力，重构宿主的事件组织、维护调度、版本语义、发布协议和上下文读取接口。每个伙伴拥有独立的记忆状态与维护节律，计算资源由宿主统一调度，不为每个伙伴常驻一组模型和原生进程。

## 目标与约束

本方案中的拟真指可观察的连续性：知道什么值得记住，能延续一件事，适度概括并保留关键细节，承认不确定和记错，经历足够变化后才反思，学到的方法能在后续行为中接受检验。它不要求模拟生物大脑，也不通过编造离线经历、反复写感想或频繁改人格制造成长感。

必须满足的约束：

1. 一套权威记忆账本、一套提交协议和一套检索语义。聊天、伙伴通信、世界行动、学习、手工资料均接入同一生命周期。
2. 原始来源与作者身份独立保存。派生文字不能获得新的来源权威，也不能扩大执行权限。
3. 不以用户提醒记住为常规前提；也不为每句消息必然调用一次整理模型。
4. 维护与前台任务可以同时推进；前台优先不等于后台永远等待空闲。
5. 应用关闭期间没有本地认知执行。重新启动恢复真实欠账，不补演每个离线小时或每一晚的梦。
6. 已接收来源和已提交记忆不得因预算不足、崩溃或排队丢失。允许推迟派生产物，并明确索引及整理状态。
7. 普通新增、标签、整理和归档不撤销任务已经合法读到的历史；硬撤销不能被快照绕过。
8. 记忆正文保持自然文本。结构化字段服务于归属、时间、来源、版本和维护，不再引入与 VCP 竞争的第二套事实检索引擎。
9. 缓存与进程同时具有数量和资源预算；不能把进程数上限当作内存上限。
10. 工程正确、模型理解质量、检索质量和拟真体验分别验收。任何单一分数都不能证明整套系统完美。

## 架构与职责

~~~mermaid
flowchart TD
    A[正式消息和真实阅读及执行凭证] --> B[来源日志与事件片段]
    B --> C[按事件聚合的短期证据层]
    C --> D[选择性编码与旧记忆核对]
    D --> E[统一提交与不可变正文修订]
    E --> F[索引投递和检索代次]
    E --> G[文档及时间线投影]
    E --> H[每伙伴维护控制器]
    H --> I[整理 反思 方法学习 联想]
    I --> E
    F --> J[原版 VCP 候选准备]
    C --> J
    J --> K[固定候选的 AIMemo 聚焦]
    K --> L[任务记忆快照]
    L --> M[伙伴主脑及显式回忆]
    R[遗忘 来源撤回 权限变化] --> S[撤销屏障及依赖传播]
    S --> E
    S --> F
    S --> L
~~~

| 模块 | 唯一职责 | 不承担的职责 |
| --- | --- | --- |
| MemorySourceLog | 保存正式来源、作者、事件时间、见证和撤销记录 | 不用模型改写原始证据 |
| MemoryEpisodeBuffer | 把消息和回执聚成仍在发生的一件事，保存处理游标 | 不把每次工具调用当成独立生活经历 |
| MemoryEncoder | 判断 skip、create、append、correct、link、uncertain，并核对旧记忆 | 不直接写文件、删除来源或自行授予权限 |
| MemoryLedger | 不可变修订及来源依赖、操作回执、伙伴正文文件的耐久发布凭证 | 不等待模型和 embedding 才提交事务；不在文件缺失时替模型回退SQL正文 |
| MemoryIndexCoordinator | 增量更新原版 VCP 索引，公布可读代次 | 不把索引重建当作新的个人经历 |
| MemoryRecallService | 原版 VCP 召回、固定候选聚焦、来源凭证和任务快照 | 不因每次工具续接重跑整套被动回忆 |
| MemoryMaintenanceController | 每伙伴欠账、节律、检查点和维护计划 | 不依赖身体 sleeping 或占用现实工作授权 |
| MemoryResourceScheduler | 跨伙伴公平、优先级、模型及 CPU、IO、内存预算 | 不读取无关伙伴的私人正文来判断谁优先 |
| MemoryProjectionService | 日记、资料、自我认识、时间线和人类可读目录 | 不把自动导出又摄取成新来源 |

这些是逻辑边界，不要求全部变成独立进程。模型只接收本次所属伙伴、该作业实际需要且获权的资料；统一调度器只看队列和资源元数据。

## 记忆对象与权威关系

| 对象 | 内容 | 权威关系 |
| --- | --- | --- |
| SourceEvent | 正式消息、真实阅读、工具结果、世界事件凭证 | 证据根；作者、见证、发生时间不可由模型改写 |
| Episode | 一件持续发生的事、参与者、阶段和来源范围 | 组织来源；阶段变动需要真实新凭证 |
| MemoryRevision | 日记、知识、主观认识、方法、假设或梦的自然文本 | 引用来源和已读修订；不可变正文版本 |
| MemoryAnnotation | 标签、标题、目录、别名、展示信息 | 可影响检索；不创造新经历 |
| Derivation | 摘要、整合、反思、时间线、方法的输入闭包 | 必须标明派生关系和输入角色 |
| RecallSnapshot | 任务实际使用的文字、候选和模型输入凭证、读代次 | 历史读取事实；始终受硬撤销约束 |
| MaintenanceJob | 作业类型、输入范围、因果事件、租约、检查点和结果 | 耐久可恢复；不把调用次数当作学习成果 |
| OwnerMemoryState | 各流水线游标、维护欠账、策略和最近成功记录 | 每伙伴独立；空闲时间本身不增长认知内容 |

统一正文类型建议为 episode、knowledge、reflection、procedure、hypothesis、dream。它们共用来源、读写和修订契约；不按文件夹各建一套存储。

日记是对一件真实经历的完整表达，不要求另外再建一份语义相同的原子事实副本。事件尚未结束时可以先有短记忆，后续新进展补入同一逻辑条目或形成明确的后续事件。长篇阶段日记和月度时间线是可重建导航，检索时按来源家族去重，避免原文、摘要、日记和反思把同一事实重复注入四次。

当前自我认识由有效 reflection 及其条件投影，不是第二个人设文件。稳定人格仍由角色配置管理。资料读过、理解过、自测能答、实际成功使用分别记录，不能自动等同于完全认可或掌握。

## 时间与版本

### 时间字段

必须区分以下时间：

- event_time：真实来源发生的世界时刻；世界与现实同步时仍保留时区和原始绝对时刻。
- observed_at：伙伴实际见证或读取来源的时刻。离线期间不存在本地执行时，不虚构观察。
- processed_at：本次实际完成编码、反思或做梦模拟的现实时间。
- due_at：宿主下次可领取维护作业的现实时间。
- coverage：日记或总结覆盖哪些事件时间范围。

日记可以写今天回顾上周的事，但不能把今天处理的上周资料冒充昨夜实际思考。时区变化只改变日历投影，不能改变事件绝对时间。夏令时、系统时钟回退和重启通过绝对时间及本地单调计时组合处理；等待租约不能只依赖可跳变的墙上时钟。

### 版本字段

| 字段 | 变化原因 | 允许产生的影响 |
| --- | --- | --- |
| source_revision 和 source_digest | 原始证据字节或正式状态变化 | 重新核验受影响证据及派生物；撤回立即进入硬撤销路径 |
| content_revision | 正文发生实际变化 | 新检索内容，精确派生物重算；旧任务可保留历史读取 |
| annotation_revision | 标签、标题、目录或检索注释变化 | 更新相关检索资产和展示；不产生新经历或反思欠账 |
| policy_epoch 和 revocation_epoch | 归属、见证、明确遗忘、权限收回 | 优先屏障、缓存失效、后续推理或发布阻断 |
| ledger_sequence | 本伙伴账本任何已提交变更 | 增量订阅与同步游标，不作为所有任务必须最新的条件 |
| index_generation | 一个已核验的检索状态或原生资产版本 | 固定本次候选准备输入；不能自行撤销历史正文 |
| derivation_revision | 某个派生产物的输入或算法变化 | 重算该派生产物，不自动重演来源经历 |

content_revision 也不能单独等于新经验。每次正文改动记录 change_kind、cause_event_id、evidence_delta 和 lineage_root_ids。措辞修整、去重合并、摘要改写属于 representation；真实新增来源、结果、纠正和有据新认识才增长相应语义欠账。模型的 change_kind 只能提出，宿主根据真实新增来源、修订关系和操作类型核验。

“新认识”允许在旧来源上形成，但必须有新的问题、条件、反例或推理贡献，记录具体差异和输入谱系；不能换句话就无限形成反思。相同输入、问题族、方法版本和无变化结论有耐久去重键。

语义新颖度不能由 change_kind 或问题字符串机械证明。首轮增加硬上限：同一原始来源谱系、同一证据增量最多自主生成一层跨事件反思；同一问题族结算后，没有新的外部证据、用户实际新问题、真实实践结果或预先登记的延迟验证原因，不自动重新打开。模型归一化问题族只辅助判断，来源谱系的周期费用上限和递归深度仍独立执行。维护报告、自发复述旧总结、梦叙述和其导出消息携带维护来源标记，不因换到正式消息表就自动成为新经验原因；一次真实的新社交互动可以单独形成有凭证的事件。

## 记录与写日记

### 来源先保存

正式消息与来源观察、待处理意图在同一事务中持久化。此时不等待日记模型和 embedding。来源正文立即可通过获权全文回查，近期未编码片段作为短期证据可参与当前上下文；界面可显示已接收、待整理，不能把后台未完成解释成伙伴从未见过。

短期证据是 prepareRecall 同次捕获的独立 typed 输入 recent_evidence，不冒充已经进入原版图的日记。默认读取当前任务/会话合法近期片段；跨入口只通过本人获权 episode 的目录和显式检索选择，不无界拼接全员近期消息。初始选择窗口为最多 12 条完整正式来源和一个稳定来源游标，超出模型能力时分段并返回未覆盖游标，不能截掉单条尾部后声称完整。按已成功编码的 coverage 去重，保留未收录的新事实；聚焦前后与任务使用时执行同样的撤销检查。它作为清楚标注的未整理证据附加给任务，固定输入对照应把这条宿主扩展和原版已索引管线分别验证。

只有原始消息系统负责其保留和删除政策。本方案不会因为某段被判断为寒暄而删除原始聊天；也不因此把所有原文无条件嵌入热记忆图。

### 以事件为编码单位

片段依据会话、任务、reply anchor、真实参与者及事件连续性聚合。不同来源域不因关键词相似就混成一篇。切换话题、完成任务、明确结果、双方达成约定、用户纠正、离开会话和静默窗口都可以关闭一个编码片段。

建议首轮调度参数如下，均是待测默认值，不是当前实现或质量承诺：

| 触发 | 建议行为 |
| --- | --- |
| 首次身份信息、明确纠正、约定或明确要求记住 | 提高编码优先级，不等静默窗口；若主脑已经成功记录，后台核对并复用 |
| 普通连续交流 | 静默 60 秒后编码一个片段，而非每句生成；60 秒期间不阻止当前回复 |
| 持续不停的交流 | 片段累计 12 条正式消息或首条未处理已等 5 分钟时，提交截至稳定边界的前缀；后续形成尾段 |
| 工具和长任务 | 依据里程碑、实际结果和失败原因编码；进度心跳与重复查询不独立写日记 |
| 一次资料阅读 | 按真实文档版本和读取片段组批；相同版本重复阅读复用凭证，不假造新知识 |
| 应用关闭或休眠 | 先持久化片段和游标；来不及调用模型则下次继续，不为完成日记延迟退出 |

宿主廉价过滤只处理可以确定的重复传输、相同来源版本、系统心跳和已完成回执。语义上是否重要采用 skip、uncertain、candidate 三态，不能用关键词规则把“你好，我叫……”当普通问候丢掉。模糊片段进入合批判断，宁可回查原始证据，也不让低成本过滤器擅自决定人物和事实。

### 编码契约

编码模型先查与事件相关的本人旧记忆，再提出：

- skip：没有持久价值，记录原因及处理水位。
- create：新的、可独立理解的经历或知识。
- append：同一件事的新增阶段，保留先前仍有效的条件。
- correct：新证据纠正旧说法，保留纠正前后和有效时间。
- link：只建立有来源的事件延续或资料关联。
- uncertain：有潜在意义但不能确认，保存问题和待核查线索。

每项写入需要 source IDs、逐字证据、实际已读旧修订和预期写版本。没有实质新增时复用旧条目并更新处理覆盖，不靠改标签或换措辞再建一篇。

幂等键绑定 owner、来源版本集合、episode、目标操作及契约版本。主动记录和后台编码走同一提交入口，登记同一事件的 coverage；不能只比较整篇文字哈希来防止两条路径重复记忆。语义匹配的候选召回使用 VCP，宿主不伪造相似度或把模型自报分数当真值。

### 细节保护

日记保留谁说了什么、何时发生、计划与完成、否定、更正、数量、限制和未确定部分。文章正文、引用、梦和角色扮演保留材料性质。可核验的数字、姓名和否定由结构及规则核查；是否完整表达含义还要通过内容评测，不能声称逐字证据存在就代表归纳正确。

长输入按模型能力分段、保存覆盖并继续，不静默截掉尾部后宣称完整记住。没有新事实和重要变化时允许不写，系统把它作为成功处理而非失败重试。

## 持续维护与每伙伴节律

### 持久维护状态

每个 owner 独立保存 capture_cursor、indexed_cursor、integration_cursor、reflection_coverage、timeline_dirty_ranges、last_success_by_kind、not_before、retry_state、pending_causes 和 policy。调度器根据已提交变更增量维护这些字段，不在每次 tick 扫描所有伙伴的全文。

维护欠账是需要处理的真实变化，不是离线经过的分钟数。区分：

| 欠账 | 主要来源 | 完成条件 |
| --- | --- | --- |
| 编码欠账 | 正式新片段、未结事件、迟到结果 | 片段得到 skip 或有效写入结算 |
| 收录欠账 | 已提交正文和检索注释差量 | 对应索引回执成功并发布 |
| 整合欠账 | 同事件重复、补充、更正、相互冲突的有效记忆 | merge、revise 或有原因的 defer |
| 反思欠账 | 有意义的新经历、反复出现的问题、真实使用结果和反例 | 一次有输入覆盖的反思或无新增结算 |
| 时间线欠账 | 某个事件或月份的内容输入变化 | 只重建相关导航及摘要 |
| 学习欠账 | 已授权目标、真实未读材料、待验证方法 | 有据阅读、复用或修订、自测/实践结算 |

defer 必须带 reason、重新打开所需的条件和输入指纹。相同输入不因 tick、跨天或“今天还没反思”重新问一次模型。失败与 defer 分开：模型故障不能伪装成“我觉得不用整理”。

### 浅整理与深度整理

浅整理持续运行，主要处理来源、编码、差量索引、去重候选、精确更正和小范围时间线。深度整理处理跨事件反思、方法复盘、长期主题整合与 DreamWave 联想。

建议初始准入：出现一个重要结果、明确冲突或 3 个有意义的新 episode，就可以登记深度欠账；普通情况下距完成上次深度决策至少 6 个现实小时，包括无新增及 defer 的成功结算。失败采用独立退避。明确冲突先走浅层精确纠正，不让每条重要来源都绕过深度预算。最早的有效深度欠账满 24 小时后，即使始终没有夜间在线，也获得下一轮受控后台服务资格。阈值只决定宿主是否值得安排一次决策，实际可返回无新认识。

这些参数不承诺每 24 小时必须成功。应用关闭、模型不可用或资源不足时持久化未完成状态；恢复后给予公平服务并展示原因。没有新的来源、真实问题、有据结果或已登记验证原因时，不因跨天创建新反思欠账；已经存在的未结欠账不会随时间自动消失。

同一伙伴至少区分整理节律、表达风格、知识兴趣和保留偏好。首轮可提供安静型、均衡型、学习型维护参数模板，统一协议不变；保留偏好只影响排序、展示和可逆归档，不能覆盖长期保留、禁记及用户停止要求。模型只能建议受界限约束的频率调整，不能自行关闭证据核验、扩大资料授权或删除用户要求保留的内容。

例：频繁聊天的伙伴更早合并同事件片段；很少被联系的伙伴不因长时间离线积累成千上万空任务；持续学习的伙伴按真实课程进展产生资料笔记和方法验证。三者都使用同一记忆服务。

## 梦境与反思的关系

### 不依赖夜间开机

深度整理有两个入口：真实身体睡眠是自然机会；应用在线的白天、任务等待和资源轮换时，后台同样可以做有据复盘与联想。认知维护不借用身体作息状态，也不因进行中的任务占满工作额度而自动禁止。

重新启动只合并真实欠账。离线一周且存在未整理资料时，安排一个逻辑恢复作业，按有界输入分批并保存检查点，保留未覆盖尾段和最早欠账时间，不能把全部历史塞进一次模型，也不能生成七份“昨夜做过的梦”。没有新材料和旧欠账时只完成廉价状态核对。

梦境体验分两种明确来源：sleep_dream 表示实际睡眠阶段内生成的叙述；rehearsal_dream 表示清醒期间后台进行的梦境模拟或休息联想。记录真实生成区间；睡眠中开始、醒来后完成时标为跨阶段或 rehearsal_dream，不为维持睡眠标签丢弃合法真实维护。两者都使用实际 processed_at，不把白天处理标成昨晚实际发生；维护界面可解释时间，日常聊天不强迫播放系统日志。

### 深度整理会话

一次会话固定输入 read set 和来源策略，分阶段持久化：

1. 检查新颖度和相关主题；不足则无需生成叙述，结算覆盖。
2. 对重复、补充、更正做独立 merge、revise 或 defer 判断。
3. 从真实经历提炼有条件反思或方法候选；没有新增则为空。
4. 需要联想时运行原版 DreamWave，保留近期、中期、远期桶及本人边界。
5. 生成可选梦叙述，始终标记虚构；叙述失败不回滚已经合法完成的真实维护。
6. 对联想得到的问题单独核查，验证通过的内容以真实依据保存，其他保留为 hypothesis。
7. 提交各阶段回执，记录被覆盖的语义变化和后续验证项。

梦不是改写事实的通道。梦可以提出“也许两次失败有共同原因”，不能把共同原因直接升级成事实；应该回查原始记录、寻找反例或安排授权范围内的验证。用户、伙伴和教材的主张不能由梦转成自己确定的信念。

### 机会与冷却

必须将有用维护和可选梦叙述分开。原版 0.6 概率及 8 小时冷却可以作为叙述体验的初始参数，但不再决定是否允许必要维护。

抽签绑定一个有真实输入的深度会话并持久化一次；重复领取不重抽，未中持久化为 skipped。维护在梦抽签失败时仍继续。建议分开 last_attempt_at、last_narrative_success_at、failure_backoff 和 next_eligible_at：同一叙述阶段默认最多 3 次尝试，达到上限终止本阶段，只有明确重试或新的合格会话才可再领取；重试不重跑已完成的真实维护。成功冷却不冒充失败退避。完成一次成功梦叙述后 8 小时内不再自动生成另一份；没有有用输入时不抽签。

梦、自己的旧摘要和没有新语义贡献的反思，不增加新的经历欠账，不作为独立证据提高可信度。只有外部新来源、真实行为结果或有明确新贡献且通过验证的反思，才能重新打开相关问题。

## 自我学习与迭代

学习按“发现缺口—获权阅读—理解—检索验证—实际使用—修订方法”闭环推进。检索失败可以产生待核查问题，不自动创建无限制的公开网络爬取任务。

| 阶段 | 保存的内容 | 不能推导的结论 |
| --- | --- | --- |
| 阅读 | 实际材料、版本、范围和作者观点 | 读过就认可或已实践 |
| 理解 | 有限定的 knowledge，矛盾与未知 | 模型概括即客观真相 |
| 回忆自测 | 不直接看到原答案时的检索和回答 | 一次能答就永久掌握 |
| 方法候选 | 适用条件、步骤、预期、风险、来源和反例 | 自动改系统提示或获得工具权限 |
| 实际使用 | 工具或任务真实回执、成功/失败条件 | 自我评价替代外部结果 |
| 修订 | 保留有效条件、反例和失败教训 | 把自己的旧总结算作新的独立支持 |

procedure 记录至少含适用范围、具体方法、来源、已知反例、验证状态和最近真实结果。后续任务按需召回，允许实践反驳它。当前缺少验证时使用候选方法的语气，不宣传“已学会”。

伙伴可以改变自己的当前认识和行事偏好，但不通过长期记忆自行修改稳定人格、宿主权限、模型路由、来源政策或维护协议。策略学习只能建议有界参数，结构变化由统一标准升级和评测决定。

## 并发读取与任务快照

### 一致性等级

| 读取 | 可见状态 | 对后续普通维护的要求 |
| --- | --- | --- |
| task_snapshot | 新任务准备时固定的获权记忆及短期证据 | 普通追加、整理、合并不重启同任务回忆 |
| latest | 显式查现在、重新核实某事 | 返回请求开始时可用的最新代次，并说明尚未索引的差量 |
| historical | 给定事件时间或正文修订 | 展示当时记忆，不冒充当前事实 |
| write_readset | 记录、纠正、合并的明确输入版本 | 精确 CAS；冲突重读受影响记录，不能盲写 |

当前已经存在的 task_passive_v1 冻结能力是任务快照基础。目标不是要求任务实时追上每条后台修改，而是让准备阶段也有稳定输入，避免整个库持续变化导致三次重跑。

新任务固定 ledger_sequence、policy_epoch 和内容修订集合；准备期间的无关新增进入下一次可读状态。输入仍然合法时，普通账本序号增长不要求重算。对“当前许可、文件是否仍存在、工作是否取消、用户刚作出的纠正”等关键前置条件，任务在实际操作前或明确决策点核验相关最新差量，不无限重放整个任务。

长任务默认保留自身上下文；只有任务需要新事实、明确新阶段或主动调用 memory 时增量读取。新增事实不会无条件改写先前推理和工具历史。用户 steer 的明确纠正立即进入本任务，不能以快照较旧为由忽略。

### 候选准备和聚焦分离

第一阶段保留原生图的真实串行边界，新增以下宿主协议：

~~~typescript
prepareRecall(request): Promise<PreparedRecall>
focusRecall(preparedRecallId, signal): Promise<RecallSnapshot>
validateSnapshot(snapshotId, useKind): Promise<Validation>
readChanges(ownerId, afterSequence, filter): Promise<ChangePage>
~~~

prepareRecall 的本地阶段在短原生队列内运行原版候选、时间处理及本地展开/联想，固定候选正文、顺序、配置、时间和 read set。需要外部 rerank、Jev 等网络阶段时，同样先复制该阶段准确输入再释放通道，后续仅消费固定输入；不能把完整含网络等待的后缀管线统称为短临界区。尚不能维持原版阶段顺序的可选模式先保留隔离受控执行，并明确其占用限制，不宣称全部模式已锁外。

释放原生命令通道与进程 busy 许可前，必须产出完全脱离 worker 生命周期的 PreparedRecall 包，不引用 worker 内可变对象或随驱逐失效的临时路径。包保存准确正文、候选顺序、完整聚焦输入、配置摘要、来源凭证、撤销代次和校验 hash。focusRecall 在通道外使用同一个原版 AIMemo 聚焦逻辑和准确序列化输入，发送模型前再次核对撤销屏障；不能再偷读已变化的实时图。

PreparedRecall 采用耐久临时包或可核验的宿主不可变对象，状态为 prepared、focusing、published、cancelled、expired。建议初始未领取 TTL 为 10 分钟，全局在途正文计费上限 32 MiB，超大合法包落盘或按原版分批，不丢输入；在途模型占用有显式引用和请求超时。崩溃后核验来源与操作回执才能重用，完成/取消后按引用清理。任务快照按现有任务历史保留政策落盘，不为每个活跃任务在 RAM 常驻全部候选；遗忘清理覆盖已落盘包及历史快照。

这需要新的 RPC 和聚焦适配，当前不是现成开关。必须先用固定输入精确对照原版候选、提示、文件顺序、批处理及入模 payload，证明阶段拆分不改变输入和原版处理语义；真实随机模型输出另做质量配对评测，不承诺逐字相同。显式 active LightMemo 仍按其原生契约执行，不能把被动回忆偷偷替换成一次简化 top K。

SQLite WAL 的读写并发不代表 Rust 索引支持长期多版本图。首期允许候选准备与索引差量发布短时互斥；模型等待、embedding 生成、文档同步都不应持有原生可变图锁。更大规模的 pinIndexGeneration 只有在新增原生 ABI、代次引用计数和资源回收通过实测后才启用，不在架构文档里假定已经存在。

### 依赖凭证

必须记录实际影响模型输出的所有正文输入，不只记录最终返回片段：聚焦候选、月摘要、反思和展开过的材料都属于其来源闭包。图选择和配置依赖另以观测时不可变的代次描述符、资产签名和可查询成员清单保存；首期它不是可供未来 readAtEpoch 的原生句柄。不能把全库哈希假装成精确的正文引用。

凭证至少区分 selected、model_input、returned、derived_source、computational_generation。能够证明精确闭包时使用索引化依赖和共享不可变凭证，避免每个任务复制全库来源。首期未能证明计算影响精确范围时，该 owner 的硬撤销使尚未发布的 prepared/focus 包保守失效；已经发布的任务沿当前冻结来源闭包验证，范围不清时同样保守阻断。普通新增和整理不会触发这个屏障。只有补齐原生依赖观测和成员反查后，才缩小撤销影响面，不为了性能删除保护。

硬撤销发生后，依赖命中或无法排除受影响的在途聚焦不得继续发布；任务后续模型调用必须清除受污染上下文并按可用合法来源恢复，必要时停止。已经发生的外部副作用不能靠记忆回滚，结果要如实保留并说明。来源在远端模型已经被看到的事实也不能被描述成可追溯消除；本地保证针对后续使用、可访问正文和发布。

## 统一提交与发布协议

所有写入口都用同一个 commitMemoryOperation，禁止学习、梦、文件监听或管理 UI 绕过。

~~~typescript
MemoryOperation = {
  operationId, ownerId, kind, causeEventId,
  inputSourceRevisions, inputMemoryRevisions,
  expectedTargets, policyEpoch,
  proposedText, annotations, derivation, coverage
}
~~~

执行顺序：

1. 在事务外读取固定输入并完成模型推理、语义检查和候选生成。
2. 短事务核对 owner、来源、见证、禁记、撤销屏障、准确写目标和幂等回执。携带观测到的 policy/revocation 身份，但不要求整个 owner 序号相等：发生无关策略变化时按最新规则重新核对本次实际输入，相关撤销拒绝提交，无关变化不要求重新推理。
3. 同事务写不可变正文修订、依赖、coverage、变更日志和索引 outbox；给调用者返回已提交状态。
4. embedding 在事务和原生写锁外生成；按输入指纹验收，过期向量不写给新正文。
5. 对原生索引执行有界差量更新并记录 acknowledged generation；尚未收录时可以通过来源和短期证据读取，不能谎报向量已就绪。
6. 合并条目在新索引成功、输入仍有效后发布替代关系，再把原文退出默认召回；保留可逆历史。
7. 发布相关文档和派生导航，记录持久处理回执。

不同数据库和文件不能靠一个 SQLite 事务获得跨系统原子性。使用耐久 outbox、幂等写入和最终发布状态机恢复；任何模型/网络 await 不放在数据库事务内。归档失败可重试，原文不能先被永久删除。

合并计划只对本次具体输入做 CAS；无关新记忆不会使计划失效。若目标已被另一个合并替代，标记 superseded 并重新读取，不按原计划继续归档。仅标签变化不应使正文整合失效，但需要在发布时采用当前合法注释或显式保留冲突。

## 多伙伴调度与资源管理

逻辑上每伙伴独立，物理上共享 CPU、embedding 和模型连接。统一模型配额网关覆盖前台主脑、AIMemo、编码、学习、梦与其他模型请求，执行同一连接的总并发、速率和费用限制；MemoryResourceScheduler 在此网关下负责维护准入、owner 公平和分类。单槽连接在每次模型请求边界分配前台/后台机会，不能只在记忆内部轮转而被外部前台持续占满。capture、索引、标签、时间线、反思、梦与学习不再各自依赖一套互相不认识的全局 busy 标记。

调度维度包括 owner、公平权重、deadline、作业阶段、输入规模、预计资源、重试、取消和欠账年龄。已运行的无害模型请求不因无关写入反复取消；需要硬撤销时立即停止。后台分成有界阶段，在边界保存检查点并释放资源。

首轮资源策略建议：

| 资源 | 建议准则 |
| --- | --- |
| 原生进程 | 沿用全局有界池，默认 4 个作为启动配置；活跃进程不被 LRU 杀死，真正退出才释放许可 |
| 图通道 | 每个实际可变图短时串行；不把远端聚焦等待算作持有图 |
| 后台模型作业 | 全局默认最多 2 个，受用户模型连接并发上限约束；每伙伴最多 1 个语义维护提议在途 |
| 优先级 | 撤销和恢复屏障最高；前台查询优先；已经等待的来源收录和维护有保底服务 |
| 公平 | owner 轮转加欠账年龄；连续前台 burst 有上限，建议从现有 8 次开始验证 |
| 保底 | 资源健康且后台有可执行欠账时，配置可测的后台服务份额；初始目标为至少 10% 的可调度机会 |
| 预算 | 限制实际模型调用、token、embedding 批量、IO 和 resident bytes；不是截掉主脑原始要求 |
| 队列 | 每类每 owner 合并相同原因；大队列落盘，内存只保留可领取窗口；达到容量要明确背压 |

10% 是调度机会指标，不是 GPU 实际算力承诺。单槽模型、不可中断调用、持续过载或外部服务故障时，记录等待原因和欠账年龄，通过分段、公平与背压维持进展；不能承诺在资源不足时仍有固定秒数完成。

索引投递也按 owner 公平领取，不能一位伙伴的慢模型或异常文档长期占住所有伙伴的唯一投递循环。共享 embedding 相同文本可复用计算，但内容缓存、向量标签和响应必须按权限分区，不能从去重缓存泄露另一伙伴是否拥有某材料。

## 启动 恢复与离线欠账

启动先恢复来源日志、撤销屏障、操作回执和过期租约。前台不等待所有伙伴完成深度整理后才可聊天。优先恢复最近访问的伙伴，其他伙伴只加载队列元数据，按公平顺序激活。

恢复按账本游标计算差量，不为离线的每个定时点建一项新任务。相同 owner、阶段、原因范围合并成耐久作业，最早等待时间保留，防止合并后看起来一直是新任务。启动批次加稳定 jitter，避免所有伙伴同时向模型发送请求。

已经完成推理但未提交的作业检查输入和操作回执后决定提交或重算。已经提交但未收录的条目继续 outbox；已经收录但未归档的合并继续发布；dirty 原生状态不能当 clean 复用。失败退避、waiting_model、waiting_resource、defer_no_change 和用户停止分别记录。

用户停止某个作业后，保存绑定 owner、作业类型和具体输入覆盖的停止栅栏；普通 tick 不得立即重建相同输入的同一作业。新的真实来源可以形成新的作业，但不能把已停止的旧范围未经明确恢复就捎带重新处理。禁用伙伴暂停其认知生成，但不阻挡显式遗忘、撤权传播及必要清理。夜间身体睡眠与手动禁用是两种状态。

不对模型调用承诺 exactly once。系统采用至少一次领取和幂等提交；若网络在模型返回前后断开，可能多付一次推理成本，但不能多保存一篇、重复归档或重放外部行为。

## 检索效率与上下文质量

快速回忆依靠稳定索引、增量同步、可复用候选和有据上下文，而不是每次重新拼完整文本库。

1. 热路径先读取本任务固定上下文、当前有效自我认识、目标及相关短期证据。近期来源未编码时仍可追溯，不强制等待日记或时间线。
2. 每个新独立任务按当前语境运行原版被动回忆；同任务工具续接复用快照。空库和明确无需长期资料的受控场景可以短路，不能伪造成功召回。
3. 候选缓存和聚焦缓存绑定完整输入、历史、owner、来源/策略、时间区间、模型和算法配置。不同问题不能仅凭主题名称复用答案。
4. 主动 read/search 可以补充精确事实和历史原话；没找到时说明证据缺口，不把相关故事当作答案。
5. 摘要、日记和原文按 provenance family 组织，抑制重复注入，保留需要展开的原文入口。
6. 冷资料 TDBKnowledge、热本人记忆和当前任务消息使用统一授权服务，保持不同材料性质；冷库查到的内容不自动变成亲历或已学会。
7. 采用增量 manifest、source 反向依赖索引和按需正文，避免为核验一篇候选重新导出全库。过滤必须在获权图或原生候选域内生效，不允许先把无权正文送给模型再过滤结果。

延迟拆成队列、来源核验、索引差量、原生检索、聚焦、复核和模型回答。首轮验收建议设定：空库不启动编码器；10k 热记忆下本地准备 p95 300 ms 内作为测量目标，计时包含请求入队、IPC、来源核验、本地候选检索和包生成，不隐藏排队。基准设备、缓存热度、并发 owner 和后台负载必须固定并报告；冷启动、首次 embedding、远端聚焦及可选网络精排分列。100k 记忆目标在基准设备上单独制定，不能混入毫秒级缓存命中宣传。未测量前不提供总延迟保证。

## 隐私 遗忘与维护边界

owner 由宿主确定，名字和模型参数不能改变归属。每条来源的见证、原始来源域和对外受众独立管理；“伙伴本人知道”不等于可在群里转述。群聊输出、伙伴通信和共享资料必须采用已有受众与保密约束，维护不能扩大公开范围。

合并默认保留同来源域边界。确有跨域本人反思需要时，只能发布到本人私人认知范围并保留所有原始域政策；不能通过私人反思清洗来源，再把摘要当公开知识。跨伙伴共同经历可共享真实公共来源，但各自私人认识独立。

明确遗忘或来源撤权，先设置耐久屏障，再异步清理原生索引、正文投影、时间线、梦、缓存和依赖。屏障生效后即使物理删除尚未完成，也不能被后续查询或迟到模型回写重新公开。恢复备份或迁移也必须导入撤销记录，不能复活已遗忘内容。

记忆老化只影响召回概率和维护优先级，不按年龄永久删除原始历史。明确要求长期保留的内容受保护；重要旧事仍能按人物、时间和原话回查。归档与遗忘必须是不同操作。

## 可观察性与用户体验

维护面板按真正的业务作业显示：待编码事件、已提交记忆、等待收录、正在整合、深度回顾、联想/梦、已处理无新增。把来源数、模型调用数、写入篇数和派生产物数分别统计。

每项作业展示触发原因、覆盖范围、最早下次检查、实际开始/结束、等待原因及产出。检查时间不是完成 ETA。普通后台活动不在聊天中频繁打断用户；有重要新认识时由伙伴按语境自然表达，而非每次展示系统流水线。

必要指标包括：每百条正式消息的编码模型调用数、重复笔记率、编码/收录延迟、最老维护欠账、每 owner 服务份额、无变化重试率、原生锁持有时间、聚焦等待、失效波及记录数、恢复成功率、峰值 RSS、缓存字节和花费。模型内容默认不写入诊断日志；测试使用合成语料和授权副本。

## 故障与竞争处理

| 情况 | 处理标准 |
| --- | --- |
| 用户连续发送新消息 | 编码稳定前缀，保留尾段；旧片段结果不能覆盖新的事件阶段 |
| 同任务期间后台合并 | 任务继续原快照；新任务使用新视图，原文历史仍可追溯 |
| 模型聚焦时新增无关记忆 | 当前固定候选继续；下一次查询取新差量，不因全库序号变化重跑 |
| 聚焦输入被遗忘或撤权 | 中断、撤销未发布结果，按合法来源恢复或停止 |
| 两个写操作修改同一条目 | 短事务 CAS；失败方重读具体目标，不全 owner 清空重算 |
| 只改标签或目录 | 更新注释及必要索引；不重新反思，不重放状态变化 |
| embedding 超时 | 记忆保持已提交、待收录；可查证据，指数退避和公平调度 |
| 合并条目索引失败 | 原文继续默认可检索，不能先删原文 |
| 模型生成梦失败 | 已成功真实维护保持；梦单独失败退避，不伪造叙述 |
| 单伙伴大量学习 | 按 owner 配额、真实覆盖和语义去重合批，不饿死其他伙伴 |
| 应用任意阶段崩溃 | 从耐久阶段恢复；操作、归档和状态效果幂等 |
| 时钟回退或休眠恢复 | 租约重核、绝对事件时间不变；不重复抽签或重演离线经历 |
| 日记文件被外部编辑 | expected revision 和内容 hash 检查；冲突保留双方，禁止静默覆盖 |
| 磁盘满或队列饱和 | 明确背压与持久化失败，不先回复已记住；已有源不因新请求失败消失 |
| 模型、embedding 或上游算法升级 | 保留来源与正文；按受影响资产重建，记录版本并做配对质量验收 |

## 重构路径

生产最终只保留这套标准。实施可以分阶段落地，但不长期维护双记忆引擎；必要的数据升级、备份和恢复不是双引擎回退。

| 阶段 | 主要改造 | 对应当前文件与模块 | 完成门 |
| --- | --- | --- | --- |
| P0 基线与契约 | 固定基准语料、当前行为、资源指标和语义边界 | shared/companion-memory、memory-service、现有真实测试 | 当前问题可复现，旧能力回归范围明确 |
| P1 版本与统一提交 | 正文/注释/撤销分离，operation、lineage、change log、coverage | memory-store、source-access、consolidation、storage contracts | 标签不触发经历重建；撤销仍覆盖全部派生 |
| P2 事件编码 | EpisodeBuffer、合批准入、主动/后台 coverage 统一 | store、capture jobs、memory-model、learning | 调用减少且姓名、约定、纠正不漏；新来源立即可回查 |
| P3 维护控制器 | 每 owner 欠账、独立预算、白天和启动恢复 | memory-service、world-service、world-store、task scheduler | 白天短开机也有维护进展，长期前台不饿死后台 |
| P4 回忆并发 | prepare/focus RPC、短原生 lane、快照凭证、增量 manifest | client、worker、peripherals、query scheduler、frozen memory | 普通新写不重跑准备；与原版同输入聚焦对照一致 |
| P5 学习与深度回顾 | 可验证 procedure、reflection、DreamWave、梦叙述分离 | learning goals、dream model、maintenance jobs | 梦无事实污染，学习有真实结果与反例闭环 |
| P6 投影与质量门 | 时间线按范围重建、可恢复导出、UI 解释和大规模验收 | memory-library、documents、processing UI、probe | 无自我导入循环，指标和真实质量共同通过 |

P1 的快照/变更接口可以先于 P4 定义；P3 上线前必须已经有 P1 的提交与撤销边界。P4 要拆原版聚焦时，先有固定输入对照，不能先改输出再补证明。

用户于 2026-10-26 明确要求清除旧存档和旧记忆，不需要为其准备兼容或迁移。实施直接采用新记忆标准，不导入旧 note、旧索引、旧梦或处理水位。角色定义、头像与模型连接配置不属于记忆迁移；其保留与认知历史清理分开。

新标准自身仍须有准确 schema 标识、事务、幂等回执和中断恢复。禁止自动把旧导出目录重新摄取成新来源。资产管理中的旧记忆索引也应通过受管服务清理，普通资产和新授权资料不得因记忆清空一并删除。实际清理是否完成以实施台账和收据为准。

## 验收标准

### 内容和拟真

固定合成与经授权真实语料分别覆盖首次姓名、重复问候、同事同名、逐次讲完的故事、跨天事件、否定、更正、计划未完成、长任务结果、第三方主张、主观认识、资料局限、游戏剧情和梦。独立审查记录原文、期望和实际输出，不能只用模型自评通过。

关键事实与限制保护作为硬门；重复率、可检索性和自然连续性作配对指标。新方案需在相同模型与语料下减少日常编码调用和冗余笔记，且不牺牲身份、更正、约定和证据覆盖。减少调用的具体幅度根据基线测量设定，不能用一组寒暄样本宣传整体提升。

### 并发与可靠性

1. 任务连续运行两小时，同时同 owner 学习、写日记、整合；原任务不无条件重跑 RAG，维护持续有已提交进展。
2. 查询准备期间连续无关新增，固定候选可完成；不能依赖刚好出现全库无变化窗口。
3. 改标签 100 次，不产生 100 份新反思，也不使所有月份时间线失效。
4. 在来源撤回、遗忘、重置期间，每个阶段的迟到结果都不能复活内容。
5. 在领取后、模型返回后、事务提交后、索引部分更新后、发布前分别杀进程并恢复，无重复写入和错误归档。
6. 合并与原文修订并发，不丢新正文、不归档不属于当前计划的版本。
7. 每天只在白天开机 20 分钟，连续一周，真实欠账可公平推进；没有七份虚构的离线梦。
8. 同时存在 100 和 1000 位伙伴，只有少量活跃时不为每位常驻原生进程；冷 owner 的真欠账不被热 owner 永久饿死。
9. 没有未结算语义欠账、真实新问题或结果，输入及相关模型/算法配置未变化且该范围已成功结算的一周内，不因 tick 或跨天反复付费生成；已有欠账恢复和必要重建仍可执行。
10. 日记和时间线导出、外部编辑、重启恢复不形成自我摄取循环。

### 检索与资源

采用 1k、10k、100k 本人记忆，及多 owner 不同活跃比例，分别报告冷启动、热新任务、相同查询缓存、并发写入、后台维护和撤销。记录 p50/p95/p99、峰值 RSS、磁盘和模型输入量，不能把 LRU 计费字节当应用 RSS。

固定原版 VCP 与宿主准备后的候选、聚焦输入序列和输出做配对验证；实际模型再测身份归属、相关性、更正、未知不编造、跨入口回忆、旧事细节和另一伙伴私有 canary。同任务缓存命中与新任务回忆分别报告。

原生真运行、模拟模型的机制测试、真实模型内容测试、UI 和打包验收各给结论。文档和接口存在不算完成；任何尚未通过的质量或资源门保留明确状态。

## 设计依据

VCP 的事件完整后落笔、先查旧记忆、有序具体标签、主动与被动回忆、时间线和跨时间联想值得保留；WorldlineBox 已有的来源校验、任务快照、持久队列、硬撤销及可逆归档是这次重构的基础。差异和源码位置见 [对照调研](companion-memory-upstream-research-2026-10-26.md)。

观察、检索与有据反思的分工也可参考 [Generative Agents](https://arxiv.org/abs/2304.03442)；分层上下文管理可参考 [MemGPT](https://arxiv.org/abs/2310.08560)。本文的维护参数、离线欠账和协议是针对本项目的设计，不是论文验证过的配置，也不把这些研究视为真人记忆的等价实现。

存储实现应遵守 [SQLite isolation](https://www.sqlite.org/isolation.html) 和 [WAL](https://www.sqlite.org/wal.html) 的边界：读写可以并行，一份数据库仍串行提交写事务；长时间固定读事务会影响 checkpoint。因此任务快照使用已保存的不可变应用数据和凭证，不跨整个模型请求持有数据库读事务，也不以 WAL 代替原生图的并发协议。
