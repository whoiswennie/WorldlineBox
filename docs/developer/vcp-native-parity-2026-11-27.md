# VCP 记忆与上下文移植验收

## 对照基线

本次以 VCPToolBox 的 `fd1eec0dfe25507c22a42232b4b64cac8c0c7768` 和 VCPChat 的 `ea8942cfbe275bbe7fca1cbf1222f6c0ca0b3fe4` 为对照。两者均在 2026 年 11 月 27 日核对了官方远程分支。本机独立导出项目使用的 ToolBox 基线是 `e03ef4b2`。到 `fd1eec0d` 之间变动的是 GPTImageGen 和两个通用工具调用模块，日记、召回、梦境与 MemoMaster 原件在这两个版本之间相同。可按随包来源清单找到各文件的 Git 路径和 SHA-256。[官方更新记录](https://www.vcptoolbox.com/?page=changelog) · [ToolBox 固定源码](https://github.com/lioensky/VCPToolBox/tree/fd1eec0dfe25507c22a42232b4b64cac8c0c7768) · [VCPChat 固定源码](https://github.com/lioensky/VCPChat/tree/ea8942cfbe275bbe7fca1cbf1222f6c0ca0b3fe4) · [ToolBox 提交间差异](https://github.com/lioensky/VCPToolBox/compare/e03ef4b27d73fc0953f5a7356018036e868da1d6...fd1eec0dfe25507c22a42232b4b64cac8c0c7768)

ToolBox 来源清单含 404 项，VCPChat 聊天清单含 43 项，另有 28 项 CDS 和记忆插件子集。各清单记录实际分发字节的 SHA-256。MemoMaster 与官方 Git blob 的原始字节一致。Windows 检出中的部分 JavaScript 和模板使用 CRLF，这些文件与 Git blob 的源码对照统一文本换行，并另外保留各自的字节摘要。

另两项高级维护测试在同一发行版上通过。它们通过本地受控的规划模型、实际 DSH 进程和 VCP 索引，验证了逐项批准与驳回、合并与归档、冲突后保护原文、撤回后清理缓存、跨群拒绝访问和失败后手动重试。初次运行有 DSH 冷启动超过 120 秒，随后从两份新建资料分别启动成功。[高级维护验收入口](../../tests/e2e/companion-bot-maintenance.test.ts)

## 检索速度与质量的测量口径

测试集含 48 篇同受众日记和 44 道中文查询。先标注足以回答每道题的日记，再由未看过运行结果的第二位审阅者检查歧义、旧说法与查询是否透露答案。修订题面后冻结测试集，SHA-256 为 `45baebd186d954b6a8e636fd67a1029b69066f454b766de6d9f9848e118ca1b1`。42 道可回答，其中 36 道的答案在一篇日记里，6 道需要两篇；另有 2 道资料库未记录的对照题。更正类问题以足以回答现行安排的最小证据为准。[固定日记、问题与标准答案](../../tests/fixtures/vcp-recall-benchmark.json)

- Top-1 衡量首条命中是否属于标准答案；Hit@3 衡量前三条中是否至少有一篇答案。分母均为 42 道可回答的查询。同一题的重复计时不增加准确率分母。
- 对多来源问题另查两篇是否都在前三条。全局来源覆盖率的分母是 48 个应召回的日记引用。两道库外问题单列。最近邻搜索仍可能返回候选，作答模型应该如何使用它们属于另一项测量。
- 对照区分首次见到某个问题、同题热重复，以及关闭进程再打开后的第一次查询。P50、P95 是实测的中位延迟和第 95 百分位延迟。聊天路径计到模型实际收到上下文，不包含模型生成答复。样机为 Windows 11、Intel Core i9-14900HX、32 GB 内存，使用应用随包的 768 维 CPU 向量模型。

官网在 RiverMemo V2 的更新条目中报告过双场检索 1–3 毫秒。这里的对照使用上述固定提交。已有查询向量时的原生读出、由中文问题开始的检索、以及打开桌面软件后首条消息抵达模型，各自单独计时。[VCP 官方更新记录](https://www.vcptoolbox.com/?page=changelog)

### 同机对照结果

### 从用户发送到模型收到记忆

使用真实的 `message.send`、DSH 0.2.2-rc.5 和随包 CPU 模型，在本机接收模型 HTTP 请求并检查当轮实际发送的 RAG 区块。问题不包含答案。冷样本每次重启应用服务、VCP 工作进程和向量进程，保留 DSH 主机、已有索引与操作系统文件缓存。热样本沿用同一会话。每个规模循环使用 12 道生活事实题，所以 25 次热投递代表 12 个不同问题。

两个规模的日记和原始消息全部完成索引与历史投影后，每组的 5 次冷、25 次热都在本轮模型收到的 RAG 区块中找到了目标事实，原生召回事件也返回了对应的完整日记。近期输入和普通 HTTP 历史均未携带目标原文。[24 篇逐次实录](vcp-native-parity-2026-11-27/chat-24.json) · [720 篇逐次实录](vcp-native-parity-2026-11-27/chat-720.json) · [聊天基准入口](../../scripts/benchmark-bot-chat-recall.mjs)

| 数据量与启动状态 | 记忆准备 P50 / P95 | 用户发送至模型 HTTP P50 / P95 | 当轮 RAG 命中 |
| --- | ---: | ---: | ---: |
| 24 篇、64 条历史，冷启动 | 2649 / 3160 ms | 2765 / 3612 ms | 5 / 5 |
| 24 篇、64 条历史，预热后 | 28 / 77 ms | 104 / 147 ms | 25 / 25 |
| 720 篇、1,000 条历史，冷启动 | 2760 / 3211 ms | 2866 / 3665 ms | 5 / 5 |
| 720 篇、1,000 条历史，预热后 | 26 / 84 ms | 107 / 157 ms | 25 / 25 |

正常样本中没有召回超时。DSH 在同一话题内会保留之前的上下文提醒，因此即便旧提醒也包含答案，评分仍要求答案出现在本轮新提醒的 RAG 区块。另一次让同受众的维护操作持续占用工作进程，新问题在 269 ms 到达模型，当轮跳过记忆注入。这个受控样本验证输入可以继续。样本库含 12 个目标事实和 708 篇按八个主题生成的干扰日记，测量覆盖这台机器的这个规模。

## 记忆维护工作台

普通整理按原始月份选取新写或修改过的版本，也能通过原生多种子联想发现其他月份的记录。一个新版本完成初次分析后，如果仍在 30 天沉淀期，到期重新参加冗余检查。已经明确驳回的同一版本保留审阅结果。维护日志属于该伙伴在当前受众的私有工作台。

| MemoMaster 原始模式 | 盒子中的入口与权限 |
| --- | --- |
| Scan 扫描报告 | 分页复查当前受众内已索引的日记，可重新扫描已处理版本。只生成报告，执行层无可写候选。 |
| Organize 智能整理 | 按原生日记、标签和来源证据处理冗余。默认由独立审阅逐项核对后执行，无把握则留给用户。工作台可关闭模型审阅。 |
| Track 事件追踪 | 追踪进行中、完结、过时和冲突。保留目标原文，向日记追加有证据的状态标注。修订涉及的日记版本在写入时再次核对。后续撤回标注所依赖的证据时，带有该标注的版本会退出召回，其他独立原件仍保留。 |
| DeepClean 深度清理 | 用户显式启动，对当前受众做全面盘点。受管理范围仅包含该伙伴有权访问的日记。候选逐项交由用户决定。 |

## 桌面实现的边界

- 开发版退役分两次记录。第一步清除旧 `memory` 和两项采集缓存，写入 `.vcp-v5-legacy-memory-retired`。第二步核验旧采集、规划和审阅模型工作文件的目录、事件编号和文件名摘要，清除相符的回执副本，写入 `.vcp-v5-legacy-work-retired`。两步独立重试。新版维护在 `vcp-maintenance-v2` 下运行。回归覆盖旧索引被占用、Windows 目录联接、同名目录重建和 V5 日记跨重启保留。[一次性迁移与重启测试](../../tests/unit/bot-memory-generation.test.ts)
- 主数据库版本 23 按伙伴、话题和已投递事件识别接收过旧日记的模型会话。后续提问使用新绑定，其他伙伴与干净话题的绑定保持可用。一次性标记 `vcp-v5-retired-evidence-removed` 确认已清除发出及未发请求中的旧式证据副本。升级过的开发资料继续沿用已记录的旧会话编号，避免把其后的正式会话误判为旧会话。这项升级保留用户的可见消息。本次按用户要求清空本机历史属于单次资料操作。[模型会话升级回归](../../tests/unit/bot-memory-session-migration.test.ts)
- 每个伙伴在每个受众有自己的日记、向量库、历史和审阅记录。官方管理员可以读取公共目录、在多个 Agent 的索引间工作，盒子将它的权限限制在当前伙伴和受众。私密伙伴资料和维护报告不会写入上游示例的公共日记本。
- 固定向量空间是应用随包的 `embeddinggemma-2-compact`，维度为 768。原始独立导出中的可选 BGE 服务、外部专用 Jev 模型和外部重排器在盒子的固定模型配置中未启用。因此，上述排名对照使用同一个本机向量空间。使用其他模型的官方服务器可能给出不同结果。[模型与权重清单](../../resources/embedding-models/manifest.json)
- 正式数据升级应保留日记文件、受众归属、写入来源与撤回记录。现有宿主在模型签名或维度发生变化时保留原库并报告需要重建索引。未来更换向量空间应从这些原件构建和校验新的派生索引，当前开发版的一次性退役规则仅适用于 demo 目录。[向量空间签名校验](../../src/main/companion-bot/memory-service.ts)
- 桌面沿用原生夜间抽样及成功冷却，并增加按伙伴交互计时的白天闲时运行、关机后的续接和 30 天沉淀期后的复查。原生选择何时需要分卷。盒子在两份索引都确认后才归档原件，以便进程中途退出仍能恢复。真实消息有前台优先权，自动召回超出本轮预算时，用当时已取得的上下文回答。
- 独立导出原本提供连接外部客户端的 HTTP 服务。桌面聊天使用内置工作进程和应用已有的模型连接。记忆不需要用户安装服务器或填写专用密钥。普通聊天、模型审阅与梦境叙事使用应用自己的聊天模型。
- 本文对照的是官方公开源码、固定输入和真实回执。模型生成内容受模型、随机性和实际对话影响，长期运行后的每次自然语言回复不在逐字等价的验证范围内。

## 复验入口

在已准备构建依赖的 Windows 项目根目录运行。两个 JSON 实录是本机验收输出，下面的环境变量指定复验时的写入位置。上下文对照默认取同级 `../vcp/VCPToolBox`、`../vcp/VCPChat` 的 Git 对象，对照已打包版本时将 `WORLDLINEBOX_PACKAGE_ROOT` 设为 Windows 应用目录。

```powershell
node scripts/stage-bot-memory.mjs
npm run verify:bot:memory
$env:WORLDLINEBOX_VCP_TOOLBOX = (Resolve-Path '../vcp/VCPToolBox').Path
$env:WORLDLINEBOX_RECALL_REPORT = 'artifacts/vcp-native-parity/semantic.json'
$env:WORLDLINEBOX_CONTEXT_REPORT = 'artifacts/vcp-native-parity/context.json'
npm run verify:bot:memory:recall
npm run verify:bot:memory:context
npm run benchmark:bot:memory:recall
npm run test:bot:protocol
node scripts/benchmark-bot-chat-recall.mjs --notes=720 --history=1000 --cold=5 --hot=25
```

桌面聊天计时使用已安装的 DSH、隔离的用户数据目录和本地可控的模型端点。用应用当前选中的真实聊天服务复验时，可运行 `node scripts/verify-bot-real.mjs --real --memory-only`。该项会用应用已有的全局模型发送合成对话，覆盖普通聊天、跨话题自动召回、带来源的日记以及显式记忆工具。
