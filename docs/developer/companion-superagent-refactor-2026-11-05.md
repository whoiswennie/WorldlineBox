# 伙伴持续主脑重构方案

目标是让每位伙伴拥有一个由 WorldlineBox 管理的持续 Agent。聊天、伙伴私聊、群、世界和执行器回执进入同一伙伴事件序列；DSH 承担独立执行，VCP 提供长期记忆。聊天窗口是消息目的地和权限视图，不再承担伙伴身份本身。

## 已确认的问题

| 问题 | 代码位置 | 改造方向 |
| --- | --- | --- |
| 转达给伙伴时，发送者消息可直接写进用户与收件人的私聊 | store.contactPeer 的 destination=user 与 trustedContact 例外 | 先进入双方伙伴真实私聊，收件人凭单次宿主授权自行向用户回复 |
| 查看伙伴私聊需要选择双方，并可创建尚无消息的空会话 | BotWorkspace 与 BotPeerConversationPicker | 真实通信自动产生聊天项，入口筛选已有记录，提供消息预览和活动提示 |
| 伙伴按会话分别调度和保存协调上下文 | scheduler、store.claim、service.respond | 同伙伴串行接纳事件，保存统一的耐久事件序列和授权任务视图 |
| 工作授权隐含在源事件、工具权限和提示中 | service 的 dsh_task 分支 | 保存不可变授权依据、来源、受众、策略版本，恢复前重新核实 |
| 后续消息没有明确的任务订阅和归属账本 | message.send 与 dsh_task_control | 保存订阅和跟进归属，明确绑定的跟进直接进入原执行器，越界请求交回主脑 |
| DSH 执行轮次 completed 可直接成为业务任务 succeeded | dsh-bridge、service.runTask | 只有结构化 ready/dropped 报告与效果核实才能结束业务任务 |

## 运行边界

每位伙伴有稳定主脑 ID、统一事件序号和全局任务协调账本。处理某个群或私聊时，只构建该受众获准的上下文视图；不同受众的原文、摘要和 VCP 资料不能因主脑统一而直接混合。用户与伙伴的私聊可查看该伙伴在用户参与会话中的任务协调信息，伙伴双方私聊和私人世界正文保持独立权限。

主脑长期存在于耐久状态中。空闲时等待事件，不通过无意义的模型轮询制造持续运行。重启恢复原事件、原任务和已提交效果；不创建相同目标的新任务代替恢复。

## 开发顺序

1. 修复伙伴通信目的地和真实消息入口，保持旁观只读与来源撤回。
2. 引入统一伙伴运行账本和按伙伴串行的调度，提供经过受众过滤的协调视图。
3. 保存任务授权和订阅，接通明确绑定的跟进，保留人工停止及未知效果栅栏。
4. 接入结构化执行器报告，分开记录执行轮次和业务进度，支持原任务接续。
5. 完善主动工作观察规则、长期记忆的获准跨会话查询和端到端验证，根据实测修正调度与上下文预算。

## 验收

- 用户要求 A 找 B 私聊：出现真实 A-B 消息，不向用户-B 私聊写入 A 的转达气泡。
- 用户要求 B 向自己发消息：A-B 内部投递有宿主绑定的请求依据，由 B 本人向用户发送，重试不重复发布。
- 伙伴私聊真实发生后自然出现在聊天列表，用户可直接查看；浏览入口不创造对话。
- 同伙伴跨会话输入具有统一处理序列，不并发产生相互冲突的主脑决策；不同伙伴仍可并发。
- 私聊、群、世界及任务回执按当前受众构造资料，无法借全局状态读取未获准正文。
- 后续输入能绑定原任务和会话；完成、停止、恢复、越界交回有耐久记录。
- Worker 正常结束但没有业务完成报告时保留待处理状态，不显示成功。
- 崩溃、重试、取消、撤回和成员变更不能重复动作、恢复已停止工作或错投受众。

## 实施记录

2026年11月5日完成本轮核心重构。已有工作区的人格模板、任务控制回执及其他未提交改动保留。

| 交付 | 实际行为 |
| --- | --- |
| 伙伴通信 | A 的转达先进入真实 A-B 私聊。B 凭单次宿主授权以本人身份向用户回复；消息目的地和重试回执绑定，不能伪装来源。 |
| 私聊入口 | 真实消息自动形成列表项，显示最近消息和有界会话内新消息提示；浏览不创建空房。旁观不获得发言或任务控制权。 |
| 持续身份 | 每伙伴一个稳定 brain ID、跨会话事件序列和串行决策入口；不同伙伴并发，DSH 长工作不占聊天主脑。 |
| 授权与跟进 | 新任务保存不可变原始授权。只有真实用户或有耐久转达证明的协作请求可开工；机器通知不会自行刷新工作授权。明确跟进绑定原任务，结构化问题冻结原 questionId。 |
| 业务状态 | 根 Worker 的 ready/dropped 报告、执行轮次终态和效果回执共同决定完成；缺报告保持 waiting，子 Agent 不能结束父任务。 |
| 历史继续 | 未被人停止的成功/失败任务可在人类明确跟进后沿原 Mandate、目录和 Session 继续。人工停止撤回后续授权并保留此前真实结果；旧 ready 不能完成新指导。 |
| 长任务 | 经过授权的执行与宿主证明的交付不因十分钟传播时限而失效；累计动作上限、派生轮数和其他自动传播时限保留。 |
| 长期记忆 | 用户 direct 可经 agent_memory_scopes → memory_list → memory_note 主动发现并读取同伙伴在用户参与群中的记忆；来源过滤、读前后 ACL 和派生撤回链均保留。默认被动召回不扫描全部域。 |
| 恢复 | 新 turn 冻结原工具表；工具升级不重发已提交写入。旧无快照 turn 先核实效果再受控结算，未知保持栅栏。续投半写回执按原生输入核实，不重投原始任务。 |
| VCP 重试 | watcher 与 repair 共用一个可取消计时器，保持原检索/索引算法与上游磁盘快照；竞争失败用例从 6 次 flush 降到原 5 次预算以内。 |

主脑工具说明采用精简运行视图，参数约束不变；初始上下文为真实工具接续保留余量，原件分页按实际调用与步骤账本计量。32k 上下文、长原件、滚动摘要和重启回读均有回归。时钟增加宿主换算的上海本地时间，UTC 原值单独保留。

## 当前边界

应用运行期间持续接收事件，空闲等待；退出后耐久保存并在下次启动恢复。按用户本次确认，当前架构以世界线盒子作为主脑、DSH 作为受派发的执行能力，云端常驻不纳入当前任务，也不作为验收缺项。外部 IM 网关、独立模型监督器、可配置主动工作规则和完整跨任务越界重新评估属于独立扩展。当前无明确授权的自动工作候选只记录，不自动执行。

跨域语义搜索、DeepMemo或TopicMemo的旧返回格式若缺少可核实来源，会返回 unavailable。受管目录与日记原件的发现/读取是真实可用路径；不能把 unavailable 解释为该事实从未存在。写入、整理和忘记仍仅限当前受众，跨域查询结果不会自动变成本域新事实。

本轮验证覆盖代码、受控协议与本机组件，未进行付费自然模型质量实验、数月连续运行或独立干净机器验收。测试使用隔离profile和夹具，未安装新的发布包。一次早期原生测试留下的临时目录删除被自动审批以 blocked by policy 拒绝，已保留；后续新测试的清理顺序已修正并通过。

## 用户界面反馈后的修正

2026-11-05 的实际使用反馈指出：08:34 的旧对话被说成凌晨，伙伴私聊的说明文字溢出且多余，聊天中的链接、文件与跟进标签不协调，原任务收到补充后聊天没有确认，以及外观壁纸被实色面板遮住。

- 时间：原历史时间戳仍为 `00:34Z`，而界面显示上海时间 `08:34`。主脑当前时钟现在明确提供“早上/上午”等时段；trigger、history 及 chat_read_message 的时间统一为 `+08:00`。原始记录保持原时间，提示同时要求核对历史正文中的旧时段，不能沿用“凌晨”推断当前时间或用户情绪。
- 跟进反馈：从持久 Inbox 和 bot_task_followups 账本在原用户消息下投影排队、已交给原任务、需补充回答、失败、取消状态，可点击回到原任务。它证明指导已获宿主原任务接纳，不冒充 DSH 已消费输入或业务已完成，也不将执行器思考过程复制到聊天。刷新页面仍能读取真实状态。
- 聊天排版：独立裸链接或有标题链接显示资源卡片，包含真实站点、路径和内置浏览器打开入口；段内链接保持行内形式。统一正文大小和段间距，减轻气泡边框。单个文件直接显示文件卡片和预览入口，两个及以上文件可展开，保留保存与原文件系统打开。跟进标签并入输入框，长标题截断并保留 title。
- 私聊列表：移除顶部说明和底部重复的空列表提示，筛选与实际消息入口不变。
- 外观：选择内置或保存的壁纸主题时自动开启“面板显示背景图”。增加启动迁移，已保存的旧主题不必重新选择即可恢复面板透出；只迁移一次，后续用户明确关闭或自定透明度会保留。联系人、聊天区、头部、消息和输入框都使用相应半透明表面；不复制壁纸、不新增视频播放或背景模糊；减少透明效果偏好保留实色回退。
