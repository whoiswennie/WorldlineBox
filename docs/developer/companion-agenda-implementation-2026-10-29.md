# 伙伴统一日程实施记录

日期：2026-10-29。关联规范：[统一日程与自主行为重构标准](companion-agenda-autonomy-standard-2026-10-29.md)。

本记录描述实际源码接入，区分“已实现”“短时验证”和“尚未证明”。不使用被否定的设计草案作为实现证据，不把模型模拟结果解释为真实模型的人格质量证明。

## 当前数据与执行入口

每位伙伴只有一个正式日程模型。对用户统一叫“日程”，在对应伙伴聊天的右侧栏进入；左侧不再设置独立任务/日程中心。内部区分任务和系统事件，日常安排是任务在时间上的投影。正式协议在 `src/shared/companion-agenda.ts`，SQLite 权威在 `src/companions/agenda-store.ts`，宿主领取与执行在 `src/main/companions/agenda-service.ts` 和 `service.ts`。

任务可以由本人、用户或其他伙伴发起，涵盖一次、定时、周期执行和长期学习/项目。`agenda.tasks.read` 将 scheduled 与 longterm 两种现有权威投影为同一任务列表，不另建一张任务表或另一套学习目标。来源分类由宿主核验真实消息及原生作业产生，不能靠模型填写 category 改变管理权。世界轮询本身是系统事件；伙伴据此真正决定开展的持续行动是任务。原生行动的具体标题与目标通过准确 owner/reference/attempt 的只读 presentation 展示，不改旧封存正文，也不重新触发执行。

规则描述将来的考虑条件；发生固定该次规则版本、概率机会和来源；执行保留实际过程、作用回执和恢复点。计划、虚拟动作、模型自述均不能直接成为已经发生的经历或已掌握的知识。

| 行为 | 当前接入 | 对用户的呈现 |
| --- | --- | --- |

## 对话协商与人格自主性

普通主脑使用原生 `agenda` 工具读取同一份日程、详情和长期方向。变更提交经过实际来源检查、权限检查和修订 CAS；界面与聊天不写两份设置。

当前职能指引要求先按已发布人格、偏好、已有承诺和真实条件作判断，可以接受、保留、延后、提出替代或拒绝。授权模型只回答“这次真人是否明确允许这项作用”，不替伙伴作人格决定。模型可以在获得允许后仍不调用写工具。拒绝不能暗中改动安排；冲突和失败不能说成已经修改。

任务控制可保存实际 accept/negotiate/decline 回应。伙伴可以暂停、继续或拒绝真实委托任务，不能改写委托人的原消息，不能管理系统维护事件。一次、间隔与窗口触发均可设置执行概率；同一次机会在数据库中固定抽样值，刷新、重复检查或重试不会反复抽取直到成功。周期任务的列表只保留最新/当前机会及下次检查，完整执行历史仍在详情弹窗保留。

已用原生结构化主脑协议、真实 SQLite 与脚本模型覆盖：

1. 查询正式日程并使用实际返回内容。
2. 接受调整后取得准确修订回执。
3. 即使有修改授权也选择拒绝/替代，且数据库没有变化。
4. CAS 冲突后告知没有改成，而不是宣称成功。

另有正常聊天生成器、原执行内核、真实日程工具读和原回复核验器组成的短链路用例。**这些证明工具与持久化行为，不证明真实提供商在长期交流中总能表现自然。** 不增加“随机拒绝率”“性格分数”来伪装人格。

## 人格与知识的边界

用户创建时写入的起点封存。后续用户可以提出培养方向和具体反馈，通过实际交流、学习、回忆、反思形成候选，再由现有发布器校验来源与差异，发布当前人格；方向本身不是已经形成的性格。

人格处理器直接读取正式日程方向，按真实会话范围固定语义定义哈希。方向暂停、结束、改变内容或来源域，会阻止旧提议继续发布。仅更新进度不会被当作新经历或新的培养依据。临时停止发布器与永久退役是不同操作；修改方向不会让伙伴永久停止成长。

长期变化依靠条件、重复经验、矛盾与修订依据表达。情绪、讲话方式、价值和认知不通过好感/服从/活跃度等数字来定义。概率只描述安排的触发机会。该工程借鉴渐进学习与反思，不声称已实现临床验证的人类人格发展模型或一种适用于所有人的固定成长曲线。

## 授权与实际能力

用户可以授予、查看、撤销持续范围。伙伴不能自行扩大持续权限。规则可以绑定具体范围；没有具体绑定时，只采用当前有效的通用范围并在实际执行前封存其 ID 和修订。撤销会阻止继续作用，不因排期较早而继续使用旧权限。

- 观察绑定明确选择的原生窗口及其当前元数据。读取像素前后检查授权、窗口变化、锁屏和取消；不回用旧截图代替实际观察。
- 资料读取与交付限制到真实目录，拒绝越界和链接绕过。交付到本人实际私聊，保留具体消息和附件回执。
- 公共网页研究使用隔离的公共读取，校验 DNS/重定向，不借用用户登录会话执行表单操作。
- 深度思考使用真实 DSH 子执行，但此自主思考入口强制新会话、只读、无工具/技能；不把认知结果当作已执行外部操作。记录会如实标记归档或返回内容截断。
- 其他私聊的内容、材料、私密输入和结果不会因为是系统保护规则而泄漏到伙伴/群聊；本人主脑可以在自己的受权范围内规划，但对外发送仍经过实际端口核验。

自主桌面观察和文件读取不是无限制电脑控制授权。普通用户明确委托的原有 DSH 执行能力继续受原运行策略管理。

## 能力过程、连续观察与原生图片分析

普通本人私聊和自主主脑均可在实际持续授权内使用 observe/think。每次真实工具调用先登记 capability 过程，再执行能力；绑定当前消息与回复，或准确的本次日程执行。过程卡沿用现有行动展示，记录输入、真实阶段、结果、失败与取消，不成为第二套任务，不重复占用顶层并发，不自动变成日记或记忆。DSH 原有执行卡保留；本次原生 think 也绑定准确 DSH taskId，能打开原始执行记录。观察、记忆、日程等调用不再只藏在“正在思考”后面。

过程可见性由 `capability-evidence.ts` 核对实际来源、父回复/循环或真实自主执行；不再强制每个能力过程都有一份旧 DSH checkpoint。来源撤回、父归属不符或持续观察权限失效仍会收起内容。能力过程不进入 DSH 子任务收件箱，不得借旧 DSH send/resume 等入口重新执行；原生失败、取消及日志故障如实区分，日志写失败不会把已启动的付费原生进程丢出父执行的回执。

observe.watch 使用实际选定窗口的 getDisplayMedia/MediaRecorder，默认约 6 秒/6 帧，无音频，得到 WebM、带时间戳的抽样帧与拼图。每次调用有独立隐藏窗口/Session；锁屏、撤权、取消、来源变更时停止。帧数、单次片段长度和传输大小边界用于限制一次调用的资源，不是每日额度或自动化预算。

素材保存到宿主确定的伙伴 `.运行/观察`，以 UUID、文件摘要和清单封存；只有本次真实执行的保存回执能引出后续分析。文件路径、模型填写的 UUID、旧图或别人的素材都不能自行建立读取权。观察不会自动把画面写进长期记忆。

think(observationId) 将已验证拼图转为真实原生图片块，经过 Main-only visualInputs、DSH broker 与原生 bridge 进入 SDK 图片附件，并要求原生接收回执匹配。保持新会话、零工具/技能，不通过放开整个文件系统来读视频。DSH 实际分析的是所提供的抽样图像，不能声称看过未抽样的完整视频或听过音轨。日志/文本只存图片元数据，不把 base64 当文字交给模型。

实际取像时出现系统级顶端短提示，使用“某伙伴正在看看你在忙什么”等措辞，合并同时观察的伙伴。提示不抢焦点、点击穿透、自动消失，不因长时间观察或连续刷新一直霸占屏幕。通知节流只限制重复提示，不限制观察本身。该原生窗口的实现已接入；本轮没有实际读取用户屏幕或运行安装版视觉验收。

## 提醒工具协议修正

修正了工具导出在根层包含 oneOf/anyOf 的明确兼容问题：发送给提供商的参数根为 object/properties，各动作仍由本地严格 Zod 协议校验。覆盖 agenda、memory、world、DSH 及新增观察工具的实际模型请求。真实隔离 SQLite 用例确认一分钟提醒可登记、幂等返回、虚拟时间到点仅执行一次。

现场 HTTP 400 的原始提供商响应未保存到可用日志，因此不能断言这个协议缺陷是现场报错的唯一原因。没有通过真实模型重复发请求来凑成功结果。

## 失败、暂停与恢复

规则和执行有独立状态；暂停一次执行不等于取消整个方向。副作用步骤在分派前留稳定作用键，成功后留真实回执；分派结果不明时标记待核对，不能自动重发。恢复前检查原生子作业的伙伴归属、原输入版本、准确 ID 与当前状态。

结构化修复有有限次数，语义拒绝不通过格式修复变成允许。多次处理失败进入搁置，显式恢复开启新故障周期；终身错误与成功步骤仍保留。放弃不删除原始消息、事件或付费结果。一个坏事件不阻止其他独立事件继续。

备份恢复会清除旧租约、保留实际回执、隔离不明作用，并撤销不能继续信任的原窗口授权。恢复规则不会自动重放已分派但未知的发送。

## 界面与读取

实际组件为 `src/renderer/companions/CompanionAgenda.tsx`，嵌入聊天右栏；日常、任务、系统事件都读同一权威。任务内同时展示周期任务与长期任务；系统维护默认折叠，不让轮询淹没日常时间线。头部收紧，时间和事项作为主体；实际并行事项并列，条件触发单独注明。用户否定的顶部状态横条、大号日期/秒钟、独立全天概览侧栏和大片橙色作息卡已删除。日期与翻页合并为紧凑导航；窄时间轴与每项共用同一行，中性细线与小节点连接事项。“此刻”按真实时刻在序列中出现，不使用与正文位置不对应的 24 小时缩略刻度。运行状态与实际阶段留在各项上，不再拼成一条重复摘要。

默认跟随今天并跨午夜推进；主动翻历史/未来日期后停止跟随，点击“今天/回到此刻”恢复。“此刻”游标只在真实今天的今天视图显示。页面隐藏会停止本地时钟，恢复可见后追上当前时刻；每秒 tick 不请求 IPC、不清空数据、不强制滚动。世界时间作息仍明确显示自己的时间规则，不借世界钟伪造真实时间。

点击事件打开独立的详情弹窗，主体列表不展开、不挪位；弹窗单独处理关闭、Escape/输入法、焦点约束与焦点返回。机会、条件、结果和恢复操作保留，真实结果字段以正文呈现，原始 JSON 技术回执折叠。权限和高级编辑按需展开。

伙伴侧栏、联系人、认知档案培养入口和记忆库均转到统一日程。独立任务中心、工作台、旧日历/生活规则等组件已撤除。完整认知档案仍只读呈现正式人格、起点、版本与来源。

日程列表通过有索引、定界、分页的 SQL 批量关联读取，不逐条读取大量检查点。列表移除秘密租约和大段执行原文；详情才取完整过程。后台刷新保留同源有效内容；阅读日程不会领取执行或重抽概率。组件截图是实际组件的隔离示例数据，不是用户当前资产库的真实运行截图。

- `artifacts/agenda-validation-2026-10-29/integration/owner-agenda-final.json`：本次收尾源码摘要、类型检查、定向 lint 与短测回执。此前 `final-integration.json` 保留为早期快照，不代表本次新增连续观察与分类功能。

最终定向单测为 6 文件 62 项，耗时约 2.15 秒；另一个准确私聊/话题绑定用例约 0.91 秒；真实 SQLite 能力卡接线只运行 1 项，测试体约 1.15 秒。Main 等改动的定向 ESLint 与全项目 `tsc --noEmit` 均无错误。它们分别验证各自的协议和接线，没有将模拟驱动解释为真实桌面/模型验收。

本轮验证使用短时协议测试、真实临时 SQLite、虚拟时钟和受控 Electron 驱动。没有耐久、十万事件、真实模型成长、多轮付费提供商或重复打包测试，没有读取真实用户屏幕或再次清空用户资产库。

尚未证明整套已安装应用的真实提供商对话、真实桌面录制/顶端提示视觉效果和长期自主生活品质。较早的 Main 短采样只证明日程工具回填，未证明完整聊天结束，旧诊断记录在 `integration/main-once.json`；没有将其算作本次完整应用验证。DSH 原生图片接入需要新 bridge 进程加载源码，已启动的旧进程不能据此宣称已更新；未匹配图片接收回执时会明确失败，不能假称已经理解图像。

普通聊天中的交互式等待/子思考仍保留原回复根执行，其认知槽不会像领域单步等待一样完全释放；此处没有虚构槽位释放或重新建立另一个任务中心。

## 源码切换与数据

新版公开入口拒绝旧 `tasks/schedule/work-order/life-rule/activity` 等管理请求，不用兼容转发维持双重调度；旧领域类中仍被复用的执行与存储函数是内部实现。旧独立语义泵在接入时停用，必要的世界物理时钟、持久化、撤回、心跳继续工作。

本轮没有重删用户已重建的伙伴。旧开发数据若无法继续使用，应从明确的伙伴退役/重建入口处理，不能扫描资产库并把全部目录转成记忆。日程、权限、原始消息、当前人格、知识与检索索引有各自职责，读取界面不会把它们相互重写。

## 20 时后现场问题修正

### 行动消息的错误隐藏与恢复

现场只读查询确认，19:46 的三条能力行动消息及正文仍在 SQLite 中，但被旧执行来源校验写入了失效标记。原生能力记录曾错误地沿用 DSH 子任务的 checkpoint/readset 前置要求。现在能力记录走独立的身份、父回复或日程执行、真实来源与当前授权核验；能力过程不能因此充当正式记忆来源。

恢复器只接受旧格式误判标记，重新通过当前能力凭证核验后，用事务比较标记、行动摘要及 SQLite 写入代数再清除。中间任何数据库写入都会拒绝这次提交，稍后重新核验。恢复留审计凭证，不重放行动、不改正文、不恢复授权。新格式正式撤回、真实来源失效、旧 DSH checkpoint 或暂时读取故障都不会被当作误判直接清除。恢复成功同时推进 Main 的校验版本，避免继续使用旧的隐藏投影。

### 主脑、能力开关与 DSH

提示词明确主脑负责人格判断、接受或拒绝、计划、协调与核验；DSH 是实际任务的主要执行能力。复杂研究、视频理解、文件加工和多步任务优先交给完整 DSH。内置浏览器是显式启用后的轻量查看能力，不能用反复定位、截图拼凑完整视频理解。关闭内置浏览器不会关闭 DSH 执行器自身的工具。开关不创建屏幕或文件授权，也不清空已经存在的人格与合法上下文；宿主既有被动回忆仍独立运行。

### 回忆与回复热路径

普通未筛选的主动回忆现在也使用与被动回忆相同的元数据增量投影。冷态仍从完整获权 canonical 正文建立原版图；暖态保留同一原生排序，仅为实际返回页取正文、文件凭证和来源。返回前同时检查投影序列、撤回代数、重建版本、外部变更代数与实际文件，期间变化则按既有边界重新核验。原版 formatter 来源观测不完整、显式模式或筛选条件不适用时，继续完整核验。原生零命中保留准确空闭包，不为没有输出的查询重新扫描整库。没有删去候选、改变 Rust 算法或将过时正文当作有效缓存。

### 原版保真与原生接线

本轮重新计算全部 129 个 vendor 文件的字节数和 SHA256，全部匹配 manifest。对照源仓 pinned commit 的 Git blob，109 个文本文件仅存在 checkout 的 CRLF/LF 差异，所有文件均无其他文本或二进制差异；Windows 原生 `.node` 与 pinned blob 逐字节相同。这里没有将“可加载原二进制”解释为独立 Rust 可复现构建，也没有修改 vendor。

### 移植增加的成本及必要边界

原版 KBM 在长驻服务中持有 Rust 存储与索引，查询按明确 diary scope 取 SQL 授权文件并复用已加载索引。本仓额外承担多伙伴、私聊/群聊、撤回、真实文件与版本凭证的隔离。旧热路径会在召回前后读取全库 snapshot，将来源递归到行动和文件，再重复 materialize/核验；这些是宿主开销。不能用取消撤回检查、扩大授权或跳过真实文件比对换取速度。正确方向是由存储 revision/撤回屏障维护元数据投影，暖态只同步变化，实际输出与 AIMemo 输入按精确依赖重核；不完整来源、旧 runtime、显式筛选模式保留完整验证回退。

物理索引也有额外启动成本：`runtime.cjs:234` 每次 worker 初始化复制一份 vendor JS/资源，随后恢复 Rust 索引、读 provenance journal；`worker.cjs` 逐 scope 串行处理命令。`memory-view-cache.ts:139` 已能复用稳定 scope，`runtime.cjs:429` 的 replace 只对 fingerprint 改变的记录写入，不能笼统说“每条消息全部重建图”。冷 scope、进程淘汰、授权变化及实际改写仍会产生恢复/摄取。`ensureArtifacts()` 仅在 dirty、缺少 artifact 或空 artifact 与非空 corpus 不一致时等待并请求原版派生发布，不是无条件每轮重建。进一步优化应围绕稳定 scope、增量同步和派生目录隔离，而非改变原算法。

日志 `worldlinebox-20261029T212422.log:8527` 的同次主动来源核验为 15,617.6ms，`:8622` 结果复核为 12,872.2ms；该用户截图同时显示原生查询约 31ms。另一轮日志 `:8910` 的原候选准备为 72.0ms，`:9090` 聚焦为 23,487.7ms，`:9212` 复核为 22,608.5ms（包含等待）。两轮数据不能相加成一次 wall time。它们说明应分别修宿主核验放大和提供商聚焦等待，不能宣称 Rust 本身慢。原生准备时间也不等于纯 Rust 执行时间；聚焦时间还包含实际模型准入、HTTP 和必要的校验。

### 本轮配置纠正与缓存边界

宿主过去强制 `AIMemoBatch=2`、`AIMemoMaxTokensPerBatch=18000`，未发现模型上下文兼容判断或其他有效代码依据；18,000 中还包含上游 10,000 固定开销，可能比原版更早拆成多批并增加合并调用。本轮仅移除这两项宿主 override，沿用 pinned 原 `AIMemoHandler.loadConfig()` 默认五批并行、每批 60,000 估算 token，并同步 behavior 展示。保留全部候选、模板、排序、聚焦与合并算法；受模型准入和提供商限制的真实并发仍以实际执行为准。原本只有一个聚焦组/批次的约 23 秒调用，不会因这个改动自动变快。

### 默认召回与恢复包规模

这次确认的关键移植差异，是宿主每次被动回忆都主动生成 `[[AIMemo=True]]` 和 `::AIMemo+`。本节的修正取代前节“首次被动回忆仍必经模型聚焦”的旧行为：默认被动回忆仍使用原版会话感知 RAG/River、时间策略及完整获权图，返回原格式器实际输出的相关片段；不再占用额外文本生成连接或发送 AIMemo 请求。`retrievalOptions.focus:true` 才选择原版 AIMemo+，没有修改 vendor 的算法、候选排序或模型模板。旧的真实聚焦任务凭证仍按它记录的模型路由恢复，不能偷偷换成另一条算法伪装同一次执行。

普通原生返回的是 chunk，其 hash 不一定等于整篇日记 hash。为此在原格式器实际收到行时捕获 `nativeSources`，与 context reference 的 ID/hash 严格绑定，再比较实际 canonical 源字节是否包含该片段。不会把整篇 hash 伪造为命中片段证明，也不跳过正文检查。已测试片段正确、被改写、错归属、hash 错误、缺少观测和未引用数据的拒绝边界。

恢复包在原生候选准备之后才捕获本次真实文件凭证。完整来源观测可将 `recovery.frozen`、笔记元数据及文件凭证收窄到实际返回/聚焦输入；完整图的 corpus hash 继续保留。未映射或 partial 观测保守保留原闭包。宿主 source closure digest 与收窄后的依赖重新绑定，恢复前仍核验来源、授权、字节和硬撤销。64 篇元数据、实际命中 1 篇的短测试中，持久恢复凭证小于原包的八分之一；这只是受控样例的序列化体积证明，不是当前用户库的性能基准，也不代表消除所有元数据计算。

### 长期索引的生命周期

伙伴拥有稳定的 `owner-v2` 类型视图，消息序号不是每次新建物理索引的 key。`memory.projection.state/page/delta` 以存储的变化序列维护元数据目录；暖态只取变化的描述及实际命中的正文，既有 native fingerprint 仍负责防止相同日记重复摄入。普通聊天不会在每轮重建 Rust 图或重新向量化全部历史。

此次进一步修复跨启动的误判：内存中的 `hasOpenScope=false`、或文件 receipt 缓存未驻留，不再直接要求整个 canonical 日记库重新 materialize。`projection-inspect` 恢复现有持久 scope 后，对账当前获权 SQL 元数据中的正文 hash、规范化注释及 native catalogue/indexed path，拒绝未知记录。只有实际新增、变化、缺失或损坏的条目需要从正式文件重取后增量摄入；删除/失权项在查询前移除。新增的 `contentHash` 只是 SQL UDF 输出的摘要，SQL 正文没有被直接送给模型。实际返回或模型输入再次从正式文件补齐来源/字节证明，先保存这些真实凭证再写恢复包。

| 情况 | 本次处理范围 |
| --- | --- |
| 已驻留、来源未变 | 复用索引，不全库 canonical 读取 |
| 新增/修订一篇 | 只处理该篇增量，再读取实际命中正文 |
| 重启/worker 被回收，磁盘索引完整 | 恢复原 scope，做元数据/派生缓存对账，不重摄取未变更日记 |
| 删除、遗忘或失权 | 查询前移除对应 native 记录；硬撤销仍使旧读取失效 |
| 局部派生缓存损坏 | 对应项回到正式 canonical 文件修复，不从损坏缓存创造正式记忆 |
| 真正首次建立、脏写中断、语义模型/投影不兼容 | 仍需要正确建立或重建；不能为求速度谎称已有可用图 |

冷恢复核验仍有目录、元数据及派生缓存文件扫描成本，会随库规模增加；它不是重新 Embedding 全库，也不是每次检索的全库正文/来源递归校验。主动返回页的独立 context 子图可只对少数返回条目恢复；`replace` 本身也按 native fingerprint 跳过未变化项，不能把方法名等同于重新计算全部向量。本次没有运行万篇/多年数据的真实性能耐久测试，不声称恢复是常数时间。

持久恢复 2 项短测证明完整主图不因重启 `replace`、新增只产生一个正文增量，以及删除不复活；真实 runtime inspector 的受控索引端口与临时缓存文件用例验证局部 raw 文件损坏与未知记录边界。最终复核的主动投影/授权版本两文件 8 项通过（24.22 秒进程、14.62 秒测试体）；runtime catalogue、detached focus、加载/菜单 UI、封面四文件 23 项通过（9.47 秒进程、5.46 秒测试体）。没有真实提供商、真实视频或用户库写入。

回忆 UI 新增独立硬授权 stamp，使用伙伴存在性、撤销代数及外部数据库写入版本；原 corpus stamp 继续表达普通内容变化。有普通新增/索引发布时保留捕获时点及结果，提示可以重新回忆；删除/失权/核验不可用时清除旧内容。它不伪称做了原本没有的全库文件监控。该前后端与真实临时 SQLite 授权短批 3 文件 44 项通过。
