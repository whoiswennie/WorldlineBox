# 伙伴行为事件与原子执行约定

伙伴的行为由宿主的持久状态和领域事件驱动。模型可以提出意图、决定说什么，不能直接改坐标、标记工作成功、跨越房门许可，或用一句文字获得精力、好感和记忆收益。渲染层只表现已经获准的行为；头顶标签、三帧动画和聊天气泡都不是执行凭据。

本项目保持一套当前实现。`revision` 是并发修改检查，时间段锚点是历史时钟换算依据，二者都不是并存的多套业务逻辑。

## 执行边界

唯一状态所有者是 SQLite UtilityProcess。`world-store.ts` 管理身体、坐标、姿态、家具占用、真实路线和生活状态；`life-event-store.ts` 管理概率规则及每个窗口的一次发生；`social-store.ts` 管理正式消息、交流渠道、发件箱和回应链；`work-order-store.ts` 管理工作来源、租约及真实行动。它们共享一个连接，可以在同一个 SQLite 事务内相互调用。

已有实现是这些领域控制器共同执行的持久状态机，不是一个接受任意字符串、自动理解一切行为的通用事件总线。增加新行为必须接入真实准入、资源占用、持续执行和终态处理，不能只增加一个日志 `kind` 和 UI 文案。保存的世界快照负责快速恢复，正式事件负责审计和后续认知；重启不会把多年的事件从头重放。

每次行为推进遵守下面的顺序：

1. 接续到当前已知的世界时刻，恢复物理位置和已有行为。补算债务未清时，不接收新自主机会。
2. 读取当前真实主体、消息来源、许可、规则、实时状态和资源。模型返回后再次读取，不能沿用调用模型前的旧判断。
3. 在 `BEGIN IMMEDIATE` 事务中校验，并同时提交身体状态、路线/占用、领域状态、事件和待执行意图。任一写入失败，整次领域转移回滚。
4. 提交成功后，界面观察新状态；Main 根据持久租约启动外部执行。迟到的进程回包必须通过来源、租约、重置状态和行动身份检查。
5. 只有实际到达、姿态计时结束、消息落库或行动成功，才确认相应完成。开始、排队、正在输入、等待对方允许都不是完成。

`world.begin/end` 先独立接续物理时刻，再用外层 `atomic` 提交工作领域变化；被拒绝的工作请求不会撤销这次已提交的补算，也不会留下半条工作路线或终止事件。其他 `world.tool` 入口当前将必要补算与该次意图一起包在事务中；拒绝意图后，该次尚未提交的补算会在下一次推进重新计算。两种入口都不能只依赖最后一次 `save()` 的内部事务来保证整个领域转移原子性。

## 原子行为与复合行为

原子行为是有清楚前置条件和完成条件的身体转移，例如开始转身、坐下、起身、躺下、醒来、进入稳定姿态，或沿当前真实路径推进到下一段。过渡有开始时刻和结束时刻，不能将播放到第 3 帧等同于已经完成。位置插值、动画帧和每个渲染帧不写入行为日志。

复合行为组织这些原子行为，并持久保存进度：

| 复合行为 | 执行链 | 完成条件与中断 |
| --- | --- | --- |
| 工作 | 真实来源 → 受理/租约 → 寻找可用电脑 → 行走 → 坐稳 → 实际行动 → 结果 → 释放 | 外部工作由对应行动终态证明。暂停、取消和重置必须终止实际进程；不能只改状态标签。 |
| 用手机交流 | 检查身体与工作 → 结束必要姿态 → 输入/阅读 → 正式消息 → 恢复生活 | 工作、用餐、睡眠中的普通消息等待。经过语义核验的紧急来源可以打断；同一来源正在执行的电脑工作不会同时被手机姿态卡住。 |
| 当面交流 | 真实相遇 → 状态/距离/同场景检查 → 暂停可恢复移动 → 有限回应链 → 恢复原生活 | 每次发言前复核全部参与者。任一人离开、开始集中工作或失去交流条件，不能把迟到回包伪装成现场说话。 |
| 拜访 | 真实申请 → 对方允许 → 路线 → 每次过门复核许可 → 在场活动 → 离开 | `allowed` 表示许可，不表示已经进屋。许可过期、撤回或删除联系人后不能穿过旧路径进入。 |
| 公园散步 | 概率机会/真实安排 → `travelling` → `strolling` → `returning` → 结束 | 只有实际在公园内走动才累计世界分钟。去程、手机停步、交谈、工作和回程不计放松。天气、精力、用餐、睡眠或工作变化会结束/中断。 |
| 疲劳恢复 | 实际精力低于门槛 → 持久恢复需求 → 保留高优先级工作/睡眠/用餐/已受理路线 → 前往沙发 → 实际就座 → 占用期间恢复 | 精力 ≤20% 触发，恢复到55%才结束；双阈值迟滞避免边界抖动。休息允许坐着回复手机；前往沙发时消息只短暂等待到就座。 |

疲劳是身体状态约束，不是一个可能抽不中的随机机会。恢复需求、目标家具和路径保存在世界快照中，重启继续同一需求；每个状态边沿只写一次事件，不按渲染帧重复创建恢复。不可达路线最多每30现实秒重新检查一次。其结束条件只读取共享精力积分器计算的真实精力；走到沙发、准备坐下、文字说“休息过”均不会获得恢复收益。

精力积分与物理控制器使用同一已抵达的模拟游标、世界时钟分段和真实家具占用记录。离线推进会在精力触及20%/55%时分段处理，再执行对应状态转移，避免跨过几个小时后才发现需要休息。整个离线推进仍受每批1000个物理边界保护。清醒空档、走路、运动和实际休息采用同一个速率函数，不能在后台以另一套常数重新推算。作息面板的“可以交流”复用实际手机准入：普通消息在集中工作、睡眠和用餐时等待，沙发休息与其他日常活动允许交流；经过核验的紧急来源保留原有有限唤醒窗口。

因果身份应复用已有的持久主体：生活 `occurrence.id`、工作 `workId/order.id`、拜访 `visit.id`、社交 `chainId`。不能在每一帧生成一个新的“行为”身份。姿态原子过渡的独立身份与动作种类、期限一起保存在 actor.transition 中。正式事件的 behavior 字段记录同一 id、kind、started/completed/interrupted、家具目标与可用的父事件身份；期限实际到达后才完成，重复推进不重复启动。

散步发生记录在受理后是 `active`。它表示复合行为已经启动，仍可能处于去程；只有物理控制器完成或中断后才变为 `done/cancelled`。开始概率窗口结束后，已接纳的散步继续按自己的持续时间执行，不因为窗口结束而凭空宣布完成。编辑或移除规则只改变未来机会，已经受理的散步保留当次不可变参数，继续按实际状态执行；新的行动、工作、作息或重置会中断实际散步，并由同一物理事务把发生记录标记为取消，不会只改界面标签。

其他规则的 `done` 需要结合 `result` 理解为这次机会已经分发：拜访可能只是已发出申请，手机消息可能仍在持久发件箱中。其真正许可/发送/回应状态由对应领域控制器持有，不能从生活机会的一个状态推断整段复合活动已完成。

## 资源与冲突

| 资源 | 宿主约束 |
| --- | --- |
| 身体与姿态 | 一个 actor 同时只有一种物理姿态。过渡先完成再开始下一步；坐标来自路径推进，不由动画表现倒推。 |
| 家具 | 电脑和长椅按真实对象 ID 预约；预约、就座和释放一起保存。多张工作单可以共享同一人的集中期，不能让两个人同时获得同一台电脑。 |
| 注意力 | 集中工作、睡眠、用餐优先于普通闲聊；手机与当面交谈不能同时冒领一个伙伴。紧急打断必须保留原来的来源与可恢复进度。 |
| 现场交流 | 所有参与者在同场景、彼此距离允许且当前可交流；每次交付都复核。群聊的真实参与者集合是场景条件的一部分。 |
| 家门许可 | 只允许进入自己的家或当前获准的家；串门不得因模型说“她同意了”而获得许可。 |
| 现实执行权限 | 只有玩家真实授权链可以创建外部 DSH 工作。伙伴委托仅创建内部工作；关系、在同一屋内或使用别人电脑都不授予玩家权限。 |

资源检查散布在对应的领域控制器中，但必须在持久提交前执行，而不是事后用一个“资源占用标签”解释已经发生的冲突。新增通用资源调度器时，需要让现有入口真实调用它，并迁移现有控制职责；只增加没有调用者的类型文件没有约束作用。

## 概率机会、状态相关性和预算

感知也是由同一物理事务执行的原子事件：每位伙伴按真实时间最多每秒观察一次已经抵达的当下，更新自己的有界见闻。它不补造离线期间的视觉经历、不调用模型，也不随观察窗口数增加。环境与当前可见对象由距离、遮挡、清醒和局部光照决定；有意义变化按十秒合并写入历史，最后已发出的签名单独保存，避免被节流的变化永久丢失。偶遇条件读取双方实际可见名单，其他模型入口使用同一感知投影；过去目击事件只能凭当时记录的观察者身份读取。详细契约见[伙伴感知与有界认知](companion-perception.md)。

生活事件采用累计风险量的非齐次泊松时钟。窗口总基础机会是 `p`，窗口长度是 `T`，基础率为 `λ₀ = -ln(1-p)/T`；窗口创建时，以持久种子生成一次阈值 `θ = -ln(U)`。推进时只累计 `H += λ₀ × m(state) × Δt`，当 `H ≥ θ` 且当前条件允许时进入待执行状态。`m` 有上下界，不可用时为 0；机会不随刷新次数、窗口数量或渲染帧率增加。

`m(state)` 使用实际精力、PAD 情绪、表达倾向、热舒适度、关系和对象是否可用。散步还要求户外天气、温度及精力达到可参与条件；中等调节需求可以提高意愿，疲惫和不适合户外的天气会抑制机会。未知的长离线间隔不假设中间一直可用，因此不补发一串虚构的社交消息。

未指定朋友时，用指数竞赛选择目标：对每位候选计算 `-ln(Uᵢ)/wᵢ`，按与实际关系相关的权重选最小者。这样是按权重采样，不是把随机数放进排序比较器，也不会把所有自主事件默认指向玩家。

现场相遇复用同一个累计风险算法，而不是每一帧掷骰子。当前实现只观察真的处于同场景、距离允许、可停步的伙伴对；短时连续在场才累计，离开就停止这次机会。再次发生受到现实时间和世界时间两种冷却限制。两人相遇可以组成最多 4 人的当面小组，全部成员必须两两满足现场条件。

冷却与预算是不同限制：冷却避免短期反复打断，世界日预算限制自主发起和回应总量，有限链长限制一个话题无休止自言自语。当前社交预算是每伙伴每天自主发起最多 2 次、回复最多 8 次，单链最多 4 条；玩家明确委托的后续汇报按其来源链处理，不能因“主动闲聊关闭”而丢失已经答应的汇报。预算、阈值、已用次数和租约均持久化，不能在重启时重置运气。

## 效果、证据与恢复

环境、休息和交流带来的状态效果由已提交的实际事件触发。`world-effects-through` 水位只在按序应用后推进，避免重复奖励。模型基于交流内容评价关系时，还需要实际消息来源和每日变化预算；忘记来源后撤回依赖，不能靠复制事件文字继续保留旧效果。

重启恢复路线、位置、散步阶段、占用时间段及已提交消息。离线物理生活可以补算；已停止的进程没有在离线期间执行外部任务，因此不能填造工作结果。失效租约、取消或重置后的迟到结果必须拒绝。界面只分页读取消息、事件和历史记录，不把多年记录复制进实时世界热状态。

## 验收依据

`tests/worker/companion-world-atomic-events.test.ts` 使用真实 SQLite，并在最终持久写入处注入失败，检查工作开始/结束产生的事件、actor JSON、家具占用、工作记录一起回滚；清除故障后的重试只产生一条有效转移。另一项测试在散步过程中请求不存在的目的地，证明准入失败不会取消旧散步，也不会留下虚假的“散步被中断”事件。

`companion-park-walk.test.ts` 检查真实步行参与、手机暂停、天气/作息/工作中断、重启恢复及返回家中；`companion-social-store.test.ts`、`companion-encounter.test.ts` 检查正式私聊/群聊、现场条件、有限回应链及冷却；`companion-work-order.test.ts` 检查真实工作来源、进程生命周期与幂等。验收还需要真实窗口中查看角色动作、位置和头顶状态，不能只以事件条数或 UI 文案证明语义正确。


## 持久行动任务与空间记忆（2026-10-16）

`activity` 是主脑可调用的持续任务能力，`start` 保存自然语言目标，`list/cancel` 查询或停止。玩家聊天的主循环提交目标后可以结束回复；任务由 `CompanionActivityTaskService` 独立调度，不依赖下一条玩家消息。世界自主决策可返回 `task:{title,goal}`，概率拜访事件也创建同一类任务。日历新增 `kind=activity`，与提醒、DSH现实工作分开。

每一步是模型对当前目标、本人有限感知、空间记忆、最近伙伴消息与已提交回执的决策。模型选择一个原子 `world` 行为或等待条件，并判断继续、完成或受阻。宿主不写死“问地址→寻路→进屋”的拜访脚本。模型上下文只保留最近12步回执与最近20条伙伴消息，每条正文最多2000字符，明确标注截断，不把任意长社交历史塞入每轮。输入来源在规划前、实际提交时重新校验，遗忘或修改的来源不能继续驱动行为。

SQLite 单一权威连接保存 `companion_activity_tasks`；领取有120秒租约，每步最多3次模型故障重试。世界副作用、发件意图和步骤回执在同一个事务提交；模型推理阶段没有副作用。崩溃后恢复未提交的规划，已经提交的步骤不重放；幂等clientId绑定主体、会话、来源和完整目标。跨重启的等待保留原始条件。任务最多32步、1现实小时，每伙伴同时最多3份并按创建顺序推进；后台最多2个规划调用。自主目标每天最多2次，并有6世界小时及120现实秒冷却。连续三次同一原子失败、空循环、超限和撤回都会停止，而非无限请求模型。

等待条件是抵达、真实伙伴新回复、许可结果或世界时间延迟。调度器查询索引和物理状态，等待期间不请求模型；抵达必须检查实际场景、终点距离和路线已结束，新回复必须是真实作者且序号大于发件前游标。最长等待5现实分钟，超时唤醒模型重新判断，而非伪造完成。工作、用餐、睡眠、存档补算会暂缓规划。取消停止后续步骤和本任务仍持有的路线，保留当前位置；新工作或手动移动接管的路线不会被旧任务取消。模型迟到结果不能越过取消、重置或来源校验。完成/受阻会以固定消息标识向原玩家会话主动汇报，行动态可在右栏“行动任务”展开。

`homeMemory` 是本人的住宅静态布局记忆，不含远程家具占用。`knownAddresses` 是独立空间记忆：本人住宅自动持久记住；联系人目录只有名字和ID，不授予他人的家庭坐标。`share_address` 或实际伙伴回复的 `shareAddress=true` 只分享房主本人地址；正式消息真正送达后才写入各收件人的 `companion_world_addresses`，绑定来源消息与会话。待发、许可、模型猜测不产生地址记忆；来源被遗忘或住宅地址改变后，旧地址不可导航。

`navigate` 使用已知的门口坐标执行寻路，终点在街区，不请求许可、不进屋；`visit` 只申请许可，不移动；`respond` 只更新房主允许/拒绝；`enter` 是新的明确决策，必须实际抵达门口且许可有效。允许拜访不再自动把客人拉进屋。`move` 不能绕过 `enter` 进入他人住宅，也不能按猜测ID定位未知住户。到门口后可以选择离开，现场交流仍复用正式私聊/群聊。

验证使用真实SQLite、真实世界物理及真实provider适配层配合明确的离线模型协议fixture，覆盖连续规划、等待不轮询模型、重启、主动回报、原子重试、拒绝/取消、遗忘和日程关联；这验证调度与协议，不把fixture当作真实模型长期行为质量评估。
