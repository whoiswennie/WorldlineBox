# 伙伴主脑与后台 DSH

目标：DSH 是有持久身份的后台执行会话。主脑提交任务即取得句柄，不等待执行结束；用户的新输入仅进入主脑。主脑根据新要求主动选择转达、取消、观察或继续等待。DSH 的阶段报告、求助和最终结果通过任务所属邮箱返回，不复制到无关会话或直接作为用户授权。

参考源码：`deepseek-harness/docs/subsystems/subagent.md`、`packages/jobs/tool-jobs/src/index.ts`、`packages/jobs/tool-jobs/tests/steer-wait.spec.ts`。DSH 将独立执行、消息接受、可中断等待和完成通知分别管理；等待被新输入唤醒不等于取消后台生产者。

公开参考：[OpenAI 多代理](https://developers.openai.com/api/docs/guides/agents-api/multi-agent)、[Codex 子代理](https://learn.chatgpt.com/docs/agent-configuration/subagents)。借鉴独立上下文、显式发送和等待机制，不依赖未公开的 ChatGPT 内部实现。

## 实现与验收清单

- [x] `dsh.run` 返回后台任务句柄；同一伙伴在不同入口的任务彼此隔离。
- [x] `dsh.send` 仅投递主脑主动组织的消息，持久记录并按调用身份去重。用户原文不自动广播。
- [x] DSH 提供 `report_to_parent`，用于重要阶段、阻碍、需决策事项；主脑提供任务相关回传条件。`wait_for_parent` 允许执行器暂停等待主脑决定。
- [x] 任务邮箱保存方向、归属与序号；语义正文只包含业务内容。报告不等于已核实的执行效果。
- [x] `dsh.wait` 等待未读报告或结束；用户新输入唤醒，不中断子任务，不消耗空转推理。处理到的序号在工具回执中持久化。
- [x] 用户停止、子任务停止、失败、恢复、关闭与重启有明确状态；已执行任务不重复启动。
- [x] 长任务上下文按实际压力压缩，保持最新输入、活动句柄、未决事项、完整调用/结果配对；原始步骤可回查。
- [x] 验证主脑在子任务未完成时响应用户，主动转达修改，收到阶段汇报后再干预，等待后完成。
- [x] 使用实际安装的 DSH Host 与本地可控模型验证双向通道和原会话续接。
- [x] 验证同一角色同时处理用户私聊、获权的伙伴委派任务及群聊；用户引导只作用于对应私聊。
- [x] 验证两个委派目标同入口不同主脑消息的隔离，取消一个目标不影响另一个目标和群聊。
- [x] 实际 DSH 工作区按伙伴名称分组；Host 重启后续接原会话，保留上下文、工作目录和原工作区 ID。
- [x] 验证邮箱分页、事件环形缓冲溢出和重启后的完整报告回放。
- [x] 真实模型通过后台工作单、定时任务和带中途确认的网页交付验收。
- [x] 完成最终相关回归、类型检查及改动文件的ESLint检查。

所有运行验证使用隔离的测试资料，不修改用户当前伙伴数据，不操控桌面。

## 协议与恢复

`dsh.run` 返回 actionId。主脑用 `status` 读取状态及信件，用 `send` 发送自己组织的必要指令，用 `wait` 等待指定句柄，用 `cancel` 停止指定子任务。信件按伙伴、会话和主脑消息共同归属，持久序号用于渐进读取；每页最多50条，并限制总字符量，完整长信件不被拆断。读取后的 nextAfter 应传入后续等待，避免反复消费旧报告。

`report_to_parent` 只向所属主脑回传重要进度、检查点或问题。执行器确实依赖主脑决定时可调用 `wait_for_parent`，无需空转请求模型。主脑等待被用户输入唤醒时，用户原文仍只属于主脑；转达内容由主脑自己选择。普通工具模式与PTC模式使用同一通信合同，通信工具注册在单个执行Agent的作用域。

任务邮箱独立于聊天与语义记忆；内部序号、归属、投递去重键服务于调度与审计，不作为自然语言记忆正文。模型只把子任务报告视为执行资料，完成状态仍要求真实回执与交付核验。持久执行记录可在事件缓冲溢出或重启后分页回放，长报告完整续读后才进入邮箱，终态前先排空积压事件。

伙伴只能选择托管工作目录。原生Session的cwd固定在本人工作区根目录，因此所有任务归入以当前伙伴名字命名的同一DSH组；独立调用拥有各自的产物目录和Session。已有项目路径写入任务输入，不另建工作区组，也不扩大文件权限。继续旧会话须使用原收据中的resumeTaskId；宿主重新核验角色、会话、来源和执行资料，保留Session及其目录、工具模式和选择。

显式停止与用户引导分别处理。重试先等待旧执行收尾，再恢复原子任务；已成功的并行任务直接复用。日程取消立即撤销发生期租约，迟到回调不能覆盖取消结果。主脑不能在子任务仍运行时以最终答复丢弃目标；缺少显式wait时宿主也会停在可唤醒等待状态。

并发受已有的伙伴任务预算约束，默认额度为3；超额来信保留并排队，不通过无限增加Agent数量来处理。加严用例先让用户私聊、伙伴委派和用户群聊的三个DSH任务同时运行，再将额度设为4，额外处理一次伙伴群聊回复。私聊更正只发送到用户网页任务；群聊任务和委派任务继续运行，随后分别完成，未重复启动任务。

长循环沿用来源绑定的工作摘要，按实际窗口压力或提供商容量错误压缩完整旧步骤，保留原始调用、签名和回执以供回查。当前角色、授权、活动句柄和未读后台报告在每次推理中重新装配，位于旧步骤摘要之外。摘要不创造授权，不把未验证报告变成完成事实。

## 2026-10-28 阶段证据

`companion-dsh-parent-channel-native.test.ts` 使用实际安装的 DSH Host 和本地可控模型，分别运行普通模式与PTC模式：执行器回传检查点后调用 `wait_for_parent`，未收到主脑消息前不新增模型请求；收到定向更正后继续，重启 Host 再通过原 task 回执续接，原检查点与更正出现在原 Session 上下文，工作区 ID、Session ID 和任务目录保持一致。普通模式额外选择空的常规工具列表，确认专属通信工具仍可用。与 `dsh-guidance-grouping-native.test.ts`、`dsh-companion-workspace-native.test.ts` 合计4项通过，报告为 `.tools/test-output/companion-background-native.json`。

`companion-background-mailbox.test.ts` 的6项验证覆盖等待被用户引导唤醒、原文不广播、显式发送、去重与游标读取、跨入口拒绝、删除级联清理、订阅竞态、混合结束状态、分页边界和压缩后保留检查点。与14项循环压缩测试合计20项通过。`dsh-task-broker.test.ts` 额外验证超过1000条事件后报告仍可完整读取，重启后序号连续且没有重复。

`companion-service.test.ts`、`companion-schedule-state.test.ts` 和 `dsh-task-broker.test.ts` 的完整回归合计190项通过，报告为 `.tools/test-output/companion-background-service.json`。另73项能力、调用协议、执行证据、交付、状态UI和压缩相关回归通过，报告为 `.tools/test-output/companion-background-regression.json`。并发断言使用受控模型与原生回执，验证隔离和生命周期，不据此声称真实模型永远正确。

最后的工作区约束回归还确认伙伴schema拒绝 `workspace.existing`，普通DSH启动器仍支持用户明确选择的项目目录；执行入口也拒绝伙伴绕过托管目录。与代理记录回放合计19项通过，报告为 `.tools/test-output/companion-background-workspace-final.json`。
