# 内置伙伴的完整重置

内置联系人不能删除。`companion.reset {id,scope:'all',expectedRevision?}` 启动完整重置；`companion.reset.status {id}` 与 `state.resetJobs` 返回同一个持久任务的状态。当前只提供完整重置，自定义联系人继续使用移除操作。资料恢复必须有对应的内置 seed，不能把自定义联系人当前设定冒充出厂设定。

## 立即生效的屏障

开始事务记录当前消息序号上限，保存仍在运行的外部任务 ID，并恢复该伙伴的默认姓名、签名、人设、头像、三视图和全局模型连接选择，保留联系人 ID 和最初创建时间。重置期间禁止该伙伴继续回复或写回结果；失败状态也保留屏障。完成后，永久消息水位继续拒绝旧来源的工作、记忆候选与上下文，不能因重新入群而重新提取过去的内容。

第一阶段为 `stopping`。Main 中止回复、后台记忆、世界和日程作业，取消并确认外部执行任务，清除专属凭据，并等待已经启动的原生文件读取/快照调用结束。只有内部 `companion.reset.cleanup {id,jobId}` 确认后，Worker 才能删除数据。取消或凭据清理失败通过 `companion.reset.cleanup-failed` 保存错误；再次重置重试同一个任务。外部任务 ID 只经内部响应返回，不在公开 IPC 中暴露。

自定义联系人的删除也先经过同一个拥有者停止流程：阻止新回复和任务，停止后台作业，等待启动中的行动与文件调用，确认相关执行进程退出后才移除联系人。取消状态只表示请求或日志状态，不能代替 `task.terminate` 对真实 Job 清空的确认。

内部 `companion.task-ids` 按拥有者读取全部已登记执行任务，不依赖前端的最近任务页。`companion.task.track` 只允许给既存且拥有者匹配的行动补登记执行 ID；若启动回包恰逢 `stopping`，在同一事务追加到持久取消清单。它不恢复行动状态或正文，SQL 清理开始后拒绝补登记。DSH 的 `task.cancel` 只发出中止请求；`task.terminate` 必须等待该任务所属 Windows Job 的进程数归零、任务收尾与 pin 释放。终止确认失败会保留所属进程清理句柄供重试，不按裸 PID 或进程名称结束其他任务。

## 数据边界

- 该伙伴的玩家私聊和双人伙伴私聊清空全部消息。由这些来源支持的其他伙伴记忆会失效；不删除其他伙伴的无关记忆。
- 玩家混合群聊保留其他作者的消息，重置的伙伴退出群聊；该伙伴自己的旧发言移除。
- 三人及以上的纯伙伴群保留原始成员集合和唯一群身份，仅移除重置伙伴自己的发言。其他作者的历史仍可由观察者阅读；重置伙伴通过永久水位隔离全部旧来源，后续新消息可以正常成为证据。
- 该伙伴的记忆、提取队列、遗忘规则、工作队列、行动、日程、连续状态、用户关系、作息、习惯进度、世界个人状态、拜访和涉及它的伙伴关系记录清理。世界的全局时钟、地图与其他住户不重建；正在其家中做客的伙伴按实际路线离开。
- 指向被删消息的跨消息引用先解除，保留另一条消息正文。记忆依赖先失效再移除边，避免分批清理间出现没有来源却仍有效的记忆。
- 仅回收已经没有消息、公开资料或其他持久文件结果引用的管理副本。原文件路径附件永不删除源文件；清理附件登记后，旧附件 ID 不再可读。文件删除队列本身持久化，崩溃后可继续。

重置不会撤销此前电脑任务已经实际产生的文件修改或外部副作用。它也不清空其他伙伴独立保存的经历，只撤回依赖已删除来源的部分。

## 分批与恢复

`reset-store.ts` 使用 UtilityProcess 现有的唯一 SQLite 连接。每批最多处理 300 个数据 ID 或引用行，空阶段在最多 5 ms 的预算内连续跳过，Worker 通过 `setImmediate` 在批次间让出事件循环。进度通知通常按 250 ms 节流，最终状态始终通知；`processed` 是处理过的行、引用和文件数量，不是完成百分比。

删除顺序涵盖房间分类、记忆与依赖、各领域所属记录、循环及文件结果、消息引用、正式消息、行动、派生失效、附件和文件。任务、游标、300-ID 暂存集及永久水位都保存在 SQLite。启动恢复未完成的 SQL 阶段；`stopping` 阶段由 Main 重新完成取消确认。任何阶段失败均保留当前任务与水位，再次重置从当前阶段继续。

索引准备先检查既有索引的首列，复用可满足查询的普通索引，只补缺失的拥有者、外键和 JSON 表达式索引。不逐条经 Renderer 发删除请求，也不把整个多年存档放进一个事务。

## 验证证据

`tests/worker/companion-reset.test.ts` 使用隔离临时 SQLite，覆盖不可删除规则、默认资料恢复、停止确认及失败重试、旧作业拒绝、共享来源失效、两类混合群边界、附件引用与源文件保护，以及中途关闭重开后续删。

合成压力数据包含 100,000 条消息和 100,000 条带来源记忆。完整实测数字单独记录在 `artifacts/companions/verified-companion-reset-pressure.json`；原生界面验收使用 `verified-companion-reset.json`，两者互不覆盖。压力报告保留启动时间、批次数、总耗时、p95、p99 与最大停顿所在阶段，不把批次预算误写成硬实时保证。该测试没有启动 Renderer 或 GPU，也没有读取真实用户存档。

2026-10-15 分离报告后的实测：启动事务 8.59 ms，2,010 批共 11.08 秒，中途关闭重开后继续完成；批次 p95 为 13.46 ms、p99 为 54.03 ms，最大批次 393.07 ms，发生在消息引用阶段折叠到批删除与全文索引维护的调用中。
