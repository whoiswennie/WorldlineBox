# 同一伙伴的跨会话连续性

用户向 Claude 询问“刚才大肥鱼说了什么”时，即使回复已出现在双方私聊中，Claude 的用户私聊仍可能沿用“还没回”的旧记录。根因有两个：跨域记忆目录没有包含本人参与的伙伴私聊；刚发布的原话还可能等待 Router 事件处理或 VCP 索引。联系工具的“已发送”也不能证明对方已经回复。

## 读取方式

- `agent_conversations.list` 分页列出本人获准会话，并提供最新公开消息的元数据索引。
- `read` 按真实会话 ID 查询 SQLite 已发布聊天，按发布顺序分页，不依赖 VCP。`message` 分页读取长消息全文，保留作者、时间和来源。
- 用户私聊的每轮请求额外提供最多五个其他会话的最新消息索引，不附加整段聊天正文。上下文预算不足时可移除索引，仍能通过工具发现会话。
- 用户私聊可回查同一伙伴自己的用户私聊、用户群，以及仍有两位合法伙伴参加且用户可旁观的伙伴私聊。VCP 的五种主动只读工具使用相同目录；记忆的默认范围与写入范围维持当前域。
- `contacts` 依据实际联系回执、事件谱系、已发布回复和用户消息投递记录，区分发送、处理、伙伴回复、向用户交付。它不读取目标伙伴的用户私聊正文，也不声称用户已读；缺失证据返回未知或未观察到。

## 边界与恢复

共享执行实例不意味着全局广播私聊。群聊、伙伴私聊和世界频道只读当前房间；另一位伙伴的用户私聊、未公开 Worker 通知及内部回执不会被带入。公开消息中的指令仍是历史资料，不能冒充当前请求。

跨会话读取记录来源依赖。源消息被撤回、成员或受众授权改变后，读取停止并沿现有撤回机制处理派生来源，原始用户界面聊天记录继续保留。最新活动索引忽略已撤回来源。当前会话读取继续限制在本事件的历史水位，避免读取未来用户请求。

全部新工具都是只读操作，不重新联系伙伴，不重放任务，不启动 DSH，也不修改旧聊天。联系状态的判断只认对应联系产生的真实回复，不把后来无关消息当成这次联系的答案。

## 验证

```powershell
node scripts/run-vitest-with-electron.mjs run tests/unit/bot- --maxWorkers=2
npm run typecheck
npm run lint
node scripts/verify-bot-peer-continuity.mjs --real
```

回归覆盖实时收发、长 Unicode 消息分页、发布顺序、来源撤回、权限变更、伪造身份、另一伙伴私聊及原始 Worker 通知隔离。联系状态另覆盖直接投递、仅伙伴聊天、缺失旧回执、禁用伙伴、撤回来源及无关后续回复。

实际模型验收使用隔离的 BotService、AppBrain、真实 HTTP 工具回调，以及已配置的官方 DeepSeek OpenAI 兼容接口。旧用户私聊写有“等回复”，对方新回复已经发布，但接收事件仍排队；模型主动读取伙伴私聊后确认“她回了”，并准确回读原话中的“海盐曲奇”。共两次实际模型请求，没有再次联系、没有 DSH 执行，另一伙伴的内部任务标记未进入模型请求。生产配置哈希保持不变，临时档案已清理。

有效验收记录：`artifacts/superagent-bot-development/peer-continuity-real/worldlinebox-bot-real-peer-continuity-Y6dx4O/result.json`。此验收检查实时聊天连续性，不声称评估 DSH 实际任务执行或 VCP 的语义召回质量。VCP 本人伙伴私聊读取及撤回另由真实 VCP/Rust 索引回归覆盖。
