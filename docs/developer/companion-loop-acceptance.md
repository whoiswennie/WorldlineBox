## 真实执行与自动化的边界

十章写作、修订和时间查询使用应用已保存的全局 DeepSeek 连接、真实 DSH CLI 与已安装官方 0.2.1-alpha.2 SDK。角色主脑只有 dsh 工具，任务内文件读取、PowerShell、写入与编辑来自原生 agent。测试者只建立共同任务说明并汇编完成的章节，没有代写章节正文。

首稿达到了文件数量、作者分工和长度要求，但小肥鱼把 2056 写成 2063，且后五章与第05章会议时间不一致。随后通过真实完整任务要求她阅读全部十章，仅修订自己的五章并更新验收报告。年份和会议时间已修正；01–05 的前后 SHA-256 一致，证明未修改姐姐章节。

这次修订约 583 秒，包含较多细粒度编辑，说明持续执行与错误修正已通，但规划和编辑效率仍有优化空间。小说不等于经过专业出版编辑：班次口径、早年人物年龄和部分信件描述仍有细节张力，报告已保留，不将模型的「全部通过」直接当作文学一致性证明。

早期真实测试还暴露了原生 setup 回调必须返回 void，以及同一实例并发准备 CLI profile 的竞争；已分别修复，再完整重跑两角色并发验收。

任务历史在 SQLite 按创建时间和 ID 倒序游标分页，按角色筛选。125 条真实数据库记录覆盖多页完整性、最近100条之外的直接详情、角色隔离与重启。桌面端用45条离线 fixture 验证20条一页、上一/下一页、角色计数、毫秒时间、时区和过程内容。时间保存 UTC，按本机时区显示；旧记录不伪造缺失的开始时间。

当前进度窗口保留每任务最近150个合并事件，Broker保留最多1000个事件；原生完整 session 由 DSH 保存。应用退出会中断正在运行任务，不自动重放外部影响。运行权限是启动时固定的 Launcher 统一配置，默认完全访问。
