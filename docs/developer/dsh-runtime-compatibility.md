# DSH 运行制品的隔离兼容性检测

共享资格不再由发行版本号决定。`RuntimeCompatibility` 为实际安装的、已封存的制品运行同一套原生能力检测；报告绑定 `runtimeId`、完整 `contentSha256` 和检测代码摘要。制品变化或检测逻辑变化后，旧报告不能继续授权共享。

## 生命周期与数据边界

安装、下载和本地导入注册制品后自动检测。已有安装在启动时补齐当前检测证据；失败或中断的报告保留，用户可以在运行版本页重试，避免无限自动重试。报告逐项更新到受管 `compatibility/<runtimeId>.json`，通过 IPC 显示。

检测只收到只读制品目录和新建 `compatibility-scratch/probe-*` 临时目录。每个原生 Host 使用独立 HOME、DSH_HOME、DSH_AGENTS_HOME、工作区及凭据文件，环境仅保留必需的系统路径和隔离变量。所有密钥、账号授权、模型端点和内容均为合成数据；不会复制用户的会话、密钥、Cookie 或插件，不调用真实模型或登录账号。

这是受控原生程序的独立数据检测，不是操作系统级恶意程序沙箱。程序来源、安装包 SRI 和全部运行文件封存仍由原有安装器负责；测试前再次校验候选和交叉检测制品的全部文件。

## 实际检查

| 检查 | 判断依据 |
| --- | --- |
| 文件完整性 | 所有文件和封存摘要一致 |
| 原生接口 | 通过正式技术路由启动真实 Web Host，包含私有技能和工作区适配 |
| 会话读回 | 原生创建、改名、写盘、正常关闭，再由新 Host 读取；观察不得激活 Agent |
| 写入锁 | 独立进程持锁时拒绝另一写入者，文件摘要不变；释放后可再次写入 |
| 工作区 | 真实工作区发现外部会话、关联和标题投影 |
| 附件 | 原生附件服务写入并无损读取合成内容 |
| 凭据 | 原生 Host 保存及解析假 API Key、读取共享凭据文件，检查账号记录格式与原子写入 |
| 模型配置 | 原生设置 RPC、临时共享配置和另外实例之间同步合成提供商 |
| CLI | 正式 Web / headless 组合运行 `--help` 并退出，不开启第二个工作台 |
| 交叉检测 | 与已通过当前检测的安装制品逐一双向读取会话、附件、凭据和模型配置，并交叉验证写入锁；只有一个制品时仍使用多个独立实例 |
| 清理 | 终止所有受管检测进程后清理临时文件；进程无法回收时不授予共享资格 |

检测按依赖顺序执行，前置失败会把后续项目标为未执行，而不是伪装成通过。错误、取消、超时、应用退出和临时清理失败均保留可解释的状态。每次检测有总时限，原生启动、RPC 和外部会话发现各有独立时限。

UI 只把全部必需检查通过的制品标记为「可共享存档」。新建共享实例、实际共享路由和外部 CLI 都检查相同证据；独立存档可继续使用。伙伴任务的原生能力接入也检查同一证据，不能仅凭一个新的版本名称绕过。

## 删除和清理

界面与主进程共用 `runtimeReferences`，展示实例、快照、整合包和运行任务引用。删除或缓存清理期间阻止新的安装、检测和实例变更，避免引用检查与实际移除之间的竞态。

删除先将完整目录重命名进 `runtime-trash`，再提交安装索引。索引提交失败时恢复；进程在提交前崩溃，启动会找回仍登记的完整制品。提交后剩余垃圾不参与启动扫描，不会把删除的版本重新注册。Windows 占用造成物理清理失败时，界面说明可以重试清理缓存。

缓存清理只覆盖运行版本拥有的安装包、暂存、隔离和删除残留、检测临时目录，拒绝链接。不会遍历或删除实例、共享存档、快照、整合包和用户原始安装来源。缓存中不符合受管命名的文件保留。

## 工作台浏览器适配

原生网页仍运行在关闭 Node、开启上下文隔离与沙箱的窗口中。仅本地工作台主文档获得剪贴板写入权限，不开放任意网页的剪贴板读取权限。

网页登录支持先打开空白页、异步取得 PKCE 地址后跳转的原生流程。每个工作台只允许一个隐藏空白占位窗口，有超时和父窗口退出清理；授权 HTTPS 导航交给系统浏览器，远程页面不会加载进工作台的本地权限上下文。普通 HTTPS 链接同样可交给系统浏览器打开。

## 验收范围

alpha.3 的主动 API Key 弹窗存在可复现的原生 UI 缺陷：`explicit=true` 时凭据保存成功，但 `finishCredential` 只刷新模型列表，没有调用 onboarding 的 `complete`。自动首次引导不受此分支影响。启动器检查实际客户端代码，在实例私有目录生成一个原生 Client 插件，通过公开 Slot 优先级包装原生编辑器，仅在主动编辑的凭据保存成功后完成该步骤。原生表单、校验、失败信息、RPC 和持久化继续由 DSH 负责；不修改封存 SDK 文件，不模拟按键或匹配 DOM 文案，也不按版本号匹配。上游实现已经修正时不加载该插件。

认证端到端回归同时覆盖首次自动弹窗和从账号菜单重新打开的弹窗。为离线进入后一流程，只模拟账号授权初始化失败；两次密钥保存与后续模型请求均使用真实 Host，重启后验证请求携带的是第二次保存的假密钥。

原生回归使用本地安装的官方 npm 制品：0.2.0-rc.2、0.2.1-alpha.2、0.2.1-alpha.3。三者均执行完整隔离检测并双向互读；写入锁通过完整原生 Host 持有，不依赖某个发布版本的内部类导出。

`tests/e2e/dsh-native-auth.test.ts` 从完整启动器导入官方 alpha.3，在原生引导弹窗输入假密钥、点击「保存并继续」、检查模型可选、停止并重新启动，再由真实会话向本机假 HTTP 服务发起请求。服务只比较请求携带的假密钥并返回预设 401，不调用线上模型；这个测试证明本地保存、重启读取和模型请求凭据路由，不能证明真实账号授权或真实密钥的服务端有效性。`dsh-workbench-browser.test.ts` 检查真实沙箱窗口的空白页异步授权跳转和剪贴板写权限，保持用户原有剪贴板内容。

界面管理验收覆盖详细失败报告、未通过时禁用共享、引用阻止删除、缓存清理与共享存档保留，并检查明暗主题。删除恢复回归覆盖索引提交前中断恢复、提交后不复活，以及不删除用户存档与未知缓存文件。以上测试均使用独立临时用户目录。

## CLI 启动与版本管理

### 原生配置与聊天模型独立

伙伴聊天使用世界线盒子的全局或联系人模型设置，任务执行使用当前所选 DSH 实例自己的配置。这两个连接不存在同步关系。任务入口只接受输入、工具接入、权限及恢复信息；不再提供模型、提供方、API 地址或 API Key 覆盖入口。已删除原有的连接注入模块、临时密钥环境变量和模型路由补丁。正在执行的任务固定实例，之后切换只影响新任务；恢复沿用原任务的实例与会话。

原生 headless bundle 默认关闭凭据、授权和账号服务，面向只使用启动环境变量的独立一次性 CLI。世界线盒子调用的是用户已经配置好的 Web profile，因此 CLI 模式保留该 profile 的 `credentials`、`authorization` 与 `deepseek-account` 服务，继续使用原生文件、锁和令牌刷新逻辑。只关闭 Web 传输与浏览器服务，不复制密钥到环境，不改模型配置。独立存档使用自身配置；DSH 的共享存档仍由 DSH 启动器管理，与应用全局聊天设置无关。

### 检测与错误显示

隔离检测从安装制品的官方 CLI 进入，通过仅存在于临时 profile 的插件观察原生会话接口。不能先直接导入 `runProfile` 再挂载配置编辑器：部分制品的原生模块解析会因此出现两份 app-boot 单例，导致原本正常的配置接口报告「profile reload requires the root Include entry」。alpha.4 已通过官方入口与错误入口的对照复现；修正后本机 alpha.2、alpha.4 均通过全部检测及双向存档检查。

已知的兼容性失败在完整文件扫描前返回，不让任务先等待无意义的校验。准备过程分别显示读取实例配置、校验运行文件、沿用实例配置、绑定任务。受控的失败原因写入操作记录和伙伴进度；未知原始异常及 stderr 不直接进入聊天，以免泄露凭据。尚未创建执行进程的失败显示「尚未进入执行阶段」，不再称为旧记录缺失。

### 重新打开工作台

实例运行时提供「打开 / 返回工作台」，关闭窗口后仍可重新进入，并保留同一 Host 的 PID、端口和浏览器分区。窗口打开请求合并，避免双击创建多个窗口；打开窗口不受其他界面操作的全局等待状态阻塞。「停止实例」负责结束后台服务，关闭窗口只关闭界面。

浏览实例详情不会自动切换 CLI，也不会触发后台环境准备；只有明确切换 CLI、打开终端或执行任务时才准备对应实例。准备提示只显示在对应实例页面，侧栏状态同样按实例 ID 绑定，消息带具体 DSH 版本，避免同名实例混淆。

旧路径在主进程校验后，独立 CLI 还会同步读取并哈希全部运行文件、再次遍历目录。正式 npm 制品约有六万多个文件，这部分开销发生在原生 CLI 启动之前。现在完整性服务在首次校验后，在递归变更监听有效期间复用结果；监听错误、文件增删改或制品目录替换使其失效。重启后按完整清单核对大小、修改时间、变更时间和文件身份，只重算改变文件的 SHA；缓存中的 SHA 必须对应封存清单，失败不更新缓存。手动「校验」忽略缓存、完整读取全部文件。

独立 CLI 通过随机令牌保护的本机校验服务请求同一制品校验结果，不启动 Harness Host 或 WebUI；启动器退出后仍可运行，退回原有独立完整校验。实例路径、制品摘要、兼容性凭据、固定任务上下文、共享数据占用保护和 Windows Job 进程树管理继续生效。一个调用取消不会中断其他任务共用的校验。

版本页默认展示已安装制品及总占用，下载目录与本地导入分标签展示。每个已安装制品分别校验和删除，并列出阻止删除的实例、快照、整合包或任务；下载目录可返回已安装版本管理。顶部不再提供全局「清理下载缓存」按钮。删除正常完成时一并移除其校验缓存及不再共用的下载源文件。

2026-10-16 本机官方 alpha.3 基准（Node 24.15.0，63,699 个文件、828,942,919 字节）：无缓存完整校验 126.9 秒；结束进程后重新创建服务，读取元数据缓存校验 1.83 秒；同进程无变更校验 0.07 毫秒；独立实例 CLI 准备 41 毫秒、再次准备 23 毫秒；通过正式命令入口执行 `--version` 0.95–1.08 秒。基准没有启动 WebUI；不包含模型、联网或具体工作耗时。首次建立索引或手动全量校验仍有完整读取成本，不把该成本隐藏成原生 CLI 启动耗时。
