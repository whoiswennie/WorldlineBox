# DSH 运行制品的隔离兼容性检测

共享资格不再由发行版本号决定。`RuntimeCompatibility` 为实际安装的、已封存的制品运行同一套原生能力检测；报告绑定 `runtimeId`、完整 `contentSha256` 和检测代码摘要。制品变化或检测逻辑变化后，旧报告不能继续授权共享。

## 生命周期与数据边界

安装、下载和本地导入注册制品后自动检测。已有安装在启动时补齐当前检测证据；失败或中断的报告保留，用户可以在运行版本页重试，避免无限自动重试。报告逐项更新到受管 `compatibility/<runtimeId>.json`，通过 IPC 显示。

检测只收到只读制品目录和新建 `compatibility-scratch/probe-*` 临时目录。每个原生 Host 使用独立 HOME、DSH_HOME、DSH_AGENTS_HOME、工作区及凭据文件，环境仅保留必需的系统路径和隔离变量。所有密钥、账号授权、模型端点和内容均为合成数据；不会复制用户的会话、密钥、Cookie 或插件，不调用真实模型或登录账号。

这是受控原生程序的独立数据检测，不是操作系统级恶意程序沙箱。程序来源、安装包 SRI 和全部运行文件封存仍由原有安装器负责；测试前再次校验候选和交叉检测制品的全部文件。

## 实际检查

| 检查 | 判断依据 |
| --- | --- |
| 文件完整性 | 所有文件和封存摘要一致 |
| 原生接口 | 通过正式技术路由启动真实 Web Host，包含私有技能和工作区适配 |
| 会话读回 | 原生创建、改名、写盘、正常关闭，再由新 Host 读取；观察不得激活 Agent |
| 写入锁 | 独立进程持锁时拒绝另一写入者，文件摘要不变；释放后可再次写入 |
| 工作区 | 真实工作区发现外部会话、关联和标题投影 |
| 附件 | 原生附件服务写入并无损读取合成内容 |
| 凭据 | 原生 Host 保存及解析假 API Key、读取共享凭据文件，检查账号记录格式与原子写入 |
| 模型配置 | 原生设置 RPC、临时共享配置和另外实例之间同步合成提供商 |
| CLI | 正式 Web / headless 组合运行 `--help` 并退出，不开启第二个工作台 |
| 交叉检测 | 与已通过当前检测的安装制品逐一双向读取会话、附件、凭据和模型配置，并交叉验证写入锁；只有一个制品时仍使用多个独立实例 |
| 清理 | 终止所有受管检测进程后清理临时文件；进程无法回收时不授予共享资格 |

检测按依赖顺序执行，前置失败会把后续项目标为未执行，而不是伪装成通过。错误、取消、超时、应用退出和临时清理失败均保留可解释的状态。每次检测有总时限，原生启动、RPC 和外部会话发现各有独立时限。

UI 只把全部必需检查通过的制品标记为「可共享存档」。新建共享实例、实际共享路由和外部 CLI 都检查相同证据；独立存档可继续使用。伙伴专用凭据和能力注入也保留原生能力保护，不能仅凭一个新的版本名称绕过。

## 删除和清理

界面与主进程共用 `runtimeReferences`，展示实例、快照、整合包和运行任务引用。删除或缓存清理期间阻止新的安装、检测和实例变更，避免引用检查与实际移除之间的竞态。

删除先将完整目录重命名进 `runtime-trash`，再提交安装索引。索引提交失败时恢复；进程在提交前崩溃，启动会找回仍登记的完整制品。提交后剩余垃圾不参与启动扫描，不会把删除的版本重新注册。Windows 占用造成物理清理失败时，界面说明可以重试清理缓存。

缓存清理只覆盖运行版本拥有的安装包、暂存、隔离和删除残留、检测临时目录，拒绝链接。不会遍历或删除实例、共享存档、快照、整合包和用户原始安装来源。缓存中不符合受管命名的文件保留。

## 工作台浏览器适配

原生网页仍运行在关闭 Node、开启上下文隔离与沙箱的窗口中。仅本地工作台主文档获得剪贴板写入权限，不开放任意网页的剪贴板读取权限。

网页登录支持先打开空白页、异步取得 PKCE 地址后跳转的原生流程。每个工作台只允许一个隐藏空白占位窗口，有超时和父窗口退出清理；授权 HTTPS 导航交给系统浏览器，远程页面不会加载进工作台的本地权限上下文。普通 HTTPS 链接同样可交给系统浏览器打开。

## 验收范围

原生回归使用本地安装的官方 npm 制品：0.2.0-rc.2、0.2.1-alpha.2、0.2.1-alpha.3。三者均执行完整隔离检测并双向互读；写入锁通过完整原生 Host 持有，不依赖某个发布版本的内部类导出。

`tests/e2e/dsh-native-auth.test.ts` 从完整启动器导入官方 alpha.3，在原生引导弹窗输入假密钥、点击「保存并继续」、检查模型可选、停止并重新启动，再由真实会话向本机假 HTTP 服务发起请求。服务只比较请求携带的假密钥并返回预设 401，不调用线上模型；这个测试证明本地保存、重启读取和模型请求凭据路由，不能证明真实账号授权或真实密钥的服务端有效性。`dsh-workbench-browser.test.ts` 检查真实沙箱窗口的空白页异步授权跳转和剪贴板写权限，保持用户原有剪贴板内容。

界面管理验收覆盖详细失败报告、未通过时禁用共享、引用阻止删除、缓存清理与共享存档保留，并检查明暗主题。删除恢复回归覆盖索引提交前中断恢复、提交后不复活，以及不删除用户存档与未知缓存文件。以上测试均使用独立临时用户目录。
