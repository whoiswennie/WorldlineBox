# 伙伴实例与话题 Agent 流程

内置角色只是创建模板，生产数据库首次启动不插入联系人。用户添加内置角色或创建自定义角色后，Main创建所选资产库中唯一的伙伴实例，资料、提示词、知识、日记、自我认识、世界经历、时间线、来源和认知索引都归入本人目录。

## 实例文件

`伙伴记忆/<伙伴ID>/instance.json` 是实例清单，列出 `profile.md`、`提示词/manifest.json`、`记忆策略.json`、`资料`、`日记`、`自我认识`、`世界经历`、`时间线`、`来源`、`记忆历史`、`形象` 和 `.认知索引`。初始化只创建结构与作者设定，不伪造经历或已学知识。没有实际经历的日记本为空是正常状态。

人设、提示词和记忆策略在创建时复制一份，后续推理读取当前实例文件；内置模板不会成为运行时修复或覆盖来源。资料缺失、损坏或版本冲突明确失败，不静默恢复旧设定。每次实际请求在模型排队结束后重新装配资料。聊天、世界决策、伙伴交流与任务结果反馈共用这个主脑入口。

“伙伴资产空间”将人设与实例、文档与记忆、提示词与规则放在同一管理入口。其“在资产管理中打开此伙伴”定位到同一资产库的链接目录，不复制另一份文件。人设编辑仍走同一个内容版本比较与保存流程。

## 联系人分组

联系人和群聊的分组分别管理。分组目录与成员归属保存于当前库的消息数据库 `contact-groups-v1` 元数据，通过版本比较原子保存，避免多个窗口覆盖修改。成员只引用实例或群聊ID，不复制角色文件或对话。默认分组可改名但不能删除；删除自定义分组后成员回到默认分组，身份、历史和权限不变。

## 所有聊天都有话题

首次打开私聊创建“主要对话”，群聊创建“主要群聊”。它们具有真实话题ID、成员、历史与工作检查点，直接显示在话题列表。主要对话、独立讨论、游戏和故事使用同一个话题存储与上下文整理流程，不再存在独立的无话题日常聊天接续引擎。

创建普通讨论时，用户选择的伙伴直接属于该聊天；游戏与故事仍保留自愿加入及主持和私态边界。切换话题只改变后续输入位置，运行中的回复始终按原消息的话题投递。浏览其他话题记录不会改变发送位置。

这对应 VCPChat 的角色→话题→历史组织：首次选中角色时创建“主要对话”，按当前话题装载历史，每次发送重新组织消息；VCPToolBox 再处理角色、记忆及本次工具循环。这里保留 WorldlineBox 的宿主身份、世界权限和工具契约。

## 本轮主脑上下文

1. 固定伙伴、来源消息、话题和实际授权。独立任务端口只装载本任务明确的消息。
2. 读取当前实例的人设、提示词、本人可见成长、当前状态及合法记忆。
3. 装配当前话题的工作检查点和未被覆盖的正式原文；长度压力达到阈值后合并旧前缀，保留逐字近期尾部和当前请求。
4. 保留原始历史，通过来源校验和原子提交推进检查点；失败不推进水位。检查点、私态与来源按本人和话题隔离。
5. 将历史发言编译为模型原生多轮消息，只有本人的正式发言成为assistant；其他伙伴、玩家和宿主资料保留真实作者。
6. 保留原生工具调用与对应结果，继续同一循环。当前人格和能力合同重新读取，已确认的作用不重复执行。

话题原文不因七天时间窗口被自然遗忘。游戏和故事保留特有的隐私与叙事核验；普通讨论不在每次回复后调用剧情审稿模型。

## 记忆与能力

话题工作检查点负责当前会话连续性；长期记忆通过本人目录的正文、来源和原版VCP检索处理。人设起点、自我认识和即时情绪分别表达其真实含义，不把角色设定写成已发生经历。知识来自真实读取与学习，不因创建空目录就视作已经掌握。

工具仍是项目设计的世界、DSH、内置浏览器和记忆能力，没有注册VCP工具插件。身份、授权、来源撤回、工具回执与私态继续由宿主核验。

消息渲染按原生执行步骤保留顺序：每段正文独立形成气泡，能力调用条挂在对应步骤下方，纯工具步骤不生成空白气泡。整体运行状态使用独立的可折叠面板；正常完成后自动隐藏，消息操作栏可主动展开历史过程和实际记忆收据。失败、中断和取消保留处理入口。状态面板关闭时卸载记忆详情，避免后台继续读取。

每个已激活实例的内部世界会话必须始终包含本人；世界同步同时维护会话与成员关系，不能仅在首次建表项时写入成员，否则世界查询产生的合法来源会让后续历史读取报“伙伴不是聊天成员”。历史或上下文准备阶段的异常也写入本条回复的具体失败原因与结束时间；问题解除后恢复同一队列任务。自动读取的相同错误在用户关闭后保持关闭，读取恢复后出现的新失败以及主动操作错误仍可正常显示。

用户重试未完成的回复时，同一步已取消或中断的DSH子任务通过原行动记录恢复，沿用可核验的原生会话；并行成功的子任务直接复用实际结果。恢复前确认旧执行已停止并重新核验来源，恢复排队与执行继续绑定该回复的取消信号。重复点击合并为同一恢复请求，等待旧执行结束期间的新取消会作废待恢复请求。取消本身可重复调用，失败只更新对应回复的状态和诊断日志，不再每次追加系统错误消息。

回复进度持久保存累计执行毫秒及当前运行区间起点。排队、取消、失败、中断不增长耗时；恢复开启新区间并延续已记录累计值，应用异常退出按最后持久进度冻结。正常阶段更新、用户停止回执和重启恢复共用同一计时规则。未记录的历史区间不凭最初消息时间猜测补齐。

新引导在宿主保存后只取消对应循环尚未提交的推理，重新装配同一步上下文，不算一次执行失败。原生任务启动期间收到的补充从持久输入箱重读投递，宿主按消息ID去重；DSH返回后仍在原循环处理最新要求。每段拟发布正文单独核验社交与文件交付声明，不把已经接受的旧计划反复当作本次完成声明。历史系统错误不再作为聊天正文重复渲染，当前回复卡保留实际失败入口。

同一角色的独立任务使用不同原生Session与托管工作目录；同一循环的后续步骤复用自己的目录，恢复沿用已核验目录。真实伙伴私聊和群聊也拥有正式主话题；只有单人世界证据端口不创建聊天话题。两个已授权协作任务、群聊回复及各自取消互相隔离。集成测试用受控原生回执覆盖耗时委托、群聊并行、启动交界补充和推理中引导，不操作玩家桌面。

聊天窗口打开或重新进入时只读取最新50条并定位底部；向上滚动后再分页，每页50条，挂载窗口最多200条。定位原文属于显式历史操作。程序滚动与普通刷新不能自动触发向前加载，阅读历史时新消息不抢滚动位置。

DSH委托使用完整任务背景、目标、输入、验收与限制。编译器只附加必要的资料和原始需求正文，去重重复文本，不再把来源ID、哈希、版本等内部证据JSON写入提示词；这些元数据继续用于宿主授权核验、续用范围校验和审计摘要。默认文本交付不追加空泛的格式说明，JSON及文件验收要求按实际配置保留，超限明确拒绝而不截断限制。

本实现直接采用当前实例和正式话题结构，不提供旧格式资料导入、空话题聊天迁移或两套接续引擎。测试环境按用户要求清空后从零创建实例。

## 提示词文件与可扩展人设

创建工厂目前生成33份Markdown行为模块和1份manifest.json。所有Markdown都被清单引用，按职责组合使用；反复加载实例不会追加副本。记忆策略JSON单独管理调度参数，不作为提示词发送。知识、日记、时间线和修订历史随真实使用积累；它们不属于这套固定行为模块。

人设模板只是起点。字段表单从当前profile.md正文中的【章节】或Markdown标题和“字段名：内容”动态投影，允许自定义章节和字段。字段编辑只替换对应源文本范围，不重建整份固定模板；删掉的字段不会自动补回。主脑读取完整当前正文，自定义设定与初始字段同等有效。

文档与记忆列表使用recordsOnly范围，配置文件不计为成长记录。提示词通过独立入口编辑；形象按当前可读图片统计，不按文本文件或内部状态文件统计。

## 删除联系人

内置实例与自定义实例均可删除。Main先停止所有本人任务、认知作业及真实执行进程，清理知识索引、执行记录与专属凭据；这些步骤失败时保留联系人供重试。随后Worker事务清理本人记忆、成长、工作、世界和参与状态，仅保留一个无原人设及图片的身份占位。普通聊天保留，内部记忆证据记录按归属撤回。

删除事务写入持久文件清理标记；Main清理实例目录及资产索引后才移除标记，中断后启动时继续。历史私聊只读，旧作者显示为已删除联系人。再次选择同一内置模板时创建新ID，旧消息不重新归给新实例。
