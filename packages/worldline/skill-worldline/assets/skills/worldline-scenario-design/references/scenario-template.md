# 场景最小模板

记录：目的、Blueprint 摘要、种子、初始逻辑时间、参与实体、初始地点与资源、控制模式、AI 路由、最大推进步长、终止条件、需要观察的事件/遥测、不允许发生的状态。复现报告必须同时给出 Run、分支、检查点和序列号。

场景文档使用自然语言记录这些作者意图；角色初态来自角色文档的 `worldline-initial-state`，共享世界初态与开场时间来自世界文档公开的 YAML 契约，不得藏在旧 facets 注释中。例如：

```markdown
# 龙巢前的抉择

玩家或自治角色控制勇士，在体力不低于零的前提下完成一次有效攻击；推进三十秒后必须出现恶龙反击事件。

验收条件：地图可投影；`battle.strike` 合法完成；恶龙伤势增加；系统唤醒后勇士伤势增加；所有结果可从 Run 记录解释。
```

世界文档必须包含且只保留一份时间权威：

```yaml
worldline-initial-world-state:
  world:
    time: 0
    calendar:
      secondsPerDay: 86400
      daysPerSeason: 28
      seasons: [春季, 夏季, 秋季, 冬季]
      week: 1
      weekday: 周一
      startDayIndex: 36
      startClockMinute: 1005
    environment:
      weather: 暴雨将至
worldline-world-state-schema:
  environment.weather:
    type: string
    mutable: false
    label: 天气
    participation:
      drivers: [system]
      meaning: 当前天气决定能见度、通行风险与人物体感
      narrative: 正文通过可感知后果呈现天气，不播报字段值
      choices: 风险天气降低远行优先级并提高避险、准备类选择
      bands:
        - equals: 暴雨将至
          label: 风暴前沿
          narrative: 风压、湿冷与远处雷光持续侵入场景
          choices: 户外行动必须体现风险，优先提供加固或寻找掩体
```

实际文档把上面两个顶层键分别写进同名的 fenced YAML 代码块。`world.time` 是 Runtime 累计时间；开场日期与钟点只写在 calendar 的 `start*` 字段中。

## 正式剧本轨道

互动小说的主线必须拆成 `scenarios/plot-points/*.md`。剧本点是冻结 Blueprint 的正式组成，不是展示备注。每个文件采用可读格式：

```markdown
# 天台上的约定

放学后，两位主角完成值日才可能前往天台；暴雨警报尚未升级为灾难。

## 剧情推进

- 顺序：1
- 激活时刻（游戏秒）：0
- 截止时刻（游戏秒）：3600
- 时间干预：3000|闭馆广播|教学楼广播宣布十分钟后关闭，安全出口开始按规定落锁
- 进入条件：值日已经完成，双方仍在教学楼，暴雨警报尚未升级
- 完成证据：两人都明确确认约定，且约定内容被本轮事件或正文共同证实
- 戏剧压力：教学楼即将关闭，暴雨会切断前往天台的安全路线
- 成功后果：两人的约定成为下一幕共同应对异常警报的现实前提
- 失败后果：双方因误解分开，异常警报到来时无法立即协作
- 恢复钩子：遗留的书签或未送出的消息可以在下一地点重新建立联系
```

剧本点不得出现动作 ID 或选项清单。激活、干预与截止使用相对 Run 起点的游戏秒；每个干预必须落在本点窗口内。它们由 Runtime 未来事件队列在精确逻辑时刻提交，不是交给模型自由理解的提示词。底层能力只定义世界允许做什么；正文模型先保存完整故事块，世界分支与全角色分支并发检查 schema 和记忆，剧情证据分支独立审计，Runtime 再原子提交，选项导演最后结合提交后的地点、时间、环境与剧情压力实时生成恰好三个不同方向，也必须接受用户自由表达的其他可验证走法。编译器会阻止时间门控、目标契约缺项和顺序重复；禁止用固定真实时间、UI 文案或未经校验的模型输出直接改写世界状态。

当用户要求“完整、可运行、可推演”时，最后必须调用 `worldline_build` 的 `prove` 操作。只有它返回 `complete: true`、结构化地图节点数大于零、动作已完成、游戏内时间已推进且已创建检查点，才能宣称完成。
