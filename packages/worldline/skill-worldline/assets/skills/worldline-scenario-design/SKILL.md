# 世界线场景设计

在设计一次可复现模拟的初始条件、参与者、目标、种子和观测指标时使用。

## 工作步骤

1. 明确模拟目的：验证、探索、压力测试或叙事体验。
2. 选择已存在的稳定角色/地点/资源 ID；每名角色都必须在 `worldline-initial-state` 中写出真实地图 `locationId`。
3. 在世界文档的 `worldline-initial-world-state` 中明确历法、开场日期与分钟数，再定义种子、时间范围、终止条件与 AI 路由；不得使用午夜、春季或教学楼等默认值。
4. 核对所有会变化的时间、天气、环境、角色与资源字段都有属性参与契约，当前区间会真实影响正文、状态导演和实时选项；拒绝只有裸数值和 UI 标签的“假状态”。
5. 定义可观察的成功、失败和风险指标，不把叙事文案当权威状态。
6. 把主线拆成有唯一顺序的剧本点。每点必须定义 Runtime 游戏秒表示的激活时刻、截止时刻和至少一个区间内的硬时间干预，并定义进入条件、可观察完成证据、戏剧压力、成功/失败后果和恢复钩子，绝不绑定动作 ID；Runtime 到点会写入不可被提示词规避的权威事件，正文保存后由状态导演提交可审计判定，最后才由选项导演实时生成三个方向。
7. 为验收场景加入至少一次顺主线推进、一次人物向选择和一次合理偏离；偏离不能自动失败，恢复钩子必须能把故事带回可完成路径。选项文本不得预写在场景或动作定义中。
8. 先冻结精确来源摘要，再创建暂停 Run；检查初始快照后才继续。内容验证要逐轮核对“正文 → 世界与完整角色名单并发推演 → 原子提交状态/记忆/证据 → 三项动态选择”的顺序，并从另一角色视角检查秘密没有越权泄漏；跨地点剧情必须观察到真实 move 完成和时钟推进后才能在新地点叙述后续动作；至少推进到一个时间干预与一个截止点，确认权威事件在精确时刻出现。视觉演绎还必须验证故事模型会逐段判断当前正文是否存在真正有叙事价值的视觉或听觉时刻：适合时把环境、角色、事件画面或环境音、音乐、角色声音自然放在对应正文位置，不适合或会重复时允许不插入，绝不规定开场配额、固定类型或轮换顺序。有真实素材时引用已导入资源，没有生成器时保留含类型、用途、提示词和文字替代的统一占位符。

## 权限边界

创建 Run 只读取冻结 Blueprint。推进、分支和控制模式变更必须绑定明确 run ID；停止 Run、切换模型或大步推进需确认或 dry-run 说明影响。场景结果不会自动写回 Canon。正文作者不能直接改写权威状态；状态导演只能引用本轮已保存正文、事件和观察提出变更或剧情判定，最终仍由 Runtime 校验并提交。
