# 世界线地图设计

在创建或审计地图节点、边、分层、通行条件、空间语义和旅行规则时使用。

## 工作步骤

1. 已有运行地图时才调用 `worldline_map read`，并读取引用它的角色、动作、系统。首次建图没有可读的运行地图，禁止用 `read` 探测格式。
2. 首次建图必须从本文末尾的完整 JSON 模板复制后整体替换值；不要从空对象开始逐字段猜测，也不要用失败调用探测 schema。
3. 使用稳定节点与边 ID，验证端点存在、ID 唯一、坐标有限、边权非负。冒号后的稳定部分至少 6 个字符，例如使用 `map-node:school-gate`，不能使用 `map-node:gate`。
4. 区分视觉布局与可执行拓扑；自动布局只改坐标，不改变连通关系。
5. 为单向、封锁、门槛、成本和跨层连接写出明确语义与来源。
6. 首次写入严格按 `validate` → `write(dry_run=true)` → `write(dry_run=false)` 执行；任何一步失败都在本地修正完整对象，不继续调用别的操作猜格式。随后构建预览。不要把 JSON 写入 Markdown。
7. 地点背景只能引用已成功导入的真实资源；严禁捏造不存在的 `assets/...` 路径。没有素材时省略背景引用，由客户端使用内置的中性地点默认图。
8. 每个地点必须有完整可读描述，至少覆盖空间风貌、主要感官、实际用途和会影响行动/叙事的环境条件；名称或一句标签不能代替描述。

## 信息来源

地图检查表、当前运行模型格式和最小示例已经附在本文末尾；它只用于工具参数。

## 权限边界

地图变更必须经项目服务和预期修订；删除被引用节点、批量改拓扑或改变旅行规则属于高影响操作，应创建 Proposal 或请求确认。不得维护第二种地图解析逻辑。
