# 世界线设定编写

在创建或修改世界观、地点、角色、组织、物件、关系等 Canon 来源时使用。本技能只处理当前 WWS 语义，不生成旧格式或兼容分支。

## 共创模式

开始时根据用户表达选择一种模式并告知用户；不要让用户重复已经提供的信息。

- **自主成案**：用户只给题材或一句话目标。Agent 可补全低影响细节，但会先列出少量会改变作品方向的高影响决定。
- **引导访谈**：用户希望共同设计。每轮只问一个最影响后续结构的问题，同时继续完成不依赖该答案的只读调查与草稿整理。
- **增量修订**：已有项目上修改。先回显“保持不变／本轮改变／仍待决定”，只改用户授权的部分。

全过程维护一个简短的共创台账：`作者事实`、`已确认决定`、`高影响未知`、`可由 Agent 自主补全`。用户的新决定覆盖早期推测，但不得静默覆盖其已确认事实。低影响未知不能阻塞创作；高影响未知包括核心身份、关系结论、秘密归属、不可逆伤亡、世界规则边界与结局方向。

## 工作步骤

1. 先用项目列表找到目标；只在第一次查询时原样提供一次 `project_id` 以选中项目。选中后所有查询、编辑、地图和构建调用都省略 `project_id`，使用当前活动项目；只有切换项目时才再次提供另一个列表返回的 ID。然后读取项目树、目标文档、相关反向链接和必要历史，确认已有稳定 ID 与作者事实。
2. 建立或更新共创台账。若存在高影响未知，先给出目前理解的两三句回显，再问一个紧凑问题；问题必须解释它会影响哪些角色、规则或剧情。用户回答后把决定写入台账，再进入下一问题，禁止一次抛出长问卷。
3. 按阶段加载并执行对应技能：Canon 与主题用本技能，OC 用 `worldline-character-design`，空间用 `worldline-map-design`，动作/系统/不变量用 `worldline-mechanism-design`，主线和验收场景用 `worldline-scenario-design`。先形成跨阶段一致的草案，再做实质写入。
4. 写入前向用户回显将保留的关键事实、将新增或改变的内容及仍未决定的高影响项。自主成案模式可直接继续；引导访谈或增量修订中，用户刚给出的明确指令即视为该范围的确认，不重复索要许可。
5. 使用稳定 ID 建立引用；显示名可以改变，身份不可随重命名改变。每个角色都要明确“知道什么、误信什么、不知道什么”，秘密不能只作为全局旁白材料。
6. 通过带 `expected_revision` 的补丁写入，保留来源锚点；冲突时重新读取，不覆盖并发编辑。修改已有文档前必须先读取当前正文；整篇替换使用 `replace.content`，局部替换才使用非空且精确匹配的 `replace.before` 与 `after`。新路径只需用 `create` 提供 `path` 与 `content`，省略 `document_id` 时工具会自动分配；不要拿空 `before` 或缺参调用试探工具格式。
7. 重新搜索断链并执行构建预览。先修复可由已确认事实决定的问题；只有诊断确实依赖作者的高影响选择时才回到单问题访谈。
8. 在作者意图闭合后才执行 `prove`。内容验收必须同时检查：角色知识是否越权、时间地点是否来自当前状态且跨地点只由 Runtime 移动、每项会变化的属性是否按参与契约实际改变叙事与选项、主线是否允许偏离与恢复、动作是否来自 Runtime 能力、正文后是否先提交状态/记忆/证据并最后实时生成选项。视觉演绎由故事模型逐段按当前情境判断：地点、光线、天气、角色登场或表情、关键物件/动作、环境声和有意义的角色声音适合时，应自然成为正文中的原生演出块；媒体没有增加信息、会重复近期演出或破坏节奏时，可以不插入。不得设置开场媒体配额、固定种类或按轮次轮换。有真实素材时必须建立资源引用；没有生成器时必须保留可解析的统一媒体意图与文字替代。编译通过但该出现时长期退化为只有旁白与头像，或不该出现时机械堆叠媒体，都不算完成。

## 信息来源

作者项目文档和已批准 Proposal 高于模型猜测；运行记录不能反向改写 Canon。对象和来源规则已经附在本文末尾。

## 权限边界

查询可直接执行。写入必须限定项目、路径、稳定 ID 和预期修订；批量移动、删除、根目录变更和冻结需明确确认。绝不通过通用文件工具绕过项目服务，绝不修改远程仓库。
