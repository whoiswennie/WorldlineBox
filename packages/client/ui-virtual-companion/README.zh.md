# 虚拟伙伴界面

[English](README.md) | 中文

这是主导航“虚拟伙伴”和“知识库”目的地的 Host/Client 双面插件。Host 在当前账户数据目录持久化伙伴通讯录、会话房间成员，以及每位伙伴的一套可移植 Agent Vault；Client 提供结构化印象卡、角色包导入导出、统一的记忆与资源工作台、文件树、专业文本编辑器、预览、自动保存和冲突恢复。内置月见八千代、酒寄彩叶和辉夜三位角色，每位都有独立的身份、形象、人设、语气、状态、记忆、能力和资源。

会话顶部显示房主和角色成员，`@` 候选可邀请新角色或强制指定发言。每位在场伙伴由一个独立、可续接的 Agent 会话驱动，并通过原生 Session 事件直接发送文字、图片、表情、音频、视频、链接和后续扩展类型。正常轮次始终复用该角色的持久会话；只有确实无法恢复时才停驻旧会话并绑定替代会话，同时保留旧日志供子代理目录按角色追溯。界面按名称和实时头像分开渲染。账户公开资料仍由 preset 内的独立上下文插件注入；头像只用于浏览器呈现，更换后通过反应式账户/伙伴存储同步到当前会话。

## 架构

`virtual-companion` Agent Preset 的主 Agent 只负责理解用户、使用业务工具和调度，不拥有公开发言身份，也绝不扮演角色。伙伴通过 `dispatch_companion` 激活；公开名称为“旁白”的独立持久 Agent 通过 `dispatch_narrator` 激活，用第三方视角描写环境、动作、神态、语气和状态，空房间也由它回应。伙伴与旁白的文字统一按 token 增量写入原生房间事件，真实表情与文字按发生顺序呈现；主调度正文不会渲染，因此不会在 Agent loop 中重复旁白。伙伴会话默认采用沉浸呈现：输入框里的“过程”开关默认关闭，隐藏主调度的思考、上下文注入和工具节点；这些事件仍照常流式接收和持久化，等待期间由伙伴头像、分阶段文案和动态圆点持续反馈房间状态，打开开关即可查看完整过程。旁白采用与角色对话同一视觉语言的轻量场景条，保留独立叙事身份但不冒充角色气泡。首次激活任一房间 Agent 时会从主会话分叉当时的已完成历史，之后续接它自己的干净上下文。

每位伙伴拥有一套独立、以文件为真源的 Agent Vault。她只能读取公共 Vault 和自己的私有 Vault，也只能修改策略明确允许的域；完全冻结会拒绝所有 Agent 写入，而用户编辑是否开放仍由独立策略决定。加入和离开房间都是持久化 Session 事件。内置伙伴可以通过应用内确认界面恢复原版；恢复会把当前 Vault 移入可恢复回收区、安装当前版本的内置原版，并退役仍在运行的角色会话，使下一次发言采用恢复后的自我。旧的知识库/引用库双产品、文本标签注入、多角色单模型扮演和补发修复协议均不再存在。

### Agent Vault 架构

磁盘上的 Markdown 和资源记录是真源，SQLite FTS5 只是可以随时丢弃并重建的投影。Vault URI 使用可移植的 `vault://...`；只有确实需要外部工具编辑时才由 Host 发放路径租约，导出的文档不会写入某台电脑的绝对路径。记忆分为立即可检索的短期收录、归一化后的中期材料，以及经过审慎归档的长期知识。整理任务有边界、有检查点、可恢复，只有一个阶段完整结束后才更新阶段稳定的常用记忆卡。结构化 `self` 与记忆、能力、技能、导航图和资源存放在同一 Vault 内，但拥有独立授权与检索域，因此普通记忆召回不会误改身份或人设。

快速方向召回组合使用层级路径、标题、别名、标签、确定性的中英文词法切分、trigram FTS5 和有界评分，不需要 embedding 模型或外部 API。深度召回使用 `memory_explore` 与 `vault_read`，沿局部 Wiki 链接渐进阅读，而不是扫描整个语料库。记忆、能力、资源、自我检查、写入、整理、路径租约与回收分别由独立工具负责。八个内置 Agent Vault skill 把收录、召回、能力学习、资源使用、冲突审查、阶段整理、治理和迁移约束成带验证的方法论，而不是一次性摘要。

资源是 Vault 的一级域，不再是第二套产品。Agent 只有在需要素材时才调用 `resource_find` 或伙伴侧的 `express`，不会自动注入完整标签或资源目录。标题、说明、标签、角色用途和可选转写进入同一套有界词法投影，二进制进入 SHA-256 内容寻址对象库。资源可以在不删除文件的情况下启用或禁用。图片、文本和音视频使用共享 MIME 渲染器注册表，未知类型安全回退为附件。大文件上传会边写磁盘边计算哈希，音视频投递支持 HTTP Range。媒体画廊仍保留适合资源的卡片式呈现，但它位于同一个 Agent Vault 工作台中。旧 `ReferenceVault` 只作为可重启的 v1 迁移读取器存在，不会作为生产数据服务挂载。

## 模型体验

模型通过主调度房间快照、每次伙伴调度时重新编译的已启用结构化印象卡、有界快速召回、渐进式 Vault 读取、语义资源 `express` 工具和原生伙伴流式/资源事件间接看到本插件的影响。不会自动注入完整记忆、能力、标签或资源目录。

#### KV Cache 影响

主调度只注入当前房间的精简成员目录和最近的原生房间事件；完整角色上下文留在各伙伴会话中。成员稳定时可保留主调度前缀，增减成员只影响房间快照，不会把未在场角色资料塞入上下文。印象卡紧凑且按阶段稳定，召回卡有严格上限，资源只在模型选择表达动作后解析，因此 Vault 不会淹没或扰乱稳定前缀。

## 已知限制与后续工作

- 无模型发现有意优先保证精确度：如果一种改写与页面的路径、标题、别名、标签和词法项完全没有重合，Agent 可能需要多次改写查询或进行一次有界目录探索。
- 恢复内置伙伴会在用户确认后按设计替换其私有编辑；它属于重置操作，不提供撤销历史。
