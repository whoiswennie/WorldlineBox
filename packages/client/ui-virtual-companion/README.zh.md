# 虚拟伙伴界面

[English](README.md) | 中文

这是主导航“虚拟伙伴”和“知识库”目的地的 Host/Client 双面插件。Host 在当前账户数据目录持久化伙伴通讯录、会话房间成员、Markdown 知识文档与引用索引；Client 提供角色卡片、文件树、专业文本编辑器、预览、自动保存、冲突恢复和引用管理。内置月见八千代、酒寄彩叶和辉夜三位角色，每位都有独立的核心身份、人设性格、说话语气和行为逻辑。

会话顶部显示房主和角色成员，`@` 候选可邀请新角色或强制指定发言。每位在场伙伴由一个独立、可续接的 Agent 会话驱动，并通过原生 Session 事件直接发送文字、图片、表情、音频、视频、链接和后续扩展类型。正常轮次始终复用该角色的持久会话；只有确实无法恢复时才停驻旧会话并绑定替代会话，同时保留旧日志供子代理目录按角色追溯。界面按名称和实时头像分开渲染。账户公开资料仍由 preset 内的独立上下文插件注入；头像只用于浏览器呈现，更换后通过反应式账户/伙伴存储同步到当前会话。

## 架构

`virtual-companion` Agent Preset 的主 Agent 只负责理解用户、使用业务工具和调度，不拥有公开发言身份，也绝不扮演角色。伙伴通过 `dispatch_companion` 激活；公开名称为“旁白”的独立持久 Agent 通过 `dispatch_narrator` 激活，用第三方视角描写环境、动作、神态、语气和状态，空房间也由它回应。伙伴与旁白的文字统一按 token 增量写入原生房间事件，真实表情与文字按发生顺序呈现；主调度正文不会渲染，因此不会在 Agent loop 中重复旁白。伙伴会话默认采用沉浸呈现：输入框里的“过程”开关默认关闭，隐藏主调度的思考、上下文注入和工具节点；这些事件仍照常流式接收和持久化，等待期间由伙伴头像、分阶段文案和动态圆点持续反馈房间状态，打开开关即可查看完整过程。旁白采用与角色对话同一视觉语言的轻量场景条，保留独立叙事身份但不冒充角色气泡。首次激活任一房间 Agent 时会从主会话分叉当时的已完成历史，之后续接它自己的干净上下文。

每位伙伴拥有独立的 Markdown 知识库与索引；她只能读取公共知识库和自己的私有知识库，也只能修改自己的私有知识库。加入和离开房间都是持久化 Session 事件。内置伙伴可以通过应用内确认界面恢复原版；恢复会用当前版本的内置原版替换用户编辑过的人物资料、私有知识库和私有引用库，并退役仍在运行的角色会话，使下一次发言采用恢复后的人设。旧的文本标签、多角色单模型扮演、引用工具和补发修复协议均不再存在。

### 知识与引用架构

知识库以磁盘上的 Markdown 为唯一真源，SQLite FTS5 只是可重建的增量索引。公共库位于统一根目录，伙伴私有库按 ID 前缀分片。每个发生变化的 agent 步骤开始前，由 Host 管理的感知层先执行确定性的标题/标签别名匹配，再进行有界的词法 FTS 回退。它最多提供 3 条元数据候选，只对首个高置信度结果读取顶部视图，抑制没有变化的 manifest，绝不把整批结果加载进上下文。这条路径不使用 embedding 模型。Agent 可以通过 `knowledge` 工具的顶部、段落或 grep 视图深入有用候选，只在确有必要时读取全文。轮次中途产生的工具结果会成为下一步骤的发现信号，因此发现过程不限于开场提示。`knowledge-use`、`knowledge-maintain` 和 `knowledge-govern` 三个内置 skill 分别约束日常使用、去重整理与治理审计。

引用库是独立的表达通道，不会把资产候选列表塞进提示。每个 Agent 只看到当前权限范围内的紧凑标签目录，并在本可输出自然语言的位置调用 `express`，自由组合标签与自然语言场景；Host 随后才延迟绑定一个新鲜、未重复的资源。资源不存在固定类别，也不保存独立的情绪、意图、主题或角色字段：表情包、视频、开心、角色名和用户自定义概念全部属于同一个开放标签空间。资源可以独立启用或禁用；禁用不会删除内容，但会把资源同时排除在 Agent 标签目录和快速召唤查询之外，管理界面仍可检索并重新启用。标题、说明、标签和可选正文/转写进入 SQLite FTS5，二进制进入 SHA-256 内容寻址对象库。呈现完全由 MIME 驱动的开放渲染器注册表处理；图片、文本、音视频使用内置渲染器，Canvas 或插件类型只需注册一次即可在资源库、预览和 Agent 对话中复用，未知类型安全回退为附件。大文件上传会边写磁盘边计算哈希，不进入进程堆内存；音视频播放按 HTTP Range 从文件读取所需区间，因此索引和 Agent 上下文成本不随影片时长增长。持久事件只保存稳定资产 ID、MIME 与投递 URL。

## 模型体验

模型通过主调度房间快照、仅在变化时出现的 `resource-awareness` 消息、伙伴自己的 `knowledge` 与 `express` 工具、原生伙伴流式/引用事件，以及下一次调度所采用的恢复后角色资料间接看到本插件的影响。

#### KV Cache 影响

主调度只注入当前房间的精简成员目录和最近的原生房间事件；完整角色上下文留在各伙伴会话中。成员稳定时可保留主调度前缀，增减成员只影响房间快照，不会把未在场角色资料塞入上下文。知识感知快照只在变化时出现且具有严格上限；引用资产则在模型选择表达动作之后才解析，因此两个资料库都不会淹没或扰乱稳定前缀。

## 已知限制与后续工作

- 无模型发现有意优先保证精确度：如果一种改写与页面的标题、标签和词法项完全没有重合，agent 可能需要显式调用 `knowledge` 搜索。
- 恢复内置伙伴会在用户确认后按设计替换其私有编辑；它属于重置操作，不提供撤销历史。
