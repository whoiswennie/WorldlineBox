# Virtual Companion UI

English | [中文](README.zh.md)

Host/Client plugin for the `Virtual companions` and `Knowledge` primary-rail destinations. The Host persists the companion directory, room membership, Markdown knowledge, and indexed references in the current account data directory. The Client provides character cards, a lazy file tree, a professional text editor, preview, autosave, conflict recovery, and reference management. The built-in directory contains Yachiyo Runami, Iroha Sakayori, and Kaguya; each profile has independent identity, persona, speaking style, and behavior rules.

The room header shows the owner and character participants. `@` candidates can invite a character or require a particular participant to reply. Every present companion is driven by an independent, continuable Agent session and sends text, images, stickers, audio, video, links, and future reference kinds through native Session events. Normal turns reuse that durable role session. If it becomes genuinely non-resumable, the runtime parks it and binds a replacement without deleting the old transcript, so the subagent catalog can retain role-grouped history. The client renders separate bubbles with live names and avatars. Public account information still enters through the preset's independent context plugin; avatar bytes remain presentation-only and reactive account/companion stores propagate changes to an open conversation.

## Architecture

The `virtual-companion` preset's main Agent is a pure coordinator: it understands the user, uses business tools, and dispatches actors, but has no public speaking identity and never role-plays. Companions are activated through `dispatch_companion`. A separate persistent Agent publicly named **Narrator** is activated through `dispatch_narrator`; it describes environment, action, expression, tone, and observable state from a third-person viewpoint and also handles empty rooms. Companion and Narrator text is written into native room events as token deltas, preserving the real order of prose and memes. Coordinator prose is hidden, preventing loop-driven duplicate narration. Companion sessions default to an immersive presentation: the composer Process switch starts off, hiding coordinator reasoning, context injection, and Tool nodes while their streams and durable events continue normally. During that hidden work, an avatar, staged presence copy, and animated dots keep the room visibly alive; switching Process on reveals the full trace. Narration uses a compact scene strip in the same visual language as character chat while retaining a distinct narrative identity instead of pretending to be a character bubble. Each room Agent's first activation forks the parent's completed history; later activations continue that Agent's clean context.

Each companion owns an independent Markdown knowledge vault and index. A companion can read only the public vault and its own private vault, and can modify only its own private vault. Join/leave changes are durable Session events. A built-in companion can be restored through an in-app confirmation surface; restoration replaces the edited profile, private knowledge vault, and private reference vault with the bundled originals and retires any active role session so its next turn uses the restored profile. The former text-tag, single-model multi-role, reference-tool, and repair protocols no longer exist.

### Knowledge and reference architecture

Markdown files on disk are the sole source of truth for knowledge; SQLite FTS5 is a rebuildable incremental projection. The public vault has one stable root, while private vaults are sharded by companion-ID prefix. Before every changed Agent step, a Host-owned awareness layer performs deterministic title/tag alias matching first and bounded lexical FTS fallback second. It contributes at most three metadata candidates, reads only the top view of a high-confidence first result, suppresses unchanged manifests, and never loads an entire result set into context. This path uses no embedding model. Agents can deepen a useful candidate through the `knowledge` tool's top/section/grep views and request full text only when necessary. Tool results produced midway through a turn become signals for the next step, so discovery is not limited to the opening prompt. The bundled `knowledge-use`, `knowledge-maintain`, and `knowledge-govern` skills cover daily use, consolidation, and audit policy.

The reference vault is a separate expression channel, not an asset candidate list injected into a prompt. Each Agent sees only a compact tag catalog for its authorized scopes and calls `express` at the same point where it could emit prose, freely combining tags with a natural-language situation. The Host then late-binds one fresh, non-repeating resource. Resources have no fixed category and no separate mood, intent, topic, or character fields: sticker, video, happy, a character name, and every user-defined concept all live in one open tag space. An asset can be enabled or disabled independently; disabling preserves it for management and later re-enabling while removing it from both the Agent tag catalog and fast retrieval. Titles, descriptions, tags, and optional text/transcripts use SQLite FTS5; binary data uses a SHA-256 content-addressed object store. Presentation is delegated to an open MIME renderer registry. Images, text, audio, and video have built-in renderers; Canvas and plugin media register once and are reused by vault cards, previews, and Agent conversation. Unknown media safely falls back to an attachment. Large uploads stream to disk while hashing instead of entering the process heap. Audio/video playback reads only requested HTTP ranges, so indexing and Agent-context costs do not grow with movie duration. Durable events retain only stable asset IDs, MIME, and delivery URLs.

## Model Experience

Indirectly, through the coordinator room snapshot, delta-only `resource-awareness` messages, companion-local `knowledge` and `express` tools, native companion stream/reference events, and the restored actor profile selected for the next dispatch.

#### KV Cache effect

The coordinator receives only the compact current-room directory and recent native room events; full role context remains in each actor session. Stable membership preserves the coordinator prefix, and absent companions are not injected into the context. Awareness snapshots are delta-only and bounded, while reference assets are resolved after the model has chosen an expression act, so neither vault floods or destabilizes the stable prefix.

## Known Limitations and Deferred Work

- Model-free discovery deliberately favors precision: a paraphrase that shares no title, tag, or lexical term with a page may require an explicit `knowledge` search.
- Restoring a built-in companion intentionally replaces its private edits after confirmation; it is a reset operation, not an undo history.
