# Virtual Companion UI

English | [中文](README.zh.md)

Host/Client plugin for the `Virtual companions` and `Knowledge` primary-rail destinations. The Host persists the companion directory, room membership, and one portable Agent Vault per companion in the current account data directory. The Client provides structured self cards, character-package import/export, a unified memory and resource workspace, a lazy file tree, a professional text editor, preview, autosave, and conflict recovery. The built-in directory contains Yachiyo Runami, Iroha Sakayori, and Kaguya; each profile has independent identity, appearance, persona, speaking style, state, memory, procedures, and resources.

The room header shows the owner and character participants. `@` candidates can invite a character or require a particular participant to reply. Every present companion is driven by an independent, continuable Agent session and sends text, images, stickers, audio, video, links, and future reference kinds through native Session events. Normal turns reuse that durable role session. If it becomes genuinely non-resumable, the runtime parks it and binds a replacement without deleting the old transcript, so the subagent catalog can retain role-grouped history. The client renders separate bubbles with live names and avatars. Public account information still enters through the preset's independent context plugin. Uploaded user avatars are materialized for explicit visual inspection, while each companion's registered portrait is a first-class `appearance` Vault resource. User and companion reference messages share the same bounded media figure instead of maintaining two size and caption systems.

## Architecture

The `virtual-companion` preset's main Agent is a pure coordinator: it understands the user, uses business tools, and dispatches actors, but has no public speaking identity and never role-plays. Companions are activated through `dispatch_companion`. A separate persistent Agent publicly named **Narrator** is activated through `dispatch_narrator`; it describes environment, action, expression, tone, and observable state from a third-person viewpoint and also handles empty rooms. Companion and Narrator text is written into native room events as token deltas, preserving the real order of prose and memes. Coordinator prose is hidden, preventing loop-driven duplicate narration. Companion sessions default to an immersive presentation: the composer Process switch starts off, hiding coordinator reasoning, context injection, and Tool nodes while their streams and durable events continue normally. During that hidden work, an avatar, staged presence copy, and animated dots keep the room visibly alive; switching Process on reveals the full trace. Narration uses a compact scene strip in the same visual language as character chat while retaining a distinct narrative identity instead of pretending to be a character bubble. Each room Agent's first activation forks the parent's completed history; later activations continue that Agent's clean context.

Each companion owns one independent, file-native Agent Vault. A companion can read only the public Vault and its own private Vault, and can modify only domains allowed by its policy; full freeze makes every Agent write read-only while user editing remains an explicit policy choice. Join/leave changes are durable Session events. A built-in companion can be restored through an in-app confirmation surface; restoration moves its current Vault to recoverable trash, installs the bundled original, and retires any active role session so its next turn uses the restored self. The former split knowledge/reference products, text-tag injection, single-model multi-role acting, and repair protocols no longer exist.

### Agent Vault architecture

Markdown and resource records on disk are the source of truth; SQLite FTS5 is only a disposable, rebuildable projection. Vault URIs are portable (`vault://...`), Host path leases cover exceptional external editing, and no exported document contains a machine-specific absolute path. Memory moves through immediately searchable short-term capture, normalized medium-term material, and deliberately archived long-term knowledge. Consolidation is bounded, checkpointed, resumable, and updates the phase-based common-memory card only after a completed stage. Structured `self` modules are stored beside memory, procedures, skills, maps, and resources but remain a separately authorized search domain, so ordinary recall cannot accidentally rewrite identity or persona.

Fast direction-finding combines hierarchical paths, titles, aliases, tags, deterministic Chinese/Latin lexical terms, trigram FTS5, and bounded scoring; it requires no embedding model or external API. Deep retrieval uses `memory_explore` and `vault_read` to follow local Wiki links progressively instead of scanning the corpus. Separate tools cover memory, procedures, resources, self inspection, writes, consolidation, path leases, and reconciliation. Eight bundled Agent Vault skills teach capture, retrieval, capability learning, resource use, conflict review, consolidation, governance, and portability as verified workflows rather than one-shot summarization.

Resources are a first-class Vault domain rather than a second product. An Agent calls `resource_find` or the companion-facing `express` tool only when it needs an asset; no full tag or asset catalog is injected. Titles, descriptions, tags, roles, and optional transcripts use the same bounded lexical projection, while binary data uses a SHA-256 content-addressed object store. Assets can be enabled or disabled without deletion. The stable `profile-appearance` record is deliberately separate from `expression` resources: `inspect_self_appearance` attaches the actual registered image before a visual description, and `show_self_appearance` sends that exact resource without substituting a meme. Images, text, audio, and video use the shared MIME renderer registry; unknown types safely fall back to attachments. Large uploads stream directly to disk under a configurable 128 GiB default safety ceiling, and content-addressed audio/video delivery supports HTTP ranges in both the gallery and conversation references without duplicating the file. The gallery remains a media-native card view inside the same Agent Vault workspace. The legacy `ReferenceVault` reader exists only for the restart-safe v1 migration and is not mounted as a production data service.

Ordinary Agents receive the same public reference channel without access to companion-private resources. An exact user-named asset is resolved through bounded `expression_search`, then `express` renders the actual public media card in the transcript; semantic hints and model-guessed tags influence ranking but are not hard catalog filters. The successful `express` result persists its resolved asset id, URL, MIME type, and title as presentation metadata, so replay and live projection render the same media instead of relying on model-facing status text. This keeps a named public video, GIF, image, audio clip, or extension MIME available without substituting an emoji, textual imitation, or web search.

## Model Experience

Indirectly, through the coordinator room snapshot, the enabled structured self snapshot compiled fresh for every companion dispatch, the stable appearance resource id, bounded fast recall, progressive Vault reads, semantic `express` resolution, and native companion stream/resource events. Appearance image bytes enter only the result of an explicit inspection tool; the complete memory, procedure, tag, and resource catalogs are never injected automatically.

#### KV Cache effect

The coordinator receives only the compact current-room directory and recent native room events; full role context remains in each actor session. Stable membership preserves the coordinator prefix, and absent companions are not injected into the context. The self snapshot is compact and phase-stable, recall cards are bounded, and resources resolve only after the model chooses an expression act, so the Vault does not flood or destabilize the stable prefix.

## Known Limitations and Deferred Work

- Model-free discovery deliberately favors precision: a paraphrase that shares no path, title, alias, tag, or lexical term with a page may require several query reformulations or a bounded directory exploration.
- Restoring a built-in companion intentionally replaces its private edits after confirmation; it is a reset operation, not an undo history.
