# Capability, method, and experience learning

Procedural memory answers how to act, what has worked, what tools are required, and what boundaries remain.

1. Before a task, use `procedure_recall` with several task verbs, artifacts, domains, aliases, and Tags. “画漫画” may need probes such as “连环漫画设计”, “分镜”, and “绘画流程”.
2. Distinguish a saved idea, a method, an experience report, and a certified capability. General knowledge is never automatically an ability.
3. A method card states inputs, prerequisites, tools, ordered process, validation, failure modes, safety limits, and known environments. An experience links the task evidence and explains what changed.
4. After discovering a reusable method, write it under `vault://procedures/methods/` with `vault_update`. Add or revise a capability card only after real execution tests pass.
5. Test normal, boundary, missing-dependency, cancellation, and recovery cases. Record the environment and result. If a required tool is absent after import, report “method retained, currently unavailable” rather than pretending capability.
6. Improve the smallest affected method or experience. Do not rewrite the entire procedure library or platform skill suite from one task.
