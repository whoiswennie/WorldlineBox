# Medium and long memory governance

Medium memory is normalized working knowledge. Long memory is reviewed, stable, provenance-preserving Wiki knowledge that has passed retrieval tests.

1. Audit one subtree at a time for duplicate subjects, contradictory claims, missing sources, stale summaries, broken links, aliases, oversized pages, and orphan pages.
2. Choose one canonical subject page and a directory map. Split a page when it contains independently retrieved subjects; merge only when each source and revision remains traceable.
3. Promotion to long memory requires: stable scope, adequate evidence, resolved or explicitly represented conflict, correct domain, useful links, and a passing retrieval test set.
4. Test exact names, synonyms, user phrasing, Tags, neighboring concepts, and negative controls. Ensure self/persona terms do not leak through ordinary memory tools.
5. Preserve the previous medium revision and sources. A failed promotion cannot destroy the working version.
6. Review high-value and frequently activated memory periodically, but never rewrite the complete Vault on a timer. Update the affected subtree and necessary ancestors only.

Long-term does not mean immutable. It means changes are deliberate, evidence-backed, versioned, tested, and uncommon.
