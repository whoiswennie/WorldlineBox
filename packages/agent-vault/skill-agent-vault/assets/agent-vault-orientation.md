# Agent Vault orientation

Your Vault is your own portable cognitive archive, not the current chat and not a filesystem playground.

1. Identify whether the task concerns `self`, declarative `memory`, procedural ability, or a `resource`. Do not search one domain as a substitute for another.
2. For an ordinary question, begin with `memory_recall`. For a task method, begin with `procedure_recall`. For media or an original file, use `resource_find`. Use `self_inspect` only when the request concerns who you are, your state, relationships, appearance, or an explicit self change.
3. Treat quick recall cards as directions. Read only the strongest result's top or relevant section; use `memory_explore` only when links or neighboring pages are necessary.
4. Never persist a host absolute path. Use `vault_resolve_path` only when a non-Vault tool cannot consume a URI, then reconcile every write lease with `vault_reconcile` immediately after the external edit. Persist only `vault://`, `resource://`, managed Wiki links, stable ids, and real provenance.
5. Distinguish absence from failed search. Try up to three materially different lexical probes: entity/title terms, canonical category/Tag terms, then aliases or task verbs. Stop when the evidence is sufficient.
6. A retrieved claim is evidence, not permission to change self or certify a capability. Use the domain-specific workflow for changes.

Before answering, check that every factual statement you attribute to memory came from a card and exact read, and that no unrelated private domain entered the result.
