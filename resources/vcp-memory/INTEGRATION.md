# WorldlineBox VCP Memory integration

This directory contains the standalone `vcp-memory` 0.1.0 module captured on 2026-11-02 from the user-provided module. Original ToolBox, VCPChat, CDS and embedding source snapshots and their integrity manifests remain unchanged. Original licenses and attribution are preserved.

WorldlineBox does not ship the standalone package's duplicate embedding model or llama.cpp binaries. A loopback gateway supplies the application's built-in EmbeddingGemma model, with profile identity and independent document/query routes. Runtime credentials are passed in the worker environment, not written to diary files or source control.

The `lib` host adapters additionally support an explicit Node executable, bounded session cancellation/shutdown, durable memory-write receipts with content-version indexing checks, bounded idempotent 100-message history episodes, changed-episode CDS mirrors, and a resident entry point to the preserved TopicMemo functions. Default standalone `search` still performs full sync; the managed adapter explicitly chooses `sync:false` only after startup reconciliation and reports pending writes separately. These are transport/storage lifecycle adaptations, not replacements for VCP retrieval, ranking or scores.

Run `node scripts/stage-bot-memory.mjs` from the WorldlineBox repository. It verifies the original source integrity manifests with an explicit managed-embedding exception: 112 standalone model/runtime assets are omitted because the application verifies and serves its own built-in bundle. It installs the exact production lockfile into `.tools/bot-memory-release/vcp-memory`, independent from Electron's native dependencies. Node 24 is required; pass `--node=<path>` to target the executable used by DSH. The staged directory is an Electron extraResource named `vcp-memory`.

Managed homes are exclusive to the bot memory adapter. Original CLI session mutations mark the CDS mirror dirty. Managed event appends notify only the changed episodes. Offline/manual filesystem edits are reconciled on the next worker startup; this adapter does not advertise arbitrary live external editing as immediately indexed. Ingestion failures remain pending/errors rather than synthetic success. Interrupted uncertain writes are not blindly repeated.

`lib/ingestion-scheduler.cjs` applies a version-pinned timer ownership adaptation when compiling the captured ingestion module for an owned memory home. A direct flush consumes an outstanding watcher timer; a failed batch stores its original repair deadline in that same `batchTimer`, which the watcher and shutdown already recognize. This prevents independent watcher and repair retry chains during an encoder outage. The adapter checks the captured module's SHA-256 before compilation and rejects unknown revisions or an already-loaded unmanaged pipeline. Snapshot files on disk remain unchanged; embedding, ingestion receipts, native index writes and retrieval algorithms retain their original implementations and retry delays. Native regression covers overlapping watcher/explicit flush, a local 503 encoder, cancellation, pending state, and subsequent complete checksum/vector/tag receipts.

Per-request preprocessed messages/OneRing metadata and completion receipts live in the adapter's SQLite database. A completed request releases its large prepared JSON; idempotency receipts remain indexed rows. Domain cancellation and shutdown retire the actual worker and its child process tree, leaving durable pending state for recovery. The background `memory-capture.ts` policy uses an action-free DSH encoder and strict JSON; its native context is isolated by domain, withdrawal epoch and durable job ID. A retry reuses that same job identity; a new job never reactivates previous capture source history. This is a host write policy, separate from the preserved VCP retrieval algorithms.

Managed `bot.forget` accepts an owned stable note ID, never a filesystem path. It first tombstones the note and source family, removes related managed diaries through the original native delete-receipt path, filters the affected bounded source episodes, synchronizes an active CDS projection, and resets per-domain OneRing/cache projections. Managed preparation, source projection, response recording and capture replay honor these tombstones. The application must also withdraw the returned original source IDs from DSH activity/context and rotate its domain context epoch. This is logical withdrawal plus deletion of managed memory projections, not a claim of physical erasure of immutable original DSH logs or arbitrary semantic paraphrases in unrelated sources.
