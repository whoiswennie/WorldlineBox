> ### 为什么不能「码流原样」：HEVC 在这个壳里放不了
>
> 一开始按作者要求做了**零重编**（`-c:v copy`，码流 md5 与源片逐字节相同，21.94 MB）——
> 结果**画面定住不动**。同一台机器的两个引擎，同一段代码，答案完全不同：
>
> | 引擎 | HEVC hvc1/hev1 | H.264 avc1 |
> | --- | --- | --- |
> | **Edge 123**（同族；WebView2 就是它） | **空 = 不支持** | probably |
> | Chrome 154 | probably | probably |
>
> HEVC 在 Chromium 家族里是**平台相关的支持**，只有较新的 Chrome 才带；
> 而 DSH 的真壳是 **Electron**（`D:\deepseek\DeepSeek Harness.exe`），属于前一类。
> **我上一轮那条「真壳实测能播 HEVC」是假绿** —— 探针跑的是 Chrome 154，比环境宽松。
> 同类皮（星海之心）当年把 HEVC 那版「不走」、发行档做成 h264，正是同一个原因。
>
> 所以发行档换成 **H.264 纯转码**：**除了编码格式，什么都不动** ——
> 不缝合回接（硬切照旧，这是作者要的「不烘焙」）、不重定时、不缩放。
> 代价只有一次编码（SSIM 0.9936）。要无缝仍是 `bake-sm-loop.py bake`
> （CRF 20 实测 21.54 MB / 回接差 0.01 / SSIM 0.9930），再把 `_assets/` 里那个文件换掉。
> 逐引擎问这件事的工具有了：`scripts/probe-engine-codec.mjs`。

这一圈里是什么（实测逐帧，`_sm/analyze.py` 对**当前这一段**量的）：

| --- | --- | --- |
| 0.0 – 2.0s | 237.8 → 226.2 | 满幅宣纸，均匀到格子间差不到 3 级 |
| 2.0 – 6.0s | 226.2 → 148.4 | 墨从左侧漫进来 |

源片首帧是**宣纸白**（不是黑），所以**不能**照搬姊妹皮那条「尾部淡出到黑」：
淡到黑反而是一次「纸 → 黑」的硬切。**要无缝只有一条路：自交叠** ——
片尾 1.2s 与**首帧的克隆**交叉溶解（`bake` 子命令，见下）。

## 宣纸的磨砂：**程序化生成**的一张纸纹

用户要「工作区加入一点宣纸的磨砂纹理的感觉」。落法是**纹理**，不是模糊：

> 这一套的规矩是**一个 backdrop-filter 都不留** —— 磨砂会把背后的墨糊掉
> （实测同一帧的屏幕像素与解码帧相关性 0.996 → 0.87）。「磨砂」在渲染上有两个方向：
> **糊掉**（blur）与**起毛**（纹理）。宣纸要的是后者。

纹理由 scripts/make-sm-paper.py 生成（256×256 无损 WebP，18 / 25 KB 两张）：
细颗粒 + **两束交叉的长纤维**（各向异性比 1.59）+ 少量草茎，
全部在 **FFT 的循环卷积**里造 —— 左右上下天然接得上，
自检判据是「四条边界条带与整幅的均值差」= **0.0036 < 3/255**，不是「看起来对得上」。

两档浓淡，因为整框与工作区不是一回事：

| 档 | 铺在哪 | 纸白均值 α | 实测 Δ亮度 | 实测 Δ高频能量 |
| --- | --- | --- | --- | --- |
| soft | 整框（画面在大面积里透出来） | 2.9% | **+4.85 级** | **+0.473**（2.468 → 2.941，**+19%**） |
| strong | 工作区那一栏 | 5.7% | **+9.37 级** | **+0.569**（2.372 → 2.941，**+24%**） |
| strong | 侧栏 / 右栏 dock | 5.7% | +6.33 级 | +0.422（+10%） |

（取样框挑的是**没有字的那一段**：铺满文字的面高频基线本来就高，
纸纹那点增量会被淹没 —— 第一版取中段时「工作区那一栏」只有 +0.025，换成底下那段空白才是 +0.569。）

Δ亮度说明纸白生效；**Δ高频能量**才是「这是纸」的证据 —— 一层平的纸白也能抬亮度，
但整幅加常数**不改变局部标准差**，所以高频那一列的增量只可能来自纹理。
量具：scripts/probe-sm-paper.mjs（逐层 A/B：把该层的 background-image 置 none 前后各拍一张）。

它还有个很合方向的性质：**在纸相里几乎不变**（纸白本来就压在纸上，233 → 233），
所以「磨砂」只对墨色那一半生效。代价也量了：会话列上段正文 5.63 → **5.27:1**。

## 设计：**墨分五色，一点墨绿**（不是颜色替换；原话是「一点青绿」，墨绿化之后叫墨绿更准）

这一套的**骨头**继承自同一族的三条视频皮（把背景视频从 z-index:-2 抬到 1、
一个 backdrop-filter 都不留、暗色专用、那个 display: contents 压暗层 bug 的修法）；
**但装饰语言整套重做了**，依据同样是画面本身：

| | 未至之境 / 雨夜 / 星海之心（继承的） | **水墨丹青（重做）** |
| --- | --- | --- |
| 线的语汇 | 连续 1px 霓虹线 / 2px 点线（2 实 4 空） | **笔锋**：收笔渐变 + 两层不等距飞白（3/8 与 7/18） |
| 四角装饰 | L 形括号 / 星点 | **墨点**（实心 + 0.6px 羽化 + 1.2px 渐隐） |
| 状态标记 | 实心竖条 / 点轨 | **二段式：一枚墨点 + 一道笔锋** |
| 悬停反馈 | 斜向扫光 / 星芒光晕 | **水波扩散**（涟漪间距渐开、振幅渐衰）+ 一片**洇开**的墨 |
| 工作区文件夹 | 无 | **一道水墨渐变**：墨从左起笔、往右化开（96deg）；收起淡、悬停中、展开最浓（竹青 → 长发蓝黑 → 深墨蓝），实测一行内落差 **11.5 级** |
| 新会话 | 品牌色→暖金渐变实心 | 落墨木板 + **一滴墨落进水里**（落点 + 两处涟漪） |
| 圆角 | 柔圆角 / 3px 硬边 | **2px 裁纸边**（气泡是唯一一处 8px 软圆角） |
| 边框 | 引擎的 1px 边 | **画出来的边**：上下两道横笔（菜单 / 新会话） |
| 分区小标 | 暖金 / 亮星 | **宋体小字 + 一枚朱点** |
| 品牌行 | 竖棒 / 四芒星标 | **一方朱印**（11px 印面 + 横竖两道刻痕） |
| 用户轮 | 品牌色淡染 + 左缘暖竖条 | **朱批**：朱色笔锋 + 一层朱墨底 |
| 唯一实心 | 新会话（品牌色→暖金渐变） | **发送键**（墨绿；墨绿高光 → 墨绿，纸白图标） |
| 字体 | 等线 + 等宽统一 | **宋（正文）+ 楷（标题）+ 等宽只留给数字** |
| 首屏 | 什么都画 / 试过星图又撤 | **什么都不画** —— t=0 就是一张还没落墨的纸 |

**十六处语汇同时换了。** 三支颜色的纪律也是重排的：

> 骨架 = 孔雀蓝（线）· 活口 = **墨绿**（深的那支做面、浅的那支承字）· 钤记 = **朱红**（只给印记）· 警示 = 暖黄

## 水波与泼墨（第五轮追加）

用户第五句：「**新会话加入一个水波纹的背景**」+「**工作区的文件夹加入点纹理之类的水墨画感觉的效果**」。
两件事各有一张「照真的是怎么来的」的算法，不是画图案。

### 一 · 新会话：一滴墨落进水里

纯 CSS（没有新资产）。四条背景层：**落点**（一枚墨绿高光的墨点）+ **两处涟漪** + 那层斜向的墨底。
涟漪的形状照**真实的水波**来，两个细节缺一个就会读成靶心：

| 真实的水波 | 这里的做法 |
| --- | --- |
| 波圈越往外越疏（色散） | 每条环的半径差 3.4 → 7.4 → 12.2 → 17.8px，**间距在长** |
| 振幅越往外越弱（阻尼） | 透明度 0.30 → 0.20 → 0.13 → 0.08，**在衰减** |
| 两个波源会干涉 | **两处**涟漪（74% 30% 与 18% 76%），相位不同 |

**悬停 = 一圈水波扩散出去**（`@keyframes sm-ripple`）。实现上只用 **transform + opacity** 两个可合成属性：
环本身是那条静态的 border，动画只放大它 —— 若去动画 box-shadow 或 background，每帧都要重绘，
而这颗按钮就在侧栏里、悬停时最容易掉帧。
基态 **visibility: hidden + animation-play-state: paused**：不悬停时既不画也不跑。
（**暂停中的动画仍然会套用自己的那一帧**，所以不能只靠 opacity=0 藏它 —— 这一条踩过一次。）

### 二 · 工作区文件夹：**一道水墨渐变**（最终形态；这一节的方向改过三次）

这一处的去向值得完整记下来，免得下一个会话又绕回去：

| 轮次 | 做法 | 结果 |
| --- | --- | --- |
| 第五轮 | 贴一张**泼墨 / 水痕**纹理（程序化，9 KB，无缝） | 用户：「文件夹背景不好看」 |
| 第六轮 | 把那一行整个重画：签条 + 写出来的横笔底线 + 展开态一笔满行高的横墨（飞白） | 用户：「文件夹背景不好看搞一个水墨渐变得了」 |
| **第七轮** | **就一道水墨渐变** | 当前这一版 |

**为什么前两版不行，现在能说清了**：那一行只有 **34px** 高，里面还塞着图标 + 名字 +
两枚悬停按钮。**纹理需要面积**才读得出来 —— 34px 里那点水痕、那段飞白，都会被压成一个
噪点带；渐变不一样，它没有形状、只有**浓淡**，而浓淡不受高度限制。
（泼墨的生成函数留在 `make-sm-paper.py` 里，一条命令就能恢复：`--only blot`；
 资产本身从装机包里撤了，省 9 KB。）

做法：**墨从左起笔、往右化开**，96deg（不是 90deg —— 完全水平像一条色带，偏 6° 才有「铺」的手感）。
三个状态是同一条笔的三种浓淡，这是「墨分五色」在一行里的最小用法：

| 状态 | 渐变 |
| --- | --- |
| 收起 | 长发蓝黑 0.40 → 深墨蓝 0.18 → 0.05 → 透明 |
| 悬停 | 竹林墨青 0.50 → 长发蓝黑 0.30 → 深墨蓝 0.10 → 透明 |
| 展开 | 竹林墨青 0.80 → 长发蓝黑 0.66 → 深墨蓝 0.40（满行，最浓）+ 左端那二段式记号（墨点 + 竖笔） |

**为什么不竖着渐变**：竖渐变在 34px 里读成「一颗有厚度的按钮」（上亮下暗的立体感）——
那是 UI 的语言；横渐变才读成「一笔横着铺过去的墨」。
右栏「工作区文件」里的条目用同一条渐变（浓淡再收一点，那儿只有 ~24px）。

### 三 · 量过（scripts/probe-sm-paper.mjs，逐层 A/B）

| 层 | Δ亮度 | Δ高频能量 |
| --- | --- | --- |
| ⑤ 新会话的涟漪（纹理：把前 3 层压成 0×0 前后） | +1.55 | **+2.139**（8.064 → 10.203，**+27%**） |
| ⑥ 工作区文件夹的渐变（渐变：整层置 none 前后） | **−2.98** | +0.052（≈0，符合预期） |

两栏的符号相反，正好说明两种东西的区别：

* **纹理**抬亮度（纸/墨的颗粒叠在深底上），并且**改变局部标准差** —— 那一栏 Δ高频 就是证据；
* **渐变**的颜色是**墨色**（比侧栏的玻璃更深），所以它是**压暗**的 —— Δ亮度 为负是对的；
  而渐变不改局部标准差，Δ高频 ≈ 0 也正是应有的结果。**判据不能套用同一条。**

另外：展开那一行做了**横向剖线**（切 6 段），剖面 **60.16 → 48.66 = 11.5 级**，全部单调下降 ——
纯渐变本来就该是干净的斜线（第六轮那版是飞白，剖面会自己起伏，两版一比就看出区别了）。

涟漪那一栏的 Δ高频 特别大，是因为**环就是高频**：一串细环落在平坦的墨底上，
局部标准差必然跳一档。另外单独量了「它到底会不会动」——
悬停那颗按钮、隔 **420ms** 连拍两张：**12.5% 的像素在变**（平均差 2.1 级）→ 水波在扩散，不是一张静态图。

## 墨绿化：绿分成两档（第三轮追加）

用户第三轮原话：「这个绿色不太好看，改成墨绿色呢」。做法是同色相（H 137°，就是原值那个绿）
**降饱和 + 压明度**：#3FB460（S 0.65 / V 0.71）→ **#3D6649**（S 0.40 / V 0.40）。

**但深色面板上墨绿当字用只有 2.28:1** —— 所以绿在这一套里从此是两档，和蓝那一族的
「牌子 / 高光端」同一套纪律：

| 档 | 色值 | 面板上 | 只用在 |
| --- | --- | --- | --- |
| 墨绿（面） | **#3D6649** | 2.28:1（不承字） | 发送键的实心、墨点、笔锋、下划线、悬停的底与边、进度环轨道 |
| 墨绿高光（字） | **#6FA87F** | **5.41:1** | 链接、悬停时的文字与图标、焦点环、进度环的进度段、成功态 |

连带改了四处「别人看不见的地方」：

1. **发送键的前景色翻了一次**：底从亮绿变成墨绿之后，原来的墨色箭头只有 3.0:1 ——
   改成**纸白图标**（5.12:1）。一颗墨绿的钮上挑一笔白，也正是「墨上留白」。
2. **焦点环 / 进度环 / 标签下划线走浅的那支**：它们是信息，不是面。
3. **代码块左缘、交付卡左缘、工具提示的框走浅的那支**：2px 的痕迹压深底上，深墨绿等于没画。
4. **徽章那种「深底 + 深框 + 浅字」的三件套**保持深底深框（面）+ 浅字（字）。

**覆盖率量具又被抓到一次「只读了一半」**：它认得墨绿，但不认得墨绿高光，
于是「只有一圈浅绿描边、没有别的面」的元素被判成 1 处 BARE。
把两支都加进特征色（仍然是从皮肤读的）之后回到 0 BARE。

## 灰墨化：把界面从「夜蓝」拉向「灰墨」（第二轮追加）

用户第二轮的原话是「这个配色我也要水墨风的配色」，选的是**改配色层**。
做法不是换色，而是**洗彩度、明度一点都不动**：把每一支「面」朝**相对亮度相同的灰**混 k。

| 角色 | 用户原值 | 生效值（灰墨化） | 彩度 | 相对亮度 |
| --- | --- | --- | --- | --- |
| 画布 | `#0F1A30` | **#171A20** | 0.687 → 0.281 | 0.0105 → 0.0103 |
| 面板 | `#152747` | **#222730** | 0.704 → 0.292 | 0.0207 → 0.0200 |
| 更深一档 | `#1B2A44` | **#262A31** | 0.603 → 0.224 | 0.0231 → 0.0229 |
| 抬起 | `#254570` | **#3D444E** | 0.670 → 0.218 | 0.0582 → 0.0568 |
| 深青底 | `#1E3A44` | **#2D383C** | 0.559 → 0.250 | 0.0372 → 0.0371 |
| 结构线 | `#35678C` | **#4D6576** | 0.621 → 0.347 | 0.1235 → 0.1219 |
| 牌子 | `#6F9CB5` | **#7D9AAA** | 0.387 → 0.265 | 0.3049 → 0.3037 |
| 高光端 | `#4A7FB0` | 洗 30% | — | — |
| 宣纸白 / 浅灰墨 / 朱红 / 暖黄 | 原值 | **原值不动** | — | — |

**为什么不是 HSV 降饱和（S × k）**：那保住的是**最大通道**而不是亮度 ——
暗蓝一降饱和三个通道一起抬上来，画布亮度直接翻倍（#0F1A30 → #232730，L 0.0105 → 0.0202），
界面整体发灰发亮、字反而更难读。**保亮度**才是「把蓝洗掉」的正确做法。

好处是**对比度关系原样保留**（每一支 ΔL ≤ 0.002）：
正文/面板 11.57 → **11.67:1**、正文/画布 13.50 → 13.57、次级/面板 7.85 → 7.91、
牌子/面板 5.02 → 5.05、墨绿/面板 5.60 → 5.65、朱红/面板 3.53 → 3.56。

**14 支原值仍然全部在场**：它们既是 inkify 的输入（写在源码里、带着注释），
也是所有强调色 —— 只有「面」那一族从夜蓝变成了灰墨。

## 暗色专用

底片 74% 的时间停在墨上，所以面板就是墨色的纸；浅色主题渲染同一套暗色 ——
系统切浅色时界面不会翻白，翻白的瞬间那块视频就成了一块孤岛。
生成器另外钉了 :root 上的 color-scheme: dark，原生控件（滚动条、回到底部那颗圆钮）也跟着暗。
