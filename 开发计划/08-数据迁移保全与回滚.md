# 数据迁移、保全与回滚

## 首要原则

当前已经整理的表情包、图片、GIF、音视频、文本引用和相关 Tag 是用户资产。重构不得通过重新 seed、删除旧数据库、重建内置资源或清空伙伴目录破坏这些内容。

迁移采用“盘点 → 只读备份 → 隔离转换 → 双向核验 → 原子切换 → 保留回滚点”的单向转换，不采用长期双写和双运行时。

## 迁移前盘点

为每个公共和伙伴私有 scope 输出只读报告：

- 资产总数、启用数、禁用数、内置数和用户新增数。
- blob、link、builtin 等来源类型数量。
- MIME 分布、总字节数和对象文件数量。
- 每个资产的稳定 ID、标题、说明、Tag、转写、作用域、enabled、built-in、source、bytes、duration、usage count、last used、created、updated。
- blob 实际路径、文件存在性、大小和 SHA-256。
- 重复哈希、孤立对象、缺失对象和损坏记录。
- 伙伴头像、内置种子和恢复原版资源的关联。

盘点工具只读，结果保存到用户指定备份目录和重构测试报告，不在旧库中写标记。

## 备份

正式迁移前生成：

```text
backup/
├─ pre-agent-vault-reference-data/
├─ inventory.json
├─ checksums.sha256
└─ migration-environment.json
```

备份包含旧 SQLite、WAL/SHM 一致性快照、对象目录、伙伴预设资源和盘点清单。备份完成后重新校验哈希。迁移代码不得自动删除这个备份；清理只能由用户在迁移验收后显式执行。

## 转换映射

旧资源字段至少按以下规则转换：

| 旧字段 | 新字段 |
| --- | --- |
| `id` | 资源稳定 ID，冲突时记录映射 |
| `scope` | Agent Vault 或 shared 归属 |
| `enabled` | 可迁移语义状态 |
| `title` | 标题 |
| `description` | 说明 |
| `tags` | 语义 Tag 候选，经规范化但保留原标签 |
| `transcript` | 转写/正文 |
| `mime_type` | MIME 系统属性 |
| `bytes` | 对象大小校验 |
| `duration_ms` | 媒体时长 |
| `source` | `resource://` 对象或受管外部链接 |
| `built_in` | origin/bundled 属性 |
| `usage_count`、`last_used_at` | 可选运行统计种子，不改变语义 |
| `created_at`、`updated_at` | 创建和更新历史 |

旧 `表情包`、`图片`、`gif`、`public` 等混合标签先原样保留在迁移记录，再转换为 `role`、MIME、scope 等系统属性和语义 Tag。任何自动规范化都必须保留原标签别名，不能导致检索丢失。

默认为现有可表达资源增加 `role: expression`。头像和角色形象增加 `role: appearance`，但不能因为文件是图片就自动认定为头像。

## 隔离转换

迁移写入新的 staging Vault：

1. 创建标准目录和 manifest。
2. 流式复制或复用每个资源对象并重新计算哈希。
3. 写入资源记录、日期导入清单和 Tag 映射。
4. 为内置伙伴生成 self、appearance、memory 和 resource 入口。
5. 构建新派生索引、缩略图和媒体预览。
6. 运行资源打开、Range、MIME 回退和 `express` 查询测试。

整个过程中旧运行目录保持只读可用。

## 核验

迁移核验必须同时检查：

- 每个旧资产都有新资源 ID 或明确的失败记录。
- blob 哈希和字节数完全一致。
- 标题、说明、转写、enabled、scope 和原始 Tag 没有静默丢失。
- 公共和各伙伴私有数量分别一致。
- 内置和用户自定义资源可区分。
- 禁用资源不会进入 Agent 查询，但在管理界面仍可见。
- 每种 MIME 至少抽样可渲染；全部资源记录可 stat。
- 现有伙伴在 `express` 中能够命中其原有资源。
- 头像和角色形象仍显示正确。

迁移报告列出成功、警告、失败、重复、缺失和人工确认项。失败数不为零时禁止原子切换。

## 原子切换

核验通过后：

1. 停止相关 Vault 写入并等待当前资源操作结束。
2. 记录最终旧库增量并补迁移。
3. 再次运行数量和哈希核验。
4. 通过目录 rename 或配置指针原子切换到新 Vault。
5. 启动新运行时并执行冒烟测试。
6. 保留旧目录和备份，不自动删除。

运行时不长期读取旧库。切换后所有正式写入只进入新 Agent Vault。

## 回滚

满足以下任一条件立即回滚：

- 资源数量或哈希不一致。
- 伙伴身份、头像或私有 scope 错配。
- 新 UI 无法查看一类旧资源。
- `express` 不能查询旧表情包。
- 新运行时产生不可解释的资源损坏或权限泄漏。

回滚通过停止新写入、保留新 Vault 诊断快照、恢复旧配置指针和旧目录完成。回滚不把新格式数据反向写回旧库，避免二次破坏。

## 旧逻辑清理

只有迁移、回滚演练和最终验收通过后，代码中才能删除旧 Reference Vault 和旧角色数据路径。用户数据备份不随代码清理删除。保留一次性迁移命令、格式说明和诊断报告读取器，不保留旧 UI、旧工具、旧提示注入或双写适配器。
