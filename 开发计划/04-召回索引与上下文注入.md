# 召回索引与上下文注入

## 目标

召回系统同时提供：

- 快速方向：在很小延迟和上下文成本下告诉 Agent 相关知识可能在哪里。
- 深度探索：以命中的目录、页面、章节或实体为原点，渐进读取相关邻域。

默认不依赖 embedding。HNSW 不作为核心索引，因为 Vault 已经拥有目录、Tag、实体、Wiki 链接和反向链接组成的可解释导航图。

## 分层检索对象

索引对象不是只有整篇文档：

- Vault 域卡
- 目录卡
- 页面卡
- 章节卡
- 实体与别名卡
- Tag 注册项
- 能力卡
- 资源记录
- 短期 dirty 卡

每个目录维护 `INDEX.md` 或等价可移植地图，描述标题、别名、主题、实体、子节点和摘要。根目录只汇总直接子目录；变更只更新页面、所在目录和必要祖先，成本与树深有关，不与全库文档数线性相关。

## 索引实现

SQLite FTS5 是默认本地派生实现，但必须满足：

- 删除数据库后能够从 Vault 完整重建。
- 索引按 Vault、域、目录、文档、章节、revision 和权限分区。
- 中文及混合语言使用 trigram；拉丁词、数字和字段检索保留词项能力。
- 用户编辑器保存单文件时同步更新最小文档卡和 dirty overlay，正文索引可随后完成。
- 大批量导入进入增量队列，查询同时合并已提交索引和 dirty overlay。
- 外部修改通过文件监听器和启动校验补录。

未来允许替换索引提供方，但工具契约和真源格式不依赖 SQLite。

## 传统 NLP 组合

召回评分组合以下信号：

1. Unicode NFKC、大小写、全半角和可选简繁归一化。
2. 实体、标题和别名精确命中。
3. Canonical Tag、Tag 别名、多 Tag 覆盖、父级和一跳相关 Tag。
4. FTS5 trigram 子串匹配。
5. BM25F 字段加权。
6. 字符 n-gram 或词项 TF-IDF 稀疏余弦补分。
7. 标题和别名有限编辑距离纠错。
8. 路径、父子目录、同级目录、Wiki 链接和反向链接邻近度。
9. 来源稳定度、成熟度和 revision 新鲜度。
10. 基于路径和 Tag 的结果多样化，避免 Top-K 全部来自一个页面。

字段权重顺序为：实体/别名和标题最高，Tag、目录名和章节标题次之，摘要居中，正文最低。权限和域过滤在评分前执行。

## Tag 系统

Tag 注册表记录：

```yaml
id: tag://domain/anime
label: 二次元
aliases: [ACG, 动漫文化]
parents: [流行文化]
related: [动画, 漫画, 游戏, 轻小说]
description: 日本动画、漫画、游戏及相关亚文化语境
```

Tag 分为语义 Tag 和系统属性。`开心`、`庆祝`、`漫画` 属于语义；MIME、scope、enabled、role 属于结构化过滤，不能用机械字段污染语义相似度。

Agent 查询可以提交必需 Tag、可选 Tag、排除 Tag、实体和多组 probe。Tag 展开默认最多一跳，并限制每个节点的扩展数。

## 快速召回工具

不同域使用不同工具：

```text
knowledge.recall
procedure.recall
resource.find
self.inspect
entity.inspect
```

`knowledge.recall` 返回少量方向卡：

```yaml
path: vault://memory/long/people/八千代/music.md
kind: page
confidence: high
matched:
  - alias: 八千代
  - tags: [音乐, 偏好]
  - heading: 最喜欢的歌曲
suggested_actions:
  - read_section: 最喜欢的歌曲
```

结果必须解释命中原因、知识成熟度、是否存在短期修订或冲突，以及下一步建议。默认不返回全文。

## 查询探针

Agent 在 Skill 指导下最多进行有预算的多轮碰撞：

1. 用户原始表达。
2. 动作、对象、产物和领域拆分。
3. 别名、上位概念、相关 Tag 和中英文变体。
4. 目标域目录卡浅扫。

默认上限示例：

```yaml
max_probe_rounds: 4
max_results_per_round: 5
max_directory_expansions: 3
```

查询“设计连环漫画”可以产生“漫画 分镜 连续画面”“绘画 视觉叙事 角色一致性”“storyboard comic”等 probe。仍未命中时只能说没有找到已建立并验证的能力或知识，不能把基础模型推理能力冒充已存能力。

## 深度探索工具

`knowledge.explore` 必须从锚点开始：

```yaml
anchor: vault://memory/long/music/
goal: 查清八千代喜欢的具体版本和来源
radius: 1
budget:
  max_pages: 8
  max_sections: 16
  max_tokens: 12000
```

读取顺序为目录地图、直接子节点摘要、高相关章节、Wiki 链接、反向链接、父级和同级、来源、历史和冲突。未完成时返回 continuation，由 Agent 决定是否扩大半径，不能自动无限扩展。

## 编译印象与上下文注入

每个伙伴维护一个有 revision 的编译印象快照。每轮只组合：

- 不可淘汰的核心身份。
- 已启用的人格和交流方式。
- 已启用且仍有效的当前情绪、状态和关系摘要。
- 最近明确的短期修订。
- 与当前问题匹配的少量常用认知入口。
- 与当前任务相关的能力和工具路线。
- 本轮快速召回产生的少量方向卡。

不注入全部常用卡、全部 Tag、全部资源候选、全部能力卡或完整目录。快照稳定时保持可缓存前缀；只有启用模块或 revision 变化才更新。

## 反馈

记录以下无模型反馈：

- 候选是否被 Agent 打开。
- 读取后是否被回答引用。
- 用户是否纠正答案。
- 工具是否找到预期路径。
- 是否产生无关上下文。
- 查询耗时和注入 token。

技术缓存可实时更新；认知常用记忆只在检查点根据衰减频率、人格关联、真实使用成功、重复度和 token 成本阶段性调整。
