# 印象卡与伙伴运行时

## 结构化自我

逻辑上是一张伙伴印象卡，物理上按变化频率拆分：

```text
self/
├─ identity.md
├─ appearance.md
├─ personality.md
├─ communication.md
├─ worldview.md
├─ interests.md
├─ emotion.md
├─ state.md
├─ common-memory.md
├─ capabilities.md
├─ expression.md
└─ relationships/
```

每个条目使用共同控制字段：

```yaml
id: cognition-anime
enabled: true
inject: contextual
user_locked: false
stage: established
stability: slow
confidence: high
summary: 熟悉并喜欢二次元文化
tags: [domain:二次元, affinity:喜欢]
routes:
  - vault://memory/long/interests/anime.md
evidence:
  - vault://memory/long/interests/anime.md@rev-12
last_changed_at: 2026-08-20
next_review_at: 2026-09-20
```

`enabled` 控制条目是否有效，`inject` 控制是否参与对话，`user_locked` 控制 Agent 是否可自治修改。关闭参与对话不能删除数据。

## 通用维度

印象 UI 至少覆盖：

- 核心身份与职责
- 视觉形象
- 人格、价值观和行为边界
- 语言与表达方式
- 认知世界观
- 兴趣与偏好
- 当前情绪
- 当前运行状态、目标和关注
- 人际关系网
- 常用记忆与认知入口
- 能力、方法和限制
- 表达媒介与资源能力

所有维度可为空。工具型机器人可以没有情绪，但仍可使用状态、目标、能力和边界。

## 形象与实体资料

`appearance.md` 区分：

- `canonical-illustration`：角色官方设定形象。
- `photo`：用户声明的真实照片。
- `avatar`：身份头像，不推断真实外貌。
- `symbolic`：风景、动物、标志等象征图。
- `unspecified`：无法判断代表程度。

记录主要资源 ID、说明来源、是否代表实际外貌、可见范围和 revision。没有图片时返回“尚未提供视觉形象”，不能把 UI 占位图当作人物形象。

房间成员列表只注入名称和 ID。需要了解对方形象时调用 `entity.inspect(fields=['appearance'])`，按权限返回结构化说明和必要图片，不在每轮加载所有头像。

对方公开资料与伙伴主观印象分开：对方形象属于对方公开 `self`；当前伙伴对其感受属于当前伙伴的 `self/relationships/<entity>.md`。任何伙伴都不能修改另一个伙伴的自我资料。

## 情绪与状态

情绪记录名称、正负倾向、强度、对象、原因、开始时间、衰减、影响范围和限制。一次争吵可以立即产生短期情绪状态，但关系或人格变化要经过累积和检查点。

提供对话模式：

- 完整伙伴模式
- 中性任务模式
- 仅核心身份
- 用户自定义模块

中性任务模式可以暂时不注入情绪和关系张力，但保留状态数据。

## 关系

每段关系记录对象、关系类型、熟悉度、信任、亲近、张力、共同经历、边界和未解决事件。原始互动先成为关系事件；聚合印象只在重要事件或维护检查点更新，并保留变化原因。

## 能力自知

印象卡只注入少量能力入口，不注入全部方法正文。能力条目必须区分：

- 运行时工具真实存在。
- 保存了方法或经验。
- 经过测试并认证。
- 缺少依赖或需要复测。

伙伴需要完成任务时调用 `procedure.recall`，不能仅凭印象摘要执行复杂方法。

## 伙伴管理页面

现有伙伴页改为 Agent Vault 的结构化投影：

- 顶部：形象、名称、身份摘要、当前心情、状态、关系概览、冻结状态和运行模式。
- 模块区：身份、形象、人格、语气、世界观、兴趣、情绪、状态、关系、常用记忆、能力和表达。
- 每个模块：参与对话、自治修改、用户锁定、编辑、变化原因、历史和恢复。
- 所有保存直接写入对应 `self/*.md`，不再维护旧角色字段真源。

创建伙伴向导直接生成标准 Agent Vault，要求最少身份和形象选择，其他维度可跳过。导入伙伴入口接受 Worldline Agent Package，完成校验后出现在同一列表。

## 伙伴运行时

伙伴独立持久 Agent 会话继续保留。运行时改为：

1. 根据房间和伙伴 ID 挂载对应 Vault。
2. 读取冻结策略和编译印象 revision。
3. 注入有界伙伴印象、房间记录和本轮任务。
4. 注册该伙伴授权域的自我、知识、能力、资源和实体工具。
5. 快速召回只在信号变化时产生有界候选。
6. 所有写操作通过 Vault 服务和 Host 守卫。

伙伴的头像和账户资料更新只改变对应 Vault 模块和 UI 投影；不会通过重建独立角色提示词形成第二真源。
