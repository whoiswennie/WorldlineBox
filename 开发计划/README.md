# Agent Vault 与虚拟伙伴整体重构计划

## 计划性质

本目录定义 WorldlineBox 下一阶段的单一完整重构目标：把虚拟伙伴、角色资料、知识、记忆、能力、经验、资源、检索、上下文感知、自治技能和管理界面统一为可冻结、可验证、可导入导出的 Agent Vault。内部步骤只表示工程依赖和验收顺序，不代表允许交付缺少关键能力的多期半成品。所有必需工作完成并通过最终验收后，本次重构才算结束。

重构前基线为 Git 提交 `e1da103718301e60410914df9fb46960747a8689`。该基线已推送到 `origin/main`，用于回溯现有行为和保护当前资源。

## 总目标

- 每个通用 Agent 或虚拟伙伴拥有一套独立、文件原生、可整体迁移的 Agent Vault。
- 伙伴管理页显示并编辑同一套 Vault 中的结构化自我印象，不再维护第二份角色卡真源。
- 短期、中期、长期记忆具有不同的写入、整理、验证和晋升方法，短期记忆保存后立即可召回。
- 常用认知以稳定、分阶段变化的印象条目参与对话；技术缓存与人格认知严格分离。
- 陈述性知识、程序性经验、结构化自我和资源资产属于同一个 Vault，但使用不同的检索域、工具和呈现器。
- Markdown、结构化清单和二进制对象是可迁移真源；SQLite FTS5 等组件只能作为可删除、可重建的派生索引。
- 默认不引入 embedding 模型、向量 API 或第三方语义服务。召回以层级目录、Canonical Tag、别名、FTS5 trigram、BM25F、字符 n-gram、稀疏 TF-IDF、链接邻域和 Agent 查询探针为基础。
- Agent 日常通过专用 Vault 工具访问数据，不依赖 Bash 直接管理真实目录。
- 用户能够冻结整个 Vault 或特定领域，Host 必须在工具执行层强制只读。
- 当前已经整理的表情包、图片、音视频、文本资源、Tag、启用状态和内置资源必须完整迁移，不允许以重构为理由删除或覆盖。

## 不在本次重构中接受的方案

- 不保留新旧两套角色卡、知识库或引用库运行时并行。
- 不把全部知识、全部 Tag、全部资源候选或全部 Skill 注入模型上下文。
- 不用普通 `knowledge.search` 搜索或修改 `self/`。
- 不把 SQLite、索引缓存、绝对路径或某个 embedding 模型产生的向量作为不可替代真源。
- 不使用一次性全库 LLM 总结作为大规模整理方法。
- 不让“查询命中”直接触发人格修改、长期记忆覆盖或能力认证。
- 不以通过少量演示用例代替迁移完整性、召回质量、权限隔离和规模测试。

## 完成定义

以下条件必须同时满足：

- 新 Agent Vault 格式、VFS、权限、索引、工具、Skill、UI、导入导出和迁移全部进入正式运行路径。
- 旧运行时逻辑已删除，不存在长期兼容分支和双写。
- 当前本地引用资源经过备份、转换、数量和哈希核对，并在新资源画廊中可查看和使用。
- 新伙伴可从零创建；现有伙伴可迁移；完整包可在不同绝对路径导入并正常运行。
- 冻结策略、域隔离、revision 防覆盖、导入安全和隐私导出通过测试。
- 快速召回、深度探索、大批量整理和上下文预算达到本计划的验收门槛。
- 所有相关 Runtime、Client、CLI、Desktop、迁移、性能和端到端测试通过。
