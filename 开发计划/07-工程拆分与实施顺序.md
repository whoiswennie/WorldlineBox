# 工程拆分与实施顺序

## 单一里程碑

所有步骤在一个完整重构分支中完成，并以最终端到端验收作为唯一交付条件。步骤按依赖排序；某一步通过只表示可以继续开发，不表示可把缺少后续能力的系统作为完成版本发布。

## 目标包结构

建议新增能力域：

```text
packages/agent-vault/
├─ agent-vault/                    # 抽象服务、类型、事件和错误码
├─ agent-vault-local/              # 本地 VFS、真源、事务、监听和历史
├─ agent-vault-index-sqlite/       # 可重建 FTS5/Tag/链接派生索引
├─ agent-vault-portable/           # 导入、导出、完整性和包格式
├─ agent-vault-governance/         # 队列、阶段、审计和检查点
└─ agent-vault-awareness/          # 编译印象、快速召回与上下文贡献

packages/tools/
└─ tool-agent-vault/               # self/knowledge/procedure/resource/entity 工具

packages/skill/
└─ skill-agent-vault/              # 平台方法论 Skill Suite

packages/client/
└─ ui-agent-vault/                 # 统一 Vault 工作台和数据客户端
```

`ui-virtual-companion` 保留伙伴列表、房间、独立伙伴会话、聊天呈现和伙伴管理入口，消费 Agent Vault 服务和 UI 组件；通用 Vault 引擎从该包移出。

实际包名在编码前按现有包约束核验，但职责边界不得重新揉回一个大型 UI 插件。

## 当前实现迁移归属

| 当前实现 | 目标归属 | 最终处理 |
| --- | --- | --- |
| `packages/client/ui-virtual-companion/src/knowledge-vault.ts` | Agent Vault local provider 与索引 provider | 拆出通用逻辑，旧类删除 |
| `packages/client/ui-virtual-companion/src/reference-vault.ts` | Agent Vault resource 域与一次性迁移器 | 迁移数据后删除独立 Vault 运行时 |
| `packages/client/ui-virtual-companion/src/resource-awareness.ts` | Agent Vault awareness | 改为编译印象和域内 recall cards |
| `packages/client/ui-virtual-companion/src/reference-expression.ts` | resource/express 策略 | 保留晚绑定思想，改用统一资源域 |
| `packages/client/ui-virtual-companion/src/actor-runtime.ts` | 伙伴运行时消费者 | 保留独立会话，改用 Vault 授权和快照 |
| `packages/client/ui-virtual-companion/src/client/KnowledgeVaultPage.tsx` | `ui-agent-vault` | 重构为统一工作台，伙伴包只注册入口 |
| `packages/client/ui-virtual-companion/src/client/VirtualCompanionPage.tsx` | 伙伴管理消费者 | 重构为结构化印象和导入入口 |

迁移期间允许在重构分支中存在短时适配层以完成测试，但最终提交前必须删除双真源、双写和旧提示注入。

## 步骤 1：冻结规范与测试夹具

- 将本计划转化为 TypeScript 契约草案、目录 schema、错误码和权限矩阵。
- 建立小型、中文别名、复杂 Wiki、大批量短期、资源媒体和损坏包夹具。
- 固定当前资源基线统计和哈希清单。
- 编写迁移前只读盘点工具，不修改用户数据。

退出条件：格式、域、URI、revision、冻结模式和迁移保全规则都有可执行测试描述。

## 步骤 2：Agent Vault 抽象服务

- 定义 Vault ID、URI、Node、Document、Asset、Tag、Policy、Revision、Lease、Query、RecallCard 和 ExportManifest。
- 定义稳定错误码：越界、只读、revision 过期、未知域、依赖缺失、损坏包、链接失效等。
- 定义 Cordis 服务、生命周期、事件和权限钩子。
- 不在抽象包中导入本地文件、SQLite、虚拟伙伴或 Client。

退出条件：Host、工具和测试可针对内存假实现编译运行。

## 步骤 3：本地 VFS 与文件真源

- 实现 `vault://`、`shared://`、`agent://`、`resource://` 和 `temp://`。
- 实现路径归一化、containment、符号链接防逃逸、Windows 文件名规则和原子写入。
- 实现 revision、history、受管移动、Wiki 链接、反向链接和真实路径租约。
- 实现文件监听、启动核对、dirty manifest 和外部写入 reconcile。
- 实现总冻结和分域冻结的 Host 守卫。

退出条件：不同真实根目录挂载结果一致，所有越界和只读写入均被 Host 拒绝。

## 步骤 4：标准 Agent Vault 与伙伴自我

- 定义 manifest、policy、self 模块、memory、procedures、resources、maps、queue、tests 和 history。
- 把内置伙伴资料、头像和人设改写为标准 Vault 种子。
- 实现结构化 self 读写、模块开关、用户锁、变化提案和编译印象快照。
- 实现实体公开资料和伙伴主观关系隔离。
- 删除旧角色字段作为运行时真源的路径。

退出条件：新建伙伴只从标准 Vault 启动；角色页和伙伴 Agent 读取同一 revision。

## 步骤 5：索引、Tag 与快速召回

- 实现目录卡、页面卡、章节卡、实体别名、Canonical Tag 和链接图提取。
- 实现 FTS5 trigram、BM25F、字段权重、Tag 组合和局部邻域评分。
- 实现 dirty overlay，使用户保存后无需等待批处理即可召回。
- 实现 `knowledge.recall`、`procedure.recall`、`resource.find`、`self.inspect` 和 `entity.inspect`。
- 用域预过滤和权限预过滤阻止跨域、跨伙伴泄漏。

退出条件：召回夹具达到目录、页面和章节指标；普通知识检索不能命中 `self`。

## 步骤 6：深度探索与上下文感知

- 实现有界目录、章节、链接、来源、历史和冲突探索。
- 实现 continuation 和明确的读取/token/半径预算。
- 重写当前 resource awareness，使其消费编译印象和新的 recall cards。
- 删除开场资源 Tag 目录注入。
- 保持伙伴稳定提示前缀和只在信号/manifest 变化时注入候选。

退出条件：大知识夹具中不会向模型发送全目录或全正文，且可从方向卡继续找到完整证据。

## 步骤 7：三阶段记忆与治理队列

- 实现短期分段、amendment、即时召回和批次清单。
- 实现可恢复任务、幂等键、检查点、预算和失败分类。
- 实现中期规范化、冲突、重复候选和局部 Wiki 更新。
- 实现长期晋升、版本保留、召回考试和回归测试。
- 实现认知常用记忆的阶段变化，不把技术缓存频率直接写入人格。

退出条件：十万条短期夹具可中断、恢复、分批完成，不出现单次无界上下文或重复提交。

## 步骤 8：能力与经验

- 实现能力卡、方法、经验、依赖和测试格式。
- 实现 Agent 查询探针和多次有预算碰撞。
- 实现经验记录、方法改进和能力认证工作流。
- 运行时能力注册表与 Vault 能力卡交叉检查，缺少工具时明确降级。

退出条件：别名和 Tag 能把“画漫画”召回“连环漫画设计”；没有成熟能力时不会伪造认证结果。

## 步骤 9：统一资源系统和零损迁移

- 把现有资源数据库盘点并备份。
- 把每项资产转换为资源记录和内容寻址对象，保留 Tag、说明、转写、作用域、enabled、built-in、来源和必要使用状态。
- `express` 改为查询统一 `resource` 域并按 role 晚绑定。
- 删除独立 Reference Vault 运行时和标签开场注入。
- 验证全部旧资源在新画廊可见、可预览、可启禁用和可表达。

退出条件：迁移报告数量、哈希和关键元数据一致；旧目录仍保留备份，尚未执行破坏性清理。

## 步骤 10：统一管理 UI

- 新建 `ui-agent-vault` 的总览、文档、记忆、能力经验、资源、Tag 与关系视图。
- 保留并迁移现有资源卡片画廊和 MIME 渲染器。
- 增加资源表格、批量操作、结构化编辑抽屉和懒加载。
- 重构伙伴页为结构化印象卡，增加模块开关、锁定、冻结、历史、导入和导出。
- 所有 UI 经 Remote/API 调用 Host，不直接访问 Node 文件系统。

退出条件：不存在“知识文档/引用库”两套产品入口；不同数据类型在同一工作台使用恰当视图。

## 步骤 11：Skill Suite 与预设集成

- 按计划实现渐进加载 Skill 族、引用资料和测试。
- 在通用 Agent 和虚拟伙伴 Preset 中安装最小 orientation 与按需技能入口。
- Skill 使用新的领域工具和 URI，不包含 Bash 维护教程或绝对路径。
- 用模拟对话测试记住、整理、晋升、检索、能力发现、自我查看、自我修改、冻结拒绝和资源表达。

退出条件：Agent 能根据任务选择正确 Skill 和工具，所有越权尝试被 Host 阻止并获得可理解反馈。

## 步骤 12：导入导出与安全

- 实现完整迁移包和可分享角色包。
- 实现快照、校验和、隔离解压、Zip Slip/压缩炸弹防护、依赖检查、ID 冲突处理和索引重建。
- 在新增伙伴 UI 提供导入入口、预览、进度、失败恢复和报告。
- 用不同绝对路径和新的 Agent ID 完成往返测试。

退出条件：包移动到另一目录后无需路径改写即可运行；私密导出策略和依赖降级正确。

## 步骤 13：删除旧逻辑并完成全量验收

- 删除旧角色资料真源、旧 KnowledgeVault/ReferenceVault 产品分割、旧标签注入和不再使用的 API/UI。
- 删除临时双写、运行时兼容读取和迁移开发开关。
- 保留独立的一次性迁移命令和只读迁移报告，不保留双运行时。
- 更新架构文档、包 README、Preset、生成目录和测试文档。
- 执行 [最终验收](09-验证基准与最终验收.md)。

退出条件：所有最终门槛同时通过，才能合并和发布。
