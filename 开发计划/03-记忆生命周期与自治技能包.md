# 记忆生命周期与自治技能包

## 两条正交维度

记忆成熟度与激活度分开管理：

```text
成熟度：短期 → 中期 → 长期
激活度：常驻 → 高频 → 普通 → 冷藏
```

短期记忆可以立即高频；长期知识也可以长期冷藏。技术查询缓存不属于认知激活度，不能改变人格。

## 短期记忆

短期记忆负责“刚刚要求记住就能立即召回”。保存流程必须同步完成：

1. 忠实记录原意、来源、时间、作用域和知识类型。
2. 分配稳定 ID 和 revision。
3. 写入有界短期分段。
4. 生成轻量快速召回卡并更新 dirty overlay。
5. 返回可检索确认，不等待整理和长期晋升。

短期记录不直接覆盖长期正文。对已有知识的修改先保存为 amendment；召回时根据类型决定优先级。用户意图和个人偏好通常以最新明确修订优先，专业事实则以“候选修订”呈现，验证前不能静默推翻长期结论。

### 分段与规模

```text
memory/short/YYYY/MM/DD/batch-id/
├─ manifest.md
├─ segment-0001.md
├─ segment-0002.md
└─ progress.md
```

每个分段设置条目数、字节数和估算 token 上限。短期状态写入 manifest，不通过重写巨型文件更新。十万条积压必须能分页普查、分批处理和断点续跑。

## 中期记忆

中期记忆表示完成过一轮规范学习但仍可能调整的知识：

- 已确定主题、类型、来源和目标目录。
- 已进行标题、Tag、别名和实体归一化。
- 已合并明显重复并保留原始证据。
- 已建立 Wiki 链接、关系和待解决冲突。
- 已生成目录卡、召回探针和初步测试。
- 允许不完整、观点并存和后续重构。

短期到中期的整理只加载一个有明确预算的任务批次及其相关知识邻域。

## 长期记忆

长期记忆是已发布的稳定知识版本，不是永久不可改：

- 结构完整，来源可追溯。
- 未解释冲突为零，或明确表达多观点和适用条件。
- 标题、别名、Tag、目录和 Wiki 路由能正确召回。
- 关键事实、概念、关系、来源和负面召回测试通过。
- 修改产生新 revision，旧 revision 进入 history 或标记 superseded。

晋升不能只依赖时间或一段摘要；必须经过验证和测试。

## 大规模整理方法

整理管线采用可恢复的分治流程：

1. 元数据普查：数量、日期、标题、Tag、来源、哈希、大小和状态，不读全部正文。
2. 确定性分组：来源批次、实体、Canonical Tag、目录、字符 n-gram、SimHash/MinHash 候选。
3. 抽样预习：读取少量代表条目，制定子任务而非立即改写长期知识。
4. 有界学习：每个任务设置最大文档、章节、token、写入数和持续时间。
5. 局部整合：只读取和更新命中的主题子树。
6. 验证提交：检查来源、重复、冲突、revision、链接和召回测试。
7. 写入检查点：记录已处理范围、失败原因和后续任务。

任务必须幂等：重复执行同一 `task_id` 不会重复写入知识。失败或中断后从最近检查点继续。

全局维护只做低成本健康统计、链接检查、索引校验和抽样测试；正文重组以变更子树、热点主题和失败测试为触发，不周期性全库 LLM 重写。

## 印象变化阶段

认知印象采用：

```text
candidate → forming → established → core
                         ↓
                      fading → dormant
```

- 新事件先进入证据，不每轮直接改印象卡。
- 当前情绪和任务状态允许较快变化，但具备持续时间、衰减和影响范围。
- 兴趣、常用认知和关系在会话结束、每日维护或重要事件检查点更新。
- 人格、价值观、核心身份只接受用户明确修改或高门槛提案。
- 晋升与降级使用不同阈值、最短驻留时间和冷却期，避免人格来回震荡。

## Skill Suite

平台提供一套渐进加载的技能族，而不是一个巨型说明文档。

### `vault-orientation`

常驻、极短。说明当前 Agent、Vault 域、冻结策略、虚拟路径、默认工具、禁止绝对路径和需要加载的后续技能。

### `self-awareness`

读取编译印象，认识身份、状态、关系、能力、边界和缺失项；不会把未知推断成事实。

### `self-development`

处理明确的自我修改、成长提案和阶段晋升。要求目标维度、证据、影响分析、用户锁和 revision。

### `memory-capture`

处理“记住”“学习这条信息”和用户编辑产生的新事实。目标是立即可靠记录，不做过度摘要和长期晋升。

### `memory-triage`

普查积压、估算成本、分组、发现明显重复和制定批次任务，不无界读取正文。

### `memory-consolidate`

将一个受限短期批次规范化为中期知识，选择 append、amend、merge、create、link、conflict、archive 或 ignore。

### `tag-governance`

使用 Canonical Tag、别名、父子、相关和排斥关系，阻止同义 Tag 爆炸；新增 Tag 前先查注册表和相似候选。

### `memory-verify`

运行确定性结构检查、来源检查、召回测试和隔离上下文理解测试，输出可复现报告。

### `memory-promote`

只有中期知识满足长期门槛时才发布稳定 revision，并保留旧版本和晋升证据。

### `memory-review`

从真实回答失败、召回失败、用户纠正和抽样测试定位问题，只修复相关局部区域。

### `memory-fast-recall` 与 `memory-deep-explore`

分别指导查询探针、域选择、方向卡理解和有界 Wiki 探索，禁止无界全库读取。

### `experience-capture`、`method-refinement` 与 `capability-certification`

从任务产物和反馈提取经验，形成可复现方法，经过测试后才更新成熟能力目录。

### `resource-ingest`、`resource-study` 与 `reference-expression`

负责二进制导入、来源登记、分批学习和自然表达。资源候选由工具延迟查询，不在技能加载时注入。

## Skill 质量契约

每个 Skill 必须定义：

- 适用条件和禁止条件。
- 需要的工具和权限。
- 输入与输出结构。
- 最大上下文、读取、写入和重试预算。
- revision、冻结和作用域处理。
- 检查点和中断恢复。
- 失败分类与用户可见反馈。
- 正例、反例和自动化验收场景。

平台 Skill 只提供通用方法论。Agent 自己学到的知识、方法和经验写入其 Vault，不能修改所有 Agent 共用的 Skill。
